# 多语言：加英文界面

目标：桌面窗口和手机 App 都能整套切到英文，开源后不懂中文的用户也能用。中文仍然完整、不打折扣。

做法：桌面完全用 mygo 自带的多语言框架（语义 ID、ARB 风格的 JSON 译文表、ICU MessageFormat、`mygo generate` 生成带类型的函数）；手机用 Flutter 官方的同一套（ARB + gen-l10n）。两端的格式、复数规则、起名规则一致。

## 关键决策

1. **桌面用 mygo 的框架，不自己造**：`mygo.json` 加 `"i18n": {"dir": "locales", "source": "en"}`，译文表是仓库根目录 `locales/` 包（`posse/locales`）里的 `en.json`、`zh-Hans.json`。`go tool mygo generate` 在 `locales/` 里写出每个键的 Go 函数，并用 `go:embed` 嵌进 JSON、自动引入 mygo 自己控件的中文（`github.com/egoist/mygo/locales/zh-Hans`）；只配 `i18n`、不配 `bindings` 时不写 TypeScript。`mygo build` 每次先重新生成，`go build -o bin/posse` 不经 mygo，所以生成的文件提交进仓库，改了 JSON 要跑 `go tool mygo generate`（AGENTS.md 写明，测试核对生成的文件是最新的）。`internal/app` 要 import `posse/locales`，否则语言不登记。
   - 用户的选择用 `mygo.App.SetLocale(tag)`（`""` 是跟随系统），mygo 自己存在 app 的 defaults 里，不进 ui.json；`SetLanguages` 是声明 app 写了哪些语言，不用调（默认取 catalog 的语言）。语言检测（macOS 首选语言）、切换后重画、复数（CLDR）、日期和数字格式（`i18n.FormatDate`、`FormatNumber`）都用它的。删掉 `menuLabels`。
   - Mac 的 `CFBundleLocalizations` 和各语言 `.lproj/InfoPlist.strings` 由 mygo 按 `locales/*.json` 写，但只自动填 app 名；以后要加的权限说明放在 `resources/<lang>.lproj/InfoPlist.strings`，打包时合并。
2. **源语言是英文**：`en.json` 有所有键和元数据（`@key` 的 description、placeholders），系统语言不是中文的（日语、德语……）都退回英文；以后有人贡献别的语言，从英文译。中文同样必须完整，核对见决策 9。
3. **手机用 Flutter 官方的 gen-l10n**：`mobile/l10n.yaml`，`lib/l10n/app_en.arb`（模板）、`app_zh.arb`，`AppLocalizations.of(context).closeTerminals(n)`；接 `flutter_localizations`，系统控件跟着语言走（中文用户也终于看到中文的复制粘贴菜单）。ARB 和 mygo 的 JSON 是同一种格式、同一套 ICU 写法，键的起名规则两端一致；两端各自一套表，不共用（文字大多不同，共用会把两边的发布绑在一起）。
4. **键怎么起**：小驼峰，界面在前、用途在后：`gitCommitButton`、`gitRollbackConfirm`、`tasksEmptyHint`、`settingsLanguageTitle`。通用词单独一组：`commonCancel`、`commonOk`、`commonClose`，各界面直接用，不再各起一个。同一句中文在不同地方意思不同，就是两个键（ID 本身就是上下文，不需要 gettext 的 `msgctxt`）。每个键在 `en.json` 写 description，说明出现在哪、是按钮还是标题，给以后的译者看。不拼句子：带数字、名字的整句是一条消息，用 ICU 的命名占位符（`{count}`、`{name}`），复数写 `{count, plural, one {…} other {…}}`。
5. **逻辑里不再用显示文字**：先把中文当逻辑值的地方改成枚举或常量（`gitx.Run` 带取消标志、`"刚刚"` 改成比较时间、聊天项目用固定的内部名、手机端的连接状态用 code、自定义按键存 key 不存 label），这一步不改任何显示，单独提交。包级表里的文字改存键（或返回文字的函数），显示时才取，切语言才会跟着变；按 label 分组、搜索的地方（`keysettings.go`）改成按键分组、按当前语言的文字搜索。
6. **各包不产出界面文字**：报错保持英文源文本、经 errtext 在界面一侧翻译；42 处中文报错改回英文、补进 errtext 的中文表。在窗口进程里跑、不经 RPC 的（`skills.Scan` 的 `Status.Why`、Git 界面调的 gitx）改成英文源文本或返回原因的枚举，在窗口里经 errtext 或 locales 翻译，不必改协议。真正跨进程的（media 的标签、`Usage.Plan` 的套餐周期、默认设备名、看桌面的 viewer 名、`internal/mobile` 里直接发给手机的文案）改成发 code 或结构化字段，由窗口和手机各自按自己的语言显示；`usage` 不再把 `/mo` 改写成中文。errtext 的语言改由调用方给：窗口用 mygo 的当前语言，手机服务用连接的语言。
7. **手机的语言放进 `clientCapabilities.update`**：hello 用 `exactKeys` 严格校验，多一个字段所有手机都连不上；`clientCapabilities.update` 是普通解析、忽略未知字段，`conn` 已经存着 `clientName`、`clientVersion`，加一个 `locale`。没带的老手机按中文。手机切语言时重发一次。改了常驻进程，要交接。
8. **英文叫法跟着参照对象**：Git 界面照 WebStorm 英文版（Commit、Rollback、Update Project、Push……），macOS 菜单照系统英文版（mygo 的英文本来就是），其余照末尾的术语表。术语表在第 3 步定稿后才开始批量翻译。
9. **核对**：`mygo i18n check` 进 `go vet` 那一组检查（AGENTS.md 的构建与测试），但它只把解析、占位符、复数形式的错当错，缺译只是警告、退出码照样是 0，而查不到的键运行时直接显示键名。所以另加 Go 测试：`zh-Hans.json` 的键和 `en.json` 完全一致；`en.json` 里没有代码用不到的键（引用的键不存在由编译保证）；生成的文件和 JSON 对得上；`internal/app` 里不再有中文字面量（注释和测试除外，用 go/ast 扫）；`internal/app` 里不直接调平面函数（见决策 11）。手机端 gen-l10n 本身检查模板，另加测试核对 `app_zh.arb` 不缺键、`lib/` 里不再有中文字面量；`design_rules_test` 照旧。
10. **排版用伪语言查**：mygo 的 `en-XA`（从英文变换出来，加长、加重音，不需要文件）。离屏预览（`preview_test.go`）加 `en` 和 `en-XA` 两套，用 `Tester.SetLocale`，测试里就能用，不必 `mygo dev -lang`；手机截图测试加英文一套。固定宽度的地方（`settings.go` 的标签列 184、`view.go` 标签最宽 280、侧栏、状态栏、按钮）按英文重排，不缩字号。
11. **视图按 `c.Locale()` 取文字**：生成的平面函数（`locales.GitCommitButton()`）读 App 全局的当前语言，`Tester.SetLocale` 改的只是测试里视图的 `c.Locale()`，两者在离屏预览和单元测试里对不上。所以 `internal/app` 一律写 `L(c).GitCommitButton()`（`L(c)` 就是 `locales.In(c.Locale())`），不调平面函数，测试禁止；平面函数只留给没有 Context 的地方（菜单、窗口标题、通知）。现有测试按中文文字找元素（`Tester.Find` 整句精确匹配），改成 `locales.In("zh-Hans").GitCommitButton()`；测试的 Tester 固定 `SetLocale("zh-Hans")`，不随跑测试机器的系统语言变。
12. **内容数据不归界面翻译**：`cheatsheet.json` 每一项加英文字段，按界面语言选。会话标题的格式（`MMDD｜类型｜摘要`、中文类型词、中文摘要）是写进 agent 会话存储的内容，单独决定，这次不跟界面语言变：一台电脑的标题风格前后一致，换语言不会让历史里的标题混着两种。
13. **更新说明分语言**：`CHANGELOG.md` 和 `mobile/CHANGELOG.md` 每节加 `### English` 小节。Mac 端在 `appupdate.go` 按当前语言截取（mygo 把整节交过来）；手机发布脚本在 latest.json 里写 `notes`（中文）和 `notes_en`，App 按语言选。
14. **文档**：加 `README.en.md`，两份 README 顶部互链；`docs/features`、AGENTS.md 仍只写中文，AGENTS.md 加一条「界面文字一律经 locales，不写字面量」的规则。

## 步骤

每一步单独提交、单独验收；第 1～4 步按顺序做，做完才开始并行。

1. **接 mygo 的框架**（已完成）：`mygo.json` 的 `i18n`、`locales/` 包和生成的文件、`L(c)`；mygo 控件跟着语言走、删 `menuLabels`；设置页加「语言：跟随系统 / 简体中文 / English」（`mygo.App.SetLocale`）；`OnLocaleChanged` 里重装原生菜单（mygo 只重贴系统角色菜单项，`installMenu` 自己加的项和 File、View、Window 这些标题要重装）；测试固定中文；`mygo i18n check` 和决策 9 的测试。只把设置页的文字换成键，走通整条路。
   - 做下来的：mygo 没有读出用户所选语言的接口，副本里加了 `App.ChosenLocale`（记在 `third_party/mygo/POSSE.md`）；语言选项按 `App.Languages()` 列、各用自己的名字（`i18n.Autonym`），加了语言自动出现。窗口标题是应用名、不分语言，不用重设。mygo 自带中文和 `menuLabels` 不同的 14 处（「转到定义」等）在 `zh-Hans.json` 用 `mygo.<键>` 覆盖，保持原来的叫法。`errtext.Current` 跟着界面语言（`setErrLang`）。没改完的文件列在 `l10n_test.go` 的 `l10nPending`，改完一个去掉一个。
2. **逻辑值去中文**（决策 5，已完成）：桌面和手机，不改显示。
   - 做下来的：Git 操作带代号（`gitKind`：fetch、push、update、commit），要不要给取消、是不是在提交按它判断；`gitx.Run` 加 `Canceled`，取消的报错是英文源文本 `gitx.MsgCanceled`，操作记录显示报错经 errtext（旧记录里中文"已取消"的操作照旧显示，只是图标算失败）；技能安装按钮按动作判断；`disclosure` 收、展两句说明分开传；退出的终端按状态判断；"刚刚"按时间判断；套餐窗口按类别（`windowKind`，手机 `WindowKind`）判断。手机：看桌面的提示带 `failed` 标记、端口框的键盘由调用方给、切空间的三个键用代号、终端键分开代号和键帽（`TermKey.id`、`keycap`，存盘的「清空」迁移成 `clear`）。
   - 聊天项目按目录认，`"聊天"` 只是第一次加项目时起的名字，不是逻辑值，留给第 5 步当普通文字翻。
3. **通用词和术语表**：`commonXxx` 一组先合入，之后 worker 只能用、不能新增；翻 Git 和设置两个界面，定下术语表和键名规则的样例（已完成）。
   - 做下来的：Git 界面 11 个文件和设置页其余 6 个文件（快捷键、套餐用量、聊天、应用更新、防休眠）换成键，表里共 745 条。还在 `l10nPending` 里的 compare、gitconsole、planusage 只剩日期和倒计时（第 7 步）。快捷键表按分组代号（`keyGroup`）分组，搜索用当前语言的文字；没有 Context 的函数（`gitDo` 这类后台操作、确认对话框）由视图传 `locales.Messages` 进去、存在操作里，不设全局的当前语言。
   - 合并时发现的：worker 会按自己界面的用法改通用词的译文和说明，合入时一律以 main 为准；原来的叫法和通用词不同的（日志里改提交信息的「确定」，通用词是「好」）另起键，保证中文不变。英文撇号一律用弯撇号 `’`。
4. **常驻进程的文字**（决策 6、7，已完成）：中文报错改英文进 errtext、非报错改 code、手机连接带 locale。交接验证。
   - 做下来的：gitx、skills、deskrelay、files、history、mermaid、daemon/desk、internal/mobile 的中文报错和说明改成英文源文本，界面碰得到的在 `errtext/zh.go` 补译文（原来的中文），只给 CLI 和 agent 看的（`posse session title` 的回话、namer）只改英文。拼起来的句子改成整句的格式串。窗口里显示的说明：`skills.Status.Why`、MCP 的「N 种写法」、读不出指向的符号链接（`files.LinkUnreadable`）、mermaid 的报错经 `errtext.Message`；技能读不到的原因改成结构化的 `NotRead`、`Reads`（目录列表要按语言连接）、查更新失败的来源改成 `skills.Failure`，由窗口用 locales 写；Git 操作记录里截断输出的记号是英文的，窗口用 `gitx.Clipped` 拆开后用 locales 写。跨进程的：media 的 `Item.Tag`（generated、codeOutput、pasted），窗口和手机各自写叫法，不再发中文 label；`Usage.Plan` 存 Cursor 给的原样（`/mo`），窗口和手机显示时换成「/月」。
   - 手机在 `runtime.clientCapabilities.update` 里带 `locale`（hello 不动），连接记下语言，报错一律 `errtext.TextIn(conn 的语言, …)`，没带的按中文；手机现在固定发 `zh-Hans`（`posseLocale()`，第 6 步换成界面语言）。手机上的 Go 库自己产出的 mermaid 报错由 Dart 写成中文。
   - 常驻进程自己显示的文字（看桌面和配对的默认手机名、恢复终端时打的一行）用 `errtext.SystemLang()`：mygo 的 `SetLocale` 把用户的选择存在 app 自己的 defaults（包 ID 的 `AppleLanguages`），常驻进程从它所在的 .app（副本的包 ID 和原包相同）找包 ID、用 `defaults read` 现读，没选或不是从 .app 运行时按 macOS 首选语言（`-g` 的 `AppleLanguages`）。CLI 里的界面路径写英文叫法（Posse > Mobile > Relay）。
   - `errtext` 的 `TestNoChineseOutsideApp` 扫 `internal/`（除 `internal/app`）和 `cmd/` 的非测试文件，允许名单只有会话标题格式和写给 agent、shell 的内容。交接记录没变，`handoffVersion` 不动。
5. **桌面窗口其余界面**（已完成）：按文件分批（sidebar 和 view、tasks、files、history、skills、usage、mobile 页……）交给 worker，各在自己的 worktree 里改代码和两张表。三个文件会冲突：两份 JSON（按键排序，冲突只在相邻行）和生成的 Go 文件（整个重写）。规则：rebase 时两份 JSON 手工合并，生成的文件不手工合、直接重新 `go tool mygo generate`，再跑测试才合入。worker 不改 `common` 开头的键（译文和说明都不改），合并时以 main 为准。每批合入前看 `en`、`en-XA` 的离屏预览。
   - 做下来的：分三批（技能和用量、侧栏和任务和终端、文件和历史和手机页）并行，表里共 1495 条；`l10nPending` 只剩 compare、gitconsole、history、mobile、planusage、skills、tasks、usage 八个文件，里面只有相对时间、日期和倒计时（第 7 步）。没有视图调用方的后台文字（系统通知、轮询里的提示、终端插件回调、快捷键文字里的键名）用 `appL()`（按 mygo 的当前语言）。计数类的数字占位符按语言加千分位，中文的「1234 条」变成「1,234 条」，和原来就带千分位的总数一致。新建技能写进 SKILL.md 的模板还是中文，归第 7 步的内容一类。

## 键名规则和通用词（第 3 步定稿）

- 键名小驼峰，界面在前、用途在后：`<界面><东西><角色>`。界面前缀：`common`（通用词）、`menu`（菜单栏）、`settings`、`git`、`branch`、`log`、`compare`、`rollback`、`files`、`editor`、`history`、`tasks`、`skills`、`usage`、`mobile`、`chat`、`sidebar`、`tab`、`term`、`dialog`、`update`（自动更新）、`awake`、`keys`（快捷键表）。角色后缀按需：`Title`（卡片、对话框标题）、`Note`（说明段落）、`Button`、`Tip`（悬停）、`Confirm`（确认对话框的标题）、`Body`（对话框正文）、`Empty`（空状态）、`Error`（报错前缀）。
- 通用词（`en.json` 里 `common` 开头的 29 个）先合入，各界面意思相同就直接用，不再另起；worker 不新增 `common` 键，缺了在报告里提。意思不同的同一个中文另起本界面的键（「提交」按钮是 `gitCommitButton`，Git 提交的列表标题是另一个键）。
- 句子带数字、名字时整句一条，ICU 命名占位符（`{name}`、`{count}`），有数量的写复数（中文只要 `other`）；不拼接 `"展开 " + path`、`what + "失败："`。
- 每个键在 `en.json` 写 description：在哪、是什么控件、占位符是什么；英文按 macOS 的大小写习惯，按钮和菜单项用标题式（Reset to Default），说明和提示用句子式。

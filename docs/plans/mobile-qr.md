# 扫码配对

桌面已经把 `orca://pair?code=` 画成二维码（窗口 `qr.Encode` level L，终端半格字符同一串）。手机配对页扫到的原文交给现有 `PairingOffer.parse`，成功就走 `connectCode`。完整 URL 和裸 base64 都能解析。不改协议、不改码的内容、不改纠错级别。Orca 仍能扫同一个码。

## 决策

- 只在配对页加「扫二维码」。合法配对码：关掉相机、回到配对页并连接。别的码忽略，相机继续开。粘贴框保留。
- iOS 用 `AVCaptureMetadataOutput`，只要 `.qr`。不挂 `AVCaptureVideoDataOutput`，Dart 不碰像素，不引入 pub 包，不上 ML Kit。
- 相机会话只在扫码页存在。认到码、返回、页面销毁都 `stopRunning`。预览用 1080p，检测整幅画面。不裁中心区域：预览层尺寸变化时改裁切会重置检测器，认码更慢。对焦限制在近处、关掉平滑对焦，不配置音频会话。握手完成就进工作区，列表没回来时转圈，不先显示空列表。
- Android 这一版仍只粘贴。按钮用 `Platform.isIOS` 收起。
- 模拟器摄像头看不到 Mac 屏幕，不作为验收。单测只覆盖哪类字符串算配对码。

## 流程

配对页点扫码 → `posse/qr` 的 `authorize` 申请相机 → 全屏预览（原生 `UiKitView`，顶栏是「对准电脑上的配对码」和关闭）→ 原生只上报不重复的字符串 → Dart 解析成功就停会话并 `connectCode` → 失败则停在配对页的错误行，可再扫或改贴。拒绝相机权限时不进预览，配对页仍可粘贴。

平台视图注册在 `didInitializeImplicitFlutterEngine`：现有引擎走这条路径。握手完成就进入工作区，列表随后补上。

## 不做

相册选图、手电筒、连扫、缩放、第二套 Vision 逐帧检测、加大纠错级别、改 `endpoints`、轮换 `mobile.json` 密钥、Android 扫码。

桌面码是几百到近千字节的 URL（token 48 个十六进制字符、公钥、UUID，再加一两个地址），level L 已经偏密。真机若对现在 220pt 的图对不上焦，只把窗口里的图放大，不改编码。终端半格码是白块黑底；若真机扫窗口成功但扫终端失败，仍用粘贴，不为此加第二条检测管线。

## 验收

- 真机扫桌面「连接手机」二维码后进入工作区列表。配对码在连接成功后才写入本地。
- 对准无关二维码时预览不关。
- 拒绝权限后可以粘贴连接。
- 返回或连接后相机灯灭。
- `fvm flutter test` 通过字符串门闩。模拟器不声称扫码成功。

Hive 文件标签页实现计划

2026-10-16

目标与范围

每个工作区新增一个“文件”标签页，和终端标签并列，用来浏览、查看、轻量编辑和检索当前工作区目录下的文件。编辑区直接用 hive 自带 mygo 里的代码编辑器 ui/editor；全部功能在窗口进程里完成，不改常驻进程的协议；思路参考 Mayoi，不复制它的代码。

要做：

  • 文件树：工作区目录的树，展开时才读目录，跟随磁盘变化，gitignore 的文件变暗
  • 查看：带行号和语法高亮的代码视图，图片直接显示，Markdown 可以切到预览
  • 编辑：直接改、⌘S 保存、标出未保存、⌘F 文件内查找替换；agent 在外面改了文件时自动重载或提示冲突
  • 快速打开：⌘P 模糊匹配文件路径，:行号 跳到某一行
  • 全文检索：⇧⌘F 在工作区目录里搜，点结果跳到那一行；先做子串匹配，大小写、正则、glob 放在最后一个阶段

不做：git diff 和 stage、多列分屏、vim、LSP 和自动补全（ui/editor 支持，但不接）、跨文件替换、远程目录。

现状

编辑器不用自己拼：hive 的 mygo 副本里有完整的代码编辑器包 third_party/mygo/ui/editor，自带行号、语法高亮、查找替换、未保存判断和 CRLF 处理，只是 hive 目前还没有引用它。要新增的是标签模型、文件树、监听和检索。

现有的位置对本功能的意义
代码编辑器ui/editor：View(c, *State)；State 的 LineNumbers、ReadOnly、SoftWrap（state.go）；LanguageFor(文件名)（languages.go）；只排版可见的行（doc.go）查看和编辑区整个用它，不再用 TextAreaBuffer 自己画行号，也不引入 Chroma
编辑器的文本缓冲editor.Buffer：NewBuffer、Reset、Modified、MarkSaved、String（buffer.go）Modified 比较的是文本本身，撤销回保存时的内容会变回“已保存”；Reset 用于从磁盘重载并清空撤销历史
编辑器自带快捷键ui/editor/keymap.go：⌘F、⌥⌘F、⌘G、⌘E、⌃G 等不占用 ⌘S、⌘P、⌘W、⌘1…9、⇧⌘F，这些仍走 hive 的全局快捷键
标签栏只画终端internal/app/view.go 的 main，遍历 w.Terminals；没有终端时画 emptyWorkspace要插入一个不来自常驻进程的标签；没有终端时也要能显示文件标签
选中哪个标签app.activeTerm（工作区 ID → 终端 ID）；currentTerminal（app.go）在记住的 ID 不是终端时会写回第一个终端直接放一个 filesTabID 会每帧被覆盖，要先改这里
快捷键view.go 的 shortcuts：⌘T、⌘W（只在 cur != nil 时）、⌘1…9⌘W 要认得文件标签
关闭窗口和退出的钩子mygo 的 Window.OnClose（可 PreventDefault，window.go）和 Application.OnBeforeQuit（app.go）；hive 目前都没有注册有未保存的文件时拦住关窗口和 ⌘Q
界面状态持久化internal/app/uistate.go（ui.json）；saveState 在 goroutine 里写，只拷贝了 ProjectOrder新加的按工作区的字段要深拷贝，否则有数据竞争
Markdown 渲染internal/app/markdown.go（goldmark）Markdown 预览直接复用
图片解码和预览internal/app/images.go、links.go 的 previews图片查看复用
终端里的路径链接卡片internal/app/links.go 的 showLinkCard加一个“在文件标签里打开”的入口

缺的：mygo 没有文件监听；internal/gitx 只有 worktree 和 merge 相关的函数。

关键决策

每个工作区只有一个“文件”标签，打开的文件在它内部切换，编辑区用 ui/editor；全部状态留在窗口进程，只监听目录，只在标签可见时监听。

事项决定理由
进程归属全部在窗口进程，常驻进程不动改协议要重启常驻进程，会断掉所有终端；关掉窗口就释放内存
编辑器用 ui/editor：editor.View 加 State{Buffer, LineNumbers}，语言取 LanguageFor；大文件打开为 ReadOnly行号、高亮、查找替换、CRLF 都现成，只排版可见行
标签模型每个工作区一个文件标签，放在终端标签前面；内部左边是树或搜索结果，右边是一排文件小标签和编辑区终端标签栏不被文件挤满；⌘数字仍按终端编号
选中状态activeTerm[工作区] 可以是常量 filesTabID；新增 filesActive(w)，currentTerminal 遇到它不改写、返回 nil；build、shortcuts、main 三处按 filesActive 分支，没有终端的工作区也能显示文件标签；选中文件标签时 ensureView("") 断开终端接入不加新字段；沿用“只接入可见终端”的省内存做法
打开和关闭⌘P、“+”菜单、链接卡片都能打开；⌘W 关当前文件，没有文件时关掉文件标签和终端的 ⌘W 语义一致
文件树展开时才读目录；目录在前、名字不分大小写排序；跳过 .git，gitignore 的条目变暗但保留大仓库也不一次性读全量
忽略规则调一次 git ls-files -co --exclude-standard 得到不被忽略的文件清单，不在清单里的变暗；这份清单同时就是快速打开的索引；不是 git 仓库时遍历目录并按固定清单跳过 node_modules 等不自己解析 .gitignore，也不逐个目录调 git
磁盘变化不用 fsnotify：文件标签看得见时每秒 stat 一次展开的目录和打开的文件；磁盘戳是 size、mtime 加 inode，目录的磁盘戳变了就重读目录，文件的变了就重读文件；标签不可见时停止macOS 上 fsnotify 基于 kqueue，监听一个目录要为其中每个文件各开一个描述符；轮询不占描述符，也认得出“写临时文件再改名”的保存，代价是最多晚 1 秒
未保存判断用 editor.Buffer.Modified()，保存成功后 MarkSaved()撤销回保存时的内容会正确显示为已保存；不用版本号（每次改动和撤销都会加一）
外部修改没有未保存改动就 Reset 重载，光标和滚动按行号保留；有未保存改动就显示横幅“磁盘上已改动：重载 / 保留我的”；文件消失就标注“已删除”agent 随时会改文件，这是和普通编辑器最大的不同
保存在同一目录写临时文件，设成原文件的权限位，再改名覆盖；写完 stat 记下新的磁盘戳，之后监听到的事件 stat 结果相同就忽略；保存前磁盘戳已变就先问改名是原子的，agent 不会读到写了一半或被清空的文件；不覆盖 agent 刚写的内容。代价是硬链接和文件所有者不保留，对工作区文件可接受
大文件和二进制前 8 KB 含 NUL 算二进制，只显示大小；超过 5 MB 只读；超过 50 MB 不打开；阈值在第 1 阶段实测后再定窗口进程内存可控
快速打开打开 ⌘P 时，索引超过 10 秒就后台重建（重建期间先用旧的）；只缓存当前工作区的，切换工作区就丢；模糊匹配自己写（子序列匹配、文件名和连续命中加分），取前 50 条只看展开的目录，看不到未展开目录里的新增，不能靠磁盘变化作废
全文检索在 goroutine 里按索引逐个读文件做子串匹配，跳过二进制和大文件；每次查询带编号，旧查询的结果丢弃；结果每 60 ms 经窗口的更新回调推一批，最多 2000 条；打开的文档搜编辑器里的内容不依赖系统是否装了 rg；未保存的改动也能搜到
持久化ui.json 按工作区记打开的文件、当前文件、展开的目录、文件标签是否打开；不存内容；saveState 对这些字段深拷贝和现有界面状态的存法一致
关窗口和退出注册 Window.OnClose 和 Application.OnBeforeQuit：有未保存的文件就阻止并弹确认（保存全部 / 放弃 / 取消），选好后再由界面触发关闭或退出不丢用户的修改

模块与文件划分

和界面无关的逻辑放进新包 internal/files，不依赖 mygo，可以单独测试；界面放在 internal/app/files*.go。

internal/files/          新包，纯逻辑
  disk.go               读文件（二进制和大小判断）、磁盘戳、原子保存
  tree.go               按需读目录、排序、展开状态、看得见的行
  list.go               调 git ls-files 得到文件清单（变暗和索引共用）；非 git 目录的遍历和跳过清单
  fuzzy.go              模糊匹配打分、取前 N 条、拆 路径:行号
  search.go             全文检索：大小写、正则、包含和排除的 glob，分批推送，可取消
  *_test.go             临时目录里的真实文件测试
internal/app/
  files.go              文件标签的状态（每个工作区一份）、filesActive，打开、关闭、保存、重载、轮询、检索，关窗口的拦截
  filesview.go          标签内部布局：左栏树或检索、右侧文件小标签和 editor.View，⌘P 浮层
  view.go               改：build、shortcuts、main 按 filesActive 分支，标签栏画文件标签
  app.go                改：currentTerminal 认得 filesTabID；saveState 深拷贝；注册关窗口和退出的钩子
  uistate.go            改：按工作区存打开的文件和展开的目录
  links.go              改：链接卡片加“在文件标签里打开”
  preview_test.go       改：用 t.TempDir() 造目录，加文件标签的离屏预览
AGENTS.md               结构和约定里补一条

调用关系：

build
├─ shortcuts：filesActive(w) 时 ⌘W 关文件、⌘S 保存
└─ main(w, cur)
   ├─ 标签栏：文件标签 → 终端标签 …
   └─ filesActive(w) 时 filesView(w)
      ├─ 左栏：tree.Children / search.Results
      └─ 右侧：文件小标签 → editor.View(c, doc.state)
每秒一次（看得见时）pollFiles → 后台 stat 比对、重读 → a.update → tree / doc 更新 → 重画

分阶段步骤与验收

分四个阶段，每个阶段单独提交、可以单独使用；前两个阶段做完就是可用的轻量查看和编辑器。

  1. 标签骨架、文件树、只读查看
    • 先做一次实测：把 ui/editor 接进 hive，分别打开 1 万行、10 万行、5 MB 的文件，记下滚动是否流畅、窗口进程的 phys_footprint 和 Hive 可执行文件体积的变化（现在约 20 MB），据此定只读和不打开的阈值
    • internal/files 的 tree、list、disk 的读取部分；filesActive 和标签栏、快捷键的接入；editor.View 只读显示，图片和 Markdown 预览复用现有代码
    • 验收：离屏预览用 t.TempDir() 造一个目录，新增“文件标签”深浅两张图；单测覆盖 currentTerminal 遇到 filesTabID 不改写、没有终端的工作区也能选中文件标签；手工在 hive 自己的仓库里展开并打开 internal/app/view.go，切到文件标签时终端断开接入，切回来内容完整
  2. 编辑、保存、外部修改、关窗口
    • 轮询、disk 的原子保存和磁盘戳；未保存标记、⌘S、冲突横幅；关窗口和 ⌘Q 的确认；ui.json 记住打开的文件
    • 验收：internal/files 的测试覆盖：外部用“写临时文件再改名”修改后仍能发现、重载、冲突、删除、忽略自己的写入、保存保留权限位；go test -race 覆盖 saveState；端到端用 HIVE_HOME=/tmp/hive-e2e/home，在终端里改文件观察自动重载和横幅，有未保存时关窗口和 ⌘Q 都弹确认
  3. 快速打开和子串检索
    • index、search 的子串版本；⌘P 浮层、⇧⌘F 左栏搜索、点结果跳行；链接卡片的“在文件标签里打开”
    • 验收：单测覆盖模糊匹配排序、索引过期重建、旧查询编号的结果被丢弃、结果分批送达；benchmark 记录 10 万个路径的匹配耗时
  4. 检索选项和收尾（可裁掉）
    • 全文检索加大小写、正则、包含和排除的 glob
    • 验收：每个选项的单元测试

每个阶段都要跑 go vet ./... && go test ./... && go tool mygo vet；内存看 footprint -p：文件标签关掉后窗口进程的 phys_footprint 要回到接近原来的水平。

借鉴 Mayoi 的思路

只借鉴做法，不复制代码。下表的文件位置取自 sorrycc/Mayoi 的 d5e4ab0，只供写代码时参考。

思路Mayoi 里的位置hive 的取舍
目录展开时才读，监听到的一串变动合并后再处理internal/workspace/tree.go照做；另加“标签不可见就停止监听”
只监听目录，打开的文件也监听它所在的目录；Rename 和 Remove 当作“消失”处理tree.go照做，事件到了统一 stat 比对磁盘戳
用 git 的结果决定哪些文件变暗、哪些不进索引internal/workspace/index.go 的 Ignored照做，一次 git ls-files 两处共用
索引和模糊匹配分开，只取前 N 条，不对全量排序index.go 的 Fuzzy照做，打分规则自己定
每次搜索带编号，旧搜索的结果丢弃；结果每 60 ms 推一批并保持按路径排序cmd/mayoi/search.go照做；不做替换
打开的文档搜内存里的内容，没打开的读磁盘search.go照做
保存时在旁边写好再改名；保存后记下写入时的文件状态，监听到自己这次写入时不重读cmd/mayoi/document.go照做；另加“保存前磁盘已变就先问”
未保存判断比较文本，而不是版本号cmd/mayoi/history.go由 editor.Buffer.Modified 现成提供
不采用：Mayoi 在 TextAreaBufferBase 上自建编辑器（行号、高亮、自动缩进）、vim、分列、sticky、远程、编辑器内的 git 标记—hive 用 ui/editor，其余超出“轻量”的范围

风险与待决定的问题

风险应对
hive 和 Mayoi 都没用过 ui/editor，实际可用性和大文件表现未经验证第 1 阶段一开始就实测；不行再退回 TextAreaBuffer 方案
引入 ui/editor（约 430 KB 源码）会增大可执行文件和窗口进程内存第 1 阶段实测体积和 phys_footprint 的增量；只在打开文件标签后才创建编辑器状态
在终端和文件标签之间切换时，终端要重新接入沿用现有的快照接入，和在终端之间切换的代价相同；若能看到闪烁再考虑保留上一个接入
轮询每秒 stat 展开的目录和打开的文件，展开得很多时开销变大只在文件标签看得见时轮询，stat 在后台做；目录展开到上千个时再考虑限量
agent 和用户同时改同一个文件保存前比对磁盘戳，变了就问，不默默覆盖

实现结果（2026-10-16）

四个阶段都已实现，在 调研 分支；和上面的计划相比只有一处改动：磁盘变化改为轮询，不引入 fsnotify。

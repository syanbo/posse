- 「断开主机」只断开客户端；「关闭终端」沿用结束程序的确认。关闭窗口、切主机、断网不结束远端终端。
- 本轮不做 Linux、远端自动安装/升级、跨主机文件同步、多窗口、跨主机任务调度、远程桌面或多人同时桌面操作。手机配对与中转沿用现有方式，不通过本机转接。

## 2. SSH、发现与连接生命周期

### SSH 传输与认证

- 使用系统 OpenSSH，沿用 `~/.ssh/config`、ssh-agent、Keychain、known_hosts 和 ProxyJump。配置保存名称、SSH 目标，以及可选用户/端口、远端程序路径和 home；不保存密码或私钥内容。
- 每个目标使用 Posse 自有的 ControlMaster、ControlPath 和本地 Unix socket，放在短路径、0700 的私有运行目录；不接管或关闭用户已有的 master。
- 普通 RPC 与终端流复用 SSH Unix socket 转发，远端 daemon 仍只监听 Unix socket，不增加公网控制端口。断开只清理自有 SSH 进程/socket。
- 未知主机显示指纹确认；主机密钥变化停止连接。密码/私钥口令通过本次连接专用的 askpass 通道交给 SSH，不落盘、不进日志；可取消，后台重连不反复弹认证框。
- SSH 参数和远端命令分开处理，验证目标/端口，严格引用自定义路径；测试空格、非 ASCII 与选项注入。默认不转发 SSH agent，远端 Git 使用远端自己的凭据。
- 首阶段实际验证 macOS OpenSSH 的 Unix socket 转发及 sshd 禁止转发的报错，不同时维护多套传输。

### 发现、启动和协议

- 增加机器可读的连接辅助命令，返回实际 home/socket、平台、CLI 版本和 daemon 状态；通过隧道再查询 daemon 的实际协议能力与实例 ID，不能拿 CLI 版本代替服务端版本。
- 优先发现远端稳定的 `$POSSE_HOME/bin/posse`，辅以标准安装位置和用户指定路径；不依赖交互 shell 的 PATH。处理 shell 启动噪声与结构化结果的分离。
- 优先连接已运行 daemon。未运行时通过远端 Posse 的 `EnsureDaemon`/`spawn` 启动，沿用签名、副本、TCC 和脱离 SSH 会话的逻辑。
- 协议能力包含主机控制会话、文件与 Git 服务，独立于 `handoffVersion`。缺能力明确提示更新远端，禁止把本机 exe 路径传给远端自动升级。
- 首次使用远端 Mac 先正常打开 Posse、完成项目目录授权。休眠、退出登录及 TCC 行为必须双机验证，不承诺 SSH 绕过系统授权。

### 主机身份与重连

- 使用稳定的本地主机配置 ID；资源键为 `(HostID, 原始资源 ID/远端路径)`。握手核对实际目标、用户/home 与实例，变更后重新绑定，不以复制过来的数据库 ID 合并主机。
- 区分主机身份、连接 generation、daemon 实例 ID 和控制 epoch。异步工作捕获固定 Client/主机上下文与文档 revision，UI 应用结果时重新核对，不能仅替换 `a.c`。
- 重连退避且可取消；认证失败、密钥变化和协议不兼容停止自动尝试。连接恢复不自动抢回已失去的控制权。
- 断线保留旧列表和未保存内容，标记过期；网络或权限错误不是文件/工作区不存在，不能触发自动清理。

## 3. 复用现有客户端，增加必要服务边界

不新增应用级通用 Backend 框架，不预先为所有页面定义可插拔后端。

```text
internal/remote/              SSH 配置、认证、发现、隧道、重连
internal/client/              现有 Call/Open/Attach；新增文件/Git 类型化调用
internal/daemon/              主机控制会话、文件/Git 服务、必要写入协调
internal/app/                 按主机保存的界面上下文与现有视图适配
internal/files、gitx、history  现有领域逻辑，按执行位置复用
```

- 保留 Unix socket 与 `rpc.Call/Open`；在 Client 层收拢 Attach 的连接入口，分离“本地启动 daemon”和“重连 SSH”策略。
- 项目、工作区、终端、任务及历史已有 RPC 继续用；仅为缺失能力补接口。新增文件/Git 请求与结果明确类型，不暴露任意 shell 命令。
- 远端文件/Git 在目标 daemon 执行。本地读取可继续直接复用原函数；本机窗口的保存和 Git 写入经过同一目标服务，使控制权检查和写入协调可在服务端强制执行。
- 复用 `files.ReadDir/ReadFile/WriteFile/ListRepos/Search/FindDefinitions`、`gitx.Discover/ReadStatus/Show/Branches/Log/Blame` 及具体写操作；复用 `history.list/search/show/resume`。
- 不直接套用手机 files/git API：它们是不同的 dispatch，缺保存和多数桌面 Git 操作。必要时共享底层服务，保持手机界面与协议行为。
- 追踪并迁移 `app.refresh` 中 HEAD、目录存在性、worktree 清理和进程内存等本机假设。设备级设置明确归属，不以远程接管为由全面重构技能、配对、讨论或更新模块。

代表路径：`internal/client/{client,conn}.go`、`internal/rpc/{rpc,frame}.go`、`internal/cli/commands.go`、`internal/daemon/{daemon,attach,window,handoff,workspace,history}.go`、`internal/mobile/branch.go`、`internal/app/{app,uistate,panes,files,repos,gitview,branchpop,history,upgrade}.go`。本轮不为操作结果新增数据库表或 schema 迁移。无 UI 废纸篓使用独立平台适配；若终端插件需补查看模式，先读 MyGo 的 AGENTS.md/架构文档并记录必要改动。

## 4. 整体接管与终端显示

### 一个实例，一个桌面控制会话

- daemon 维护一个实例级桌面控制会话，记录客户端 ID、epoch 和存活状态。普通本机窗口在没有控制者时取得控制；新远程连接默认查看，显式「接管」后切换。
- 接管与桌面写请求的接受在同一互斥边界核验。旧端未被接受的请求、迟到输入、resize 和终端查询回复被拒绝，不能只在 UI 禁用按钮。
- 接管不会中断旧端已经被接受的 Git/保存/资源变更。新端显示这些仍在执行的操作，并遵守相应资源队列；收到成功不等于这些操作已被取消。
- 旧端收到通知后进入查看状态；保留 dirty 文档、禁用后续编辑/保存。重新收回控制后，保存仍须重新核对远端版本，不能沿用接管前的确认。
- 正常切主机/断开主动释放控制；断网通过控制会话保活超时释放。每次转移/重连使用新的 epoch，旧端恢复连接不能自动抢回。daemon 重启后重新建立控制会话，不持久化租约。
- 这是一项避免误操作的产品规则，不是同一系统用户下的安全隔离。所有桌面修改入口显式带控制身份；hooks、agent 和 CLI 的工作不被误当作另一桌面连接而整体拦截。

### 终端

- 不为每个终端建立独立租约或单独的接管按钮。目标实例所有桌面终端输入、resize、查询应答都服从同一个控制会话。
- 查看端仅接入已存在的 live 终端，接收快照和增量，按实际 PTY 尺寸显示，允许选择、复制、滚动；不能发送输入、resize 或自动回复。控制转移使旧连接立即失去写入资格，不等待 UI 收到通知。
- `terminal.attach` 当前会在没有 liveSession 时调用 `restoreTerminal` 并启动进程，因此恢复分支必须在调用前通过同一控制身份和写入接受门禁，纳入 handoff 活跃写操作管理；查看者点开待恢复记录只显示状态并提示接管后恢复，不能因浏览启动 agent/shell 或修改恢复记录。交接接入已有终端仍按原流程工作。
- 沿用 GUI 应答机制，只允许有效控制会话的对应终端接入者回复；没有该接入者时由 daemon 内核应答。快照回放、接管和重连都不能产生重复应答或重放按键。
- 配色沿用现有窗口报告机制，但只接受当前桌面控制端的报告；查看端不改全局配色。无需引入逐终端主题/控制者管理。
- 保留手机的 `HoldSize/ReleaseSize/ReclaimSize`，仅桌面控制端可以收回手机尺寸。手机输入与显式 `terminal send` 继续作为独立操作，不取得桌面控制权、不重放失败输入。
- 现有 GUI/插件的 attach 统一走实例级控制仲裁；旧 attach 不支持能力协商时拒绝冲突接入。当前 CLI 没有交互式 attach，本轮不新增；现有显式 `terminal send/resize` 等 CLI 操作继续作为独立操作，不取得桌面控制权。桌面端不能改用这些独立入口绕过控制身份检查。
- 因终端内核重建重新接入不等于主机断线，不因此释放整体控制。正常 handoff 后重新协商实例/连接状态，旧 epoch 失效。

## 5. 文件、预览与条件保存

- 保留文件树、全文检索、快速打开、定义/import 跳转、未保存内容 overlay、预览和现有文件大小限制。远端执行磁盘查找，本机负责编辑与渲染。
- 对可见目录/文件批量轮询，隐藏时释放缓存；不全盘监听、不做本地文件镜像。大资源分段/流式读取并限量。
- 读取返回磁盘戳与内容指纹；保存携带读取版本、提交内容摘要与编辑 revision。目标端按规范化路径及所属仓库协调，版本检查到原子替换处于同一临界区，复用权限与软链语义。
- 版本变化返回冲突，不静默覆盖；覆盖确认基于重新读取的版本。保存等待期间的新编辑保持 dirty，只将已确认的 revision 标为已保存。
- **保存回复丢失不自动重发**：重连后检查原请求是否仍在当前 daemon 的执行器中，再重读文件版本/内容。内容与提交快照相同可确认该内容已在磁盘上，不声称证明了操作历史；不同或仍无法确定则保留 dirty/冲突状态，由用户决定。daemon 重启后不把新文件盲目覆盖成旧快照。
- 文件不存在是明确状态；网络/权限错误不是删除。切主机、失去控制、断线均保留 dirty 文档；退出检查所有主机的未保存内容。
- 删除在目标 Mac 移到废纸篓。新增小型无 UI macOS 适配，基于 NSFileManager，遵守 purego 线程/自动释放池规则；不能直接调用依赖 App/UI 主线程的 `mygo.Shell.TrashItem`。失败保留原文件，不启动隐藏窗口，不退化成永久删除；历史删除共用。
- 图片/视频、历史附件、Markdown/HTML 相对资源通过目标资源读取；预览限制资源根，禁止远端 HTML 读取本机文件。临时缓存按主机/版本区分并回收。
- 图片粘贴先上传，成功后发送远端路径；失败不发送本机临时路径。「用本机应用打开」下载明确的副本，不能暗示会回写原文件。
- 项目添加/重定位使用远端目录选择。远端 localhost 链接明确归属，不默默打开本机同端口；自动端口发现、跨端网页自动化不属于本轮。

## 6. Git、必要写入协调与操作结果

### 完整 Git 与稳定目标

- 按 `docs/features/git.md` 逐项迁移：多仓库、状态/diff、部分及逐段提交、分支/标签、fetch/pull/push、stash、日志/blame、比较、merge/rebase/cherry-pick、冲突继续/跳过/中止和回滚。
- UI 闭包改为类型化请求，继续调用现有 gitx；保留未选中暂存内容、autostash、强推保护、凭据/签名与现有确认语义。
- 写操作在资源锁内重新核对目标：储藏使用 commit hash（复用 `StashDropHash` 的方式），不能依赖会移动的 `stash@{n}`；分支更新、删除、reset、回滚等校验必要的预期 HEAD/引用/文件基线，不能信任缓存的 `Branch.Current`。
- 即使只有一个桌面控制端，手机、CLI、agent 仍可改变状态，因此稳定目标校验必须保留。不匹配返回冲突、刷新后重新确认，不要求每次哈希整个仓库。

### 必要协调

- 文件保存/删除、Git 工作树变更与工作区移除共用目标端协调，防止保存检查后被 checkout/reset 改写、随后保存又覆盖回旧内容。
- 按 Git common-dir 关联 worktree；文件取得所属仓库/工作区的相应锁，非仓库文件按规范化路径协调，目录移除与子路径写入互斥。多资源按固定顺序取得锁。
- 参与者明确包含桌面文件/Git、auto-fetch、手机 checkout、daemon 的 workspace create/remove/merge/relocate、项目删除与任务创建 worktree。仅统一可能相互覆盖的入口，不扩展成全应用事务框架。
- 外部编辑器、agent 直接写文件及直接运行 git 不受 Posse 锁约束；继续依靠 Git 自身锁和文件版本校验。不能承诺消除所有外部写入与 rename 间的竞争。

### 当前 daemon 内的操作结果

- 读操作可在重连后重试；终端按键永不重放；有副作用的操作不得因超时/断线自动重做。
- Git 操作由目标 daemon 执行器持有，接受后脱离 RPC 请求 ctx，连接关闭不取消；取消须显式发起，取消也不意味着回滚已产生的改动。
- Git 使用客户端 request ID，返回 daemon 实例 ID；同一实例内相同 ID/参数查询或返回已有操作，不同参数拒绝。运行中项目不回收，完成结果有数量/体积/时间上限；容量不足在接受新操作前报忙，不能悄悄丢掉活跃结果。
- 短保存及创建/删除沿用具体服务入口，仅保留当前实例内必要的进行中/完成请求信息，供去重、交接门禁及重连核对；**不统一建持久化操作表，不存完整请求正文或文件内容，不做跨 daemon 的执行历史恢复**。
- 重启/handoff、记录回收或实例变化后查不到结果，明确显示“结果未知”，读取文件/仓库/资源现状，交由用户确认是否再操作；不能将查无记录解释为从未执行。新控制端也不得自动重放旧端未知操作。
- Git outcome/warnings 使用结构化结果：至少包含 autostash hash/冲突、push rejection、取消/超时及领域冲突。首次响应与当前实例内的结果查询共用结构，保留“主操作成功但恢复改动冲突”的恢复入口。
- Git Console 沿用现有有界历史记录机制并按主机显示；日志只是诊断/展示，不承担去重或 exactly-once 保证。多仓库分别记录成功失败，不承诺跨仓事务。

## 7. 升级与退出：操作完成后再交接

- 第一版不迁移进行中的 Git 子进程，也不迁移结果缓存。Git 或其他已接受写操作未结束时，更新提示“操作完成后可更新”，handoff 返回可重试 busy，不启动新 daemon。
- 写入接受与交接门禁共用互斥边界：确认没有活跃/已接受排队写入后封住新写入，再交接；失败解封，成功旧代不再接受写入。
- 新 daemon 仍按现有约定立即服务必要 hook、查询和终端接入，但取得 home 文件锁前不执行新的工作区写操作，防止两代同时改数据。
- 本地自动升级遇到操作繁忙不记成永久的“该 PID 已尝试”；操作完成后再触发一次，不高频轮询重试。远端连接不自动升级目标 daemon。
- 正常停止先停止接受操作、取消/收拢执行器及 Git 子进程，再关闭存储；异常终止后，客户端把未确认结果作为未知。原有终端 handoff 能力继续保留。

## 8. 界面状态与功能归属

- 在 app 内增加轻量 `HostSession`：固定 Client、连接/控制状态、项目与文件文档、generation 和必要缓存，不扩展成通用插件化后端。
- 持久化主机配置和按主机划分的 UI 状态；现有 ui.json 数据迁入本机分区，保留标签顺序、分栏与设置。主题、字体、快捷键属于本机窗口。
- 切换主机释放原终端订阅/渲染器和控制权；远端进程继续。近期 SSH master 在有数量/空闲时间上限的缓存中保留，仅做传输保活，不持续轮询全部主机或保留隐藏终端渲染器；超限/超时回收空闲连接。用户显式「断开」立即关闭该目标连接，不进入保留缓存。
- 切回恢复原工作区/标签与 dirty 内容，重新订阅可见终端。快速切换不会默默抢回控制：远程连接仍按「查看→接管」规则操作，界面明确显示是否已有其他控制者。
- 项目/工作区、任务、历史、用量、agent 检测属于当前主机；补齐历史上下文/附件/删除的本机路径假设。窗口内存与远端进程统计明确区分。
- 聊天属于当前主机的特殊工作区：聊天目录配置、路径发现、目录创建和项目登记都在目标端完成，不将本机 `a.home`、`chatDir` 或 `MkdirAll` 的结果交给远端。沿用目标已有聊天目录；远端聊天目录设置本轮在目标 Mac 修改。查看模式可浏览已有聊天，首次创建目录/项目、启动新聊天和转成项目须先接管。聊天标签、选中状态和异步结果随 HostSession 隔离。
- 第一版讨论页面整体固定本机，入口/页面标明「本机」：列表、消息、成员、附件、草稿和讨论 RPC 始终绑定本机 Client 与本机上下文；远程工作区切换不重绑讨论 Client，不把本机附件路径交给远端。讨论的项目/工作区选择也只列本机资源，不从当前远程工作区推导默认值。讨论仍使用现有局域网协作，不接管远端 Mac 的讨论管理；其修改操作遵守本机实例控制状态，不能因当前远端已接管而绕过本机检查。
- 工作区技能文件按远端文件处理。全局技能安装、手机配对、应用更新与系统授权等设备管理明确标为本机或提示在目标 Mac 操作，不全面远程化这些模块。
- 查看模式覆盖全部修改入口，包括菜单、快捷键、确认回调、自动清理/auto-fetch 等后台动作；旧窗口不能绕过控制状态发起新的桌面写操作。只保留服务端仍需的独立维护和 hooks。
- 主机菜单、接管/收回控制、查看状态、远端目录选择和断线界面先做深浅离屏预览。沿用 style、keymap、自绘菜单与 locales/errtext，不新增一排逐终端控制按钮。

## 9. 实施顺序与验收

| 阶段 | 交付 | 必须证明 |
|---|---|---|
| 0. 全局导航 | 常驻图标栏、模块侧栏、固定工作区迁移与选择恢复 | 旧固定项保序；聊天/工作区返回正确；讨论草稿及附件切换不丢；收起侧栏后错误/更新入口仍可达；深浅和窄窗口正常 |
| 1. SSH 基础 | 配置、认证、发现、隧道、能力握手与诊断 | SSH config/路径引用正确；复用 master；断开不停止 daemon；不兼容明确报错 |
| 2. 主机接管 | 主机状态隔离、整体控制会话、项目工作区与终端 | 接管/收回覆盖全工作区；旧端迟到输入/写请求无效；不串主机；agent 继续运行 |
| 3. 文件 | 文件服务、条件保存、搜索预览、上传/下载、无 UI 废纸篓 | 失去控制/断线/切主机保留 dirty 内容；保存回复丢失能核对；不覆盖外部改动 |
| 4. Git | 完整 Git 服务、必要协调、当前实例结果缓存、升级门禁 | 稳定目标和 autostash 语义不丢；回复丢失不重复执行；保存与 checkout/reset 协调；忙时不能交接 |
| 5. 工作区收口 | 历史/任务/用量归属、设备入口检查、文档、真实双 Mac | 所有主路径作用于目标机器；旧 UI 数据兼容；完整工作区通过双机验收 |

阶段 2 仅验证接管基础，阶段 3–5 完成才算满足完整工作区需求。写操作执行器、协调及交接门禁按相关入口迁移同步落地，不能先把不受保护的远端写功能交付给用户。

关键测试：

- 相同资源 ID/路径的两台主机不串，旧主机异步结果不覆盖当前视图；旧 ui.json 正确迁移。
- 整体接管、收回、保活超时、重连与正常 handoff；查看端输入/resize/自动回复/菜单/后台修改均受限，dirty 文档保留；已接受操作不因换控制端重复或被隐式取消。
- 查看者点开 lost/待恢复终端不新增进程、不修改恢复记录；接管后可恢复，恢复与 handoff 门禁互斥。
- 手机尺寸与输入、现有 GUI/插件 attach、CLI terminal send/resize、agent hooks 正常；终端快照不产生重复应答，断线按键不重放。
- 工作区、聊天、讨论往返切换后选择正确，讨论文字/引用/附件和文件 dirty 内容保留；收起侧栏后全局错误/更新入口仍可达。
- 远端聊天使用目标配置与目录，只查看不创建；远端工作区模式进入本机讨论时，列表、附件、草稿及项目选择均留在本机，所有请求绑定对应 Client，不串主机。
- 保存中继续编辑、保存回复丢失、接管前旧确认、agent 外部改文件；磁盘内容相同和冲突两种核对结果。
- UI 确认储藏删除后手机/CLI 新建储藏；排队更新时分支改变；保存与 reset/手机 checkout/workspace remove 交错；固定锁序不死锁。
- Git 成功但响应丢失可在同一实例查询；daemon 重启/缓存过期后显示未知而非自动重试；typed autostash warning 往返保留恢复入口。
- 长 Git/保存遇到升级返回 busy，完成后可交接，新旧代不并行写；正常取消和退出回收子进程。
- 无远端 GUI 也能移到废纸篓；权限失败保留文件。远端预览不访问本机路径，上传失败不粘贴本机路径。

## 10. 实施与交付约束

- 实现前重新读取根 AGENTS.md 并检查 Git 状态，保护已有工作；需要隔离时用 `posse workspace create ... --mode worktree`。未经要求不提交、不合并、不发布。
- 本机集成使用 `$TMPDIR` 下隔离 home、仓库及故障注入；UI 使用 `scripts/dev-app.sh` 的 PosseDev 和离屏预览，默认无头，不抢窗口。临时截图/日志放 `$TMPDIR`。
- 最终用两台真实 Mac 的开发包和开发 home 验证接管、完整文件/Git、断网恢复、休眠/唤醒、TCC、版本不匹配、图片粘贴与手机共存。第二台机器及远端安装目标在双机阶段前确认；不可拿本机双 home 代替双机验收。
- 不触碰日常 `~/.posse` 或日常 Posse.app，不自动交接日常 daemon。不可用的架构/实机场景标为未验证，不报告全部通过。
- 按阶段运行相关测试；集成后执行项目要求的 build/vet/test、`go tool mygo vet` 和 i18n check，Go 测试清除 `GIT_TRACE2_EVENT/GIT_TRACE2_ENV_VARS`。改译文生成 catalog，gofmt 使用工具链版本。
- 检查空闲连接、多次接管/重连后的进程、描述符、goroutine 与 `footprint`；对照本机基线，不给未经测量的固定内存承诺。
- 同步远程功能说明、`docs/features/{ui,files,git,history,agents}.md` 及根 AGENTS.md 中已变化的文件/Git 执行约定。正式实施文档放 docs/plans，个人验收报告放 `$POSSE_NOTES`。

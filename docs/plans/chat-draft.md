# 手机对话页：正在输出的草稿

## 目标

agent 回复时，手机对话页像终端一样一段段看到正文，不必等整段写进会话文件。第一版只做 Claude、Codex。

## 依据（2026-10-28 实测）

用测试常驻进程起真实的 Claude 2.1.312、Codex 0.163（100×40），各写约 300 字，每 200ms 读一次屏幕：

| | 屏幕上第一行 | 屏幕上写完 | 会话文件写入正文 | 会话文件比屏幕晚 |
|---|---|---|---|---|
| Claude（418 字） | 发出后 2.4s | 6.2s | 与写完同时 | 约 3.7s，随长度增长 |
| Codex（340 字） | 约 6s | 约 20s | 本轮结束时 | 约 14s |

- Claude 的会话文件按内容块写：thinking、text、tool_use 各在写完时成一行，正文整块到。Codex 的回复在 `task_complete` 前才写。
- 屏幕上的文字是 TUI 渲染过的：按终端宽度硬折行、续行缩进 2 格；Claude 去掉了 `##`、`**`、反引号和代码围栏，表格画成框线；Codex 保留 `## `，列表换成 `•`，代码围栏去掉。所以草稿只能当纯文本，正式消息到了再换成 Markdown。
- 回复开头：Claude 是第一列的 `⏺`，Codex 是第一列的 `•`；状态行分别是 `✻ …`、`• Working (…)`（`internal/mobile/status.go` 已经在认）。

## 方案

```
chatStream（internal/mobile/chat.go）
├── chatTick        读会话文件（不变）
├── sendStatus      认状态行（不变）
└── sendDraft       新：和 sendStatus 共用节流（250ms）和同一份屏幕
      agentDraft(agent, lines) → draft.go
```

1. **取草稿**（`internal/mobile/draft.go`）
   - 只在认得出状态行（agent 在干活）时取；状态行消失后推一次空草稿。
   - 从状态行往上找最近一个回复块的开头：Claude 取 `⏺` 开头、不是工具调用（`⏺ Name(…)` 后面跟 `⎿` 的是工具）的块；Codex 取 `•` 开头、不是 `Working`、`Ran`、`Explored` 这类条目的块。块的范围到状态行或下一个第一列开头的块为止。
   - 接回折行：去掉续行的 2 格缩进；上一行行尾和下一行行首都是中日韩文字就直接拼，否则补一个空格；空行保留成段落分隔；框线表格和缩进的代码行原样保留（手机用等宽字体画）。
   - 去重：记住会话文件里最近一条助手正文（规范成同样的纯文本），草稿和它相同或是它的前缀就不推。块写进文件后，屏幕上的同一段不会再被当成草稿。
2. **回复超出一屏**：开头已经滚进回滚区时，只看屏幕找不到 `⏺`。`term.Terminal` 加一个只取最后 N 行（含回滚区，N 约 200）的接口，不用 `Lines()`：那是整个回滚区（最大 4 MB），每 250ms 转一遍太重。屏幕里找到块开头就只用屏幕。
3. **协议**：对话流里加 `{"type":"draft","text":"…"}`，空串表示撤掉；声明 `posse.draft.v1` 的连接才发。变了才推。旧手机不受影响。
4. **手机**（`mobile/lib/chat/chat.dart`）
   - 收到 `draft` 后在消息和本地回显之后、状态行之前画一个草稿气泡：纯文本，框线和缩进的行用等宽字体，标「正在输出」。
   - 撤掉的时机：收到空草稿、会话文件里出现新的助手正文（`_window.applyFrame` 之后）、对话流断开。
   - 滚动沿用 `_anchor(before)`：停在底部时跟着长，往上翻着看时不动。
5. **文档**：`docs/features/mobile.md` 的「Posse 扩展协议」加 `posse.draft.v1`，「对话页与历史」改掉「Claude 的回复整段写完才进会话文件」那条的说法。

## 步骤

1. **补录屏幕**：用测试常驻进程（`POSSE_HOME=/tmp/...`，Codex 用已信任的目录）录这几种，存成 `internal/mobile/testdata/draft/*.json`，只留变化的帧：
   - 超过一屏的长回复；
   - 先调工具再写正文的一轮；
   - 带 Markdown（标题、列表、代码、表格、中英混排）。
   
   Claude、Codex 各一套。2026-10-28 的两份录制在 `/tmp/posse-stream/`，可能已被清掉，以重录为准。
2. **常驻进程**：`draft.go` 和单元测试（逐帧回放：草稿只增不减、和最终正文的纯文本一致、工具块不进草稿、写进文件后不再推）；最后 N 行的接口；接进 `chatStream`；能力声明。
3. **手机**：草稿气泡；在 `mobile/test/chat_scroll_test.dart` 的假 RPC 里推 `draft` 帧，测在底部时跟随、往上翻时不跳、正式消息到了撤掉。
4. **实测**：iOS 模拟器（iphone-sim）接测试常驻进程，真实 Claude、Codex 各跑一次长回复，看草稿延迟和替换时有没有跳动。

## 注意

- `internal/mobile/chat.go`、`methods.go`、`mobile/lib/chat/chat.dart`、`mobile/lib/protocol/rpc.dart` 现在有别的会话没提交的改动，动手前先等它们提交，或者只在新文件里写、最后再接进去。
- TUI 改版会让规则失效：步骤 2 的回放测试就是为此留的，Claude、Codex 升级后重录一次对比。
- 不做：还原 Markdown、Grok 和 Cursor、桌面端。

## 进度（2026-10-29）

已实现：`internal/mobile/draft.go`（取草稿、跨帧拼接）、`chat.go` 接进对话流、`posse.draft.v1`；手机 `mobile/lib/chat/draft.dart` 草稿气泡，`chat.dart` 撤掉和滚动。录制在 `internal/mobile/testdata/draft/`（Claude 2.1.312、Codex 0.163，100×32，gzip 的 JSON：只留变了的屏幕帧，带这一轮写进会话文件的助手正文和写入时刻、录制前最后一条回复），`TestDraftReplay` 回放（`*-live` 两段是下面模拟器实测时录的）。

补录后和上面方案不一样的地方：

- **流式写正文时两家都没有状态行**：Claude 的 `✻ …` 在正文出来后就不画了，Codex 的 `• Working` 也一样。所以「只在认得出状态行时取」改成 agent 在干活（hooks 报 working，或者有状态行）时取。
- **回滚区里没有回复**：Claude 每次重画连回滚区一起清掉（`terminal read --lines 200` 永远只有屏幕那几行），Codex 在备用屏幕上。所以没加「最后 N 行」的接口；回复超出一屏后，每帧只取看得见的部分，和上一帧拼好的接起来（在已拼的行里找这一帧第一行，后面的行也对得上就从那里接上，正在写的末尾几行和空行不比；接不上时中间写 `⋯`）。手机中途才打开对话页时，看不到已经滚出屏幕的开头。
- Codex 回复滚出屏幕后，顶上一行钉着截断的用户提示（`› ……`），要跳过；一轮结束后正文下面多出 `└ Tip: …` 和 `Worked for …`。
- Codex 写完一段重排时偶尔有一帧画错（正在写的那行换成下一段开头，下一帧又好了），同一块草稿缩回去时最多按住 4 帧。
- Claude 开始调工具时先只有一行 `⏺ Reading 1 file…`，`⎿` 稍后才画；进行中的工具块头上的 `⏺` 会闪，闪灭时看着像上一块的续行。
- 会话文件可能比屏幕上最后一两行先到（Claude 约 0.1s）。

录制注意：测试常驻进程是没签名的 `go build` 二进制，项目放在「桌面」「文稿」下会弹系统授权框挡住它（git、agent 都卡住），录制目录要避开；Claude 用它已信任、不在受保护目录下的目录（不同意新的信任框）。

模拟器实测（iPhone 17 模拟器，测试常驻进程，真实 Claude、Codex 各写约 1500 字；电脑每 200ms 读屏，手机每 150ms 查一次「正在输出」）：

| | 屏幕上第一行 | 手机出草稿 | 会话文件写入 | 手机换成正式消息 |
|---|---|---|---|---|
| Claude | 2.24s | 2.20s | 17.81s | 18.15s |
| Codex | 3.06s | 3.35s | 83.63s | 83.76s |

出草稿的延迟在两边的采样间隔以内；草稿比正式消息早 15s（Claude）、80s（Codex）。停在底部时草稿一段段长、贴着底部；往上翻着看时草稿变长画面不动。换成正式消息时：翻到最顶上的情况下起初上移约 35pt（草稿用整行空行分段，比 Markdown 的段距高，内容变矮后被顶端夹住），草稿改成按段、段后 6 以后，停在列表中间时还有约 8pt 的下移，原因没查清。

Posse 的 Git 操作计划（参照 WebStorm）

2026-10-16

目标与范围

按你在 WebStorm 里实际用得最多的操作，在 posse 里做一套 Git 界面：改动列表和 diff、分支弹窗、和分支比较、Push、Git 日志。每个工作区（包括 agent 的 worktree）各自一份。全部在窗口进程里调用系统 git，不改常驻进程。

依据：你的 ~/Library/Application Support/JetBrains/WebStorm2025.3/options/actionSummary.xml（各操作的使用次数）、vcs.xml、diff.xml；界面细节取自 JetBrains 官方 WebStorm 帮助文档的截图（2026.2 版，你装的是 2025.3.3，都是新版界面，结构相同是推断，解锁后再对照你的 WebStorm 核实）。

不做：GitHub/GitLab 的 PR 和代码审查、子模块、多仓库同步、本地历史（Local History）、三方合并工具的完整版本（第 5 阶段只做简化版）。

提交只有 27 次，审查和整理分支的操作却有上千次：提交多半是 agent 做的，你主要在看改动、比较分支、同步和整理分支。posse 的 Git 界面也照这个重心来设计。

WebStorm 界面要点

以下来自官方文档截图（管理分支、提交和推送、查看改动），posse 照这个结构做。

界面结构
分支弹窗点顶栏的分支名打开。顶部是搜索框，右上角是 Fetch 按钮（你用得最多的 1956 次就是它）和设置。下面三组：Update Project ⌘T、Commit ⌘K、Push ⇧⌘K；New Branch ⌥⌘N、Checkout Tag or Revision；然后是 Recent、Local、Remote 三组分支。远端分支按前缀分成文件夹（feat、renovate），收藏的分支前面是星号，有待推送提交的分支后面有绿色箭头，右侧灰字是跟踪的远端分支
分支的子菜单Checkout；New Branch from…；Checkout and Rebase onto 当前；Checkout and Update（远端分支）；Compare with 当前；Show Diff with Working Tree；Rebase 当前 onto 它；Merge 它 into 当前；New Worktree from…；Update；Push…；Rename（F2）；Delete
Compare with在日志里列出两边各自独有的提交
Show Diff with Working Tree按目录分组的文件树，目录后写文件数；顶部一行"差异来自哪两边"，可以对调
Commit 工具窗口工具栏：刷新、回滚、搁置、预览 diff、展开 / 收起；改动列表带勾选框，文件名后面灰字是目录；下面是 Amend 勾选、提交信息、Commit 和 Commit and Push 两个按钮
Push 对话框左边"本地分支 → origin : 远端分支"下列出要推的提交；右边是选中提交改的文件树和提交信息；底部 Push tags 勾选，Push 按钮带下拉（强制推送在下拉里）
Git 日志左边是分支树（HEAD、Local、Remote），中间是提交图和筛选栏（文字或哈希、正则、大小写、Branch、User、Date、Paths），右边是选中提交改的文件和提交信息
Annotate行号左边一栏写日期和作者，同一次提交的行底色相同，悬停显示提交哈希、作者、时间和提交信息

功能对照

WebStorm 的几个界面在 posse 里都有对应的位置。文件标签已经有左栏和文档区，Git 界面放进去，不另开窗口。

WebStormposse 里的位置现成的基础
Commit 工具窗口（改动列表）文件标签左栏加第三段"改动"（带数量），和"文件""检索"并列左栏的分段、文件树的行样式
diff 查看器文档区里的 diff 标签页，和打开的文件并列mygo 的 editor.DiffView：左右对照或上下合并、行内改动、折叠、逐段回滚、跳到下一段
编辑器行号旁的改动标记文件标签里打开的文件，行号旁标出相对 HEAD 的改动，可回滚一段editor.State.DiffBase 和 RevertHunk 命令
状态栏的分支弹窗标签栏右边已有的分支名，点开就是分支弹窗；终端标签下也能用标签栏的分支名（metaMono）

Push 对话框对话框：列出要推的提交，可选强制推送现有的对话框样式
Git 工具窗口的日志文档区里的"日志"标签页：提交图、分支筛选、提交详情无，要新做；思路参考 Mayoi 的 graph.go
Annotate、文件历史编辑器右键菜单和文件标签的操作无，要新做

关键决策

事项决定理由
进程窗口进程直接调系统 git，扩展 internal/gitx（状态、diff、分支、日志、推送）；常驻进程不动改常驻进程的协议要重启，会断开终端；git 本身就是事实来源
范围每个工作区一份 Git 视图，操作作用在这个工作区的目录上；worktree 工作区就是 agent 的分支posse 的工作区和 worktree 一一对应，审查 agent 的成果最直接
刷新改动列表随文件标签的轮询自动刷新（看得见时每秒检查一次 git status 的变化），不需要手动点WebStorm 里点了 1230 次刷新，正是因为它不总是自动刷新
和 agent 并行agent 正在工作的工作区，切分支、rebase、reset 这类会改动工作目录的操作先提示"agent 正在这个工作区里工作"agent 和人同时改一个目录，容易互相覆盖
被其他 worktree 占用的分支分支弹窗里标出"在 xx 工作区里"，点切换时跳到那个工作区，而不是报错git 不允许同一分支在两个 worktree 里检出；posse 正好知道每个 worktree 是哪个工作区
有破坏性的操作强制推送用 --force-with-lease；删除未合并的分支、reset --hard、回滚文件都要确认，确认框里写清会丢什么防止误删别人的提交和未保存的改动
忽略空白diff 默认忽略空白差异（和你的 WebStorm 设置一致），可以切换。mygo 的 DiffView 没有这个选项，要改 third_party/mygo，改动记进它的 POSSE.md你在 WebStorm 里就是这样设的
快捷键沿用 WebStorm 的：F7 / ⇧F7 下一处 / 上一处改动，⌘K 提交，⇧⌘K Push，⌥⌘N 新建分支，⌥⌘Z 回滚；WebStorm 的"更新项目"是 ⌘T，和 posse 的新建终端冲突，不沿用，放进分支弹窗保持肌肉记忆
Rebase 一类的交互操作squash、reword、drop 用 git rebase -i 配一个由 posse 生成的 GIT_SEQUENCE_EDITOR 脚本，不打开编辑器和 WebStorm 一样在界面里完成

分阶段步骤与验收

按你的使用次数排序：先做看改动和 diff，再做分支，最后做日志和冲突。每个阶段单独提交，单独可用。

  1. 改动与 diff
    • 左栏"改动"：已暂存、未暂存、未跟踪三组，文件名后面写所在目录和增删行数；点开是 diff 标签页
    • diff：左右对照或上下合并、忽略空白、F7 / ⇧F7 跨文件跳到下一处改动、逐段回滚、从 diff 跳到编辑器里的同一行
    • 文件操作：回滚（确认）、加入 git、取消暂存；编辑器行号旁标出改动，可回滚一段
    • 提交：提交信息框加"修改上一次提交（amend）"；储藏用 git stash（含未跟踪文件，照 WebStorm 叫"储藏"；WebStorm 的"搁置"是 IDE 自己存的补丁，不做），列表里可弹出、应用
    • 验收：internal/gitx 的单测在临时仓库里覆盖状态解析（重命名、冲突、未跟踪）、逐段回滚、stash 往返；界面测试覆盖改动列表、F7 跨文件、回滚确认；离屏预览深浅两套
  2. 分支弹窗和比较
    • 点标签栏的分支名打开，结构照 WebStorm：搜索框和右上角的 Fetch 按钮；更新、提交、Push；新建分支、检出标签或修订；最近、本地、远端三组，远端按前缀分文件夹；收藏、待推送 / 待拉取的箭头、跟踪的远端分支
    • 每个分支的子菜单照 WebStorm 的顺序：检出、基于它新建分支、检出并 rebase 到当前分支、和当前分支比较、和工作区比较、把当前分支 rebase 到它上面、合并到当前分支、基于它新建工作区（调用 posse 的 worktree 工作区，代替 WebStorm 的 New Worktree）、更新、Push、重命名、删除
    • "和当前分支比较"：两边各自独有的提交两列，点提交看改动；"和工作区比较"：按目录分组的文件树，点文件看 diff
    • 验收：单测在本地建一个裸仓库当远端，覆盖 fetch、更新（快进和分叉两种）、删除未合并分支要确认、被其他 worktree 占用的分支；界面测试覆盖弹窗搜索和比较页
  3. Push
    • 对话框列出每个要推的提交，第一次推送自动设上游；强制推送用 --force-with-lease，被拒时说明原因（远端有你没拉的提交）
    • 验收：单测用裸仓库覆盖普通推送、设上游、强制推送被 lease 拒绝
  4. Git 日志
    • 日志标签页：提交图、按分支 / 作者 / 文字筛选、标签名；选中提交看改动的文件和 diff
    • 提交的操作：cherry-pick、reset（soft / mixed / hard，hard 要确认）、revert、reword、squash、drop
    • 文件历史和 Annotate（每行是谁、哪次提交改的，点了跳到日志里的那次提交）
    • 验收：单测覆盖 log 解析（合并提交、标签）、交互式 rebase 脚本生成的 todo；界面测试覆盖筛选和 cherry-pick 冲突时出现提示
  5. 进行中的操作和冲突
    • rebase、merge、cherry-pick 进行中时，顶部显示横幅（继续 / 中止 / 跳过）；冲突文件单列，可以用"采用我的 / 采用他们的"，或在编辑器里改完后标记为已解决
    • 验收：单测制造冲突，覆盖继续、中止、采用一方

每个阶段都要跑 go vet ./... && go test ./... && go tool mygo vet；测试只在临时仓库里做，不碰你的真实仓库。

可以借鉴 Mayoi（只借鉴思路，不复制代码）：internal/git/git.go（status --porcelain=v2 解析、StageText 按段暂存）、cmd/mayoi/scm.go（改动分组）、diffhunks.go（逐段暂存和回滚）、graph.go（提交图）、blame.go。

风险

风险应对
mygo 的 DiffView 没有忽略空白的选项第 1 阶段先在 third_party/mygo 里加；加不上就先在 posse 这边比较时规范化空白，只用来决定显示哪些段
大仓库的 status 和 log 慢在后台执行，只在看得见时轮询；日志分页加载，每页 200 条
人和 agent 同时操作同一个工作区会改动工作目录的操作先检查 agent 状态并提示；所有写操作之前重读一次 status
文档截图是 2026.2 版，你用的是 2025.3.3解锁后打开你的 WebStorm 的分支弹窗和 Commit 窗口核对一次

实现结果（2026-10-16）

五个阶段都已实现，在 调研 分支。两个问题按默认：分叉时更新用 rebase；提交只做"全部提交"和"只提交已暂存的"。

和计划的出入原因
Annotate 是单独的标签页（每行左边是日期和作者，点了看那次提交），不在编辑器行号旁mygo 的编辑器行号栏只能画圆点，画不了文字
合并提交只做"和上一个提交合并"，不支持多选几个提交一起合并日志列表暂时不支持多选
diff 只忽略空白，不忽略空行去掉只增删空行的段会让左右两边对不齐
远端分支按远端名分组，没有再按前缀分文件夹；没有收藏分支先做常用的，靠搜索框找
冲突只能整个文件采用一方，或在编辑器里改完标记为已解决；没有三方合并工具和计划一致（简化版）

需要你决定

  • "更新分支"在本地和远端分叉时用 rebase 还是 merge？WebStorm 里是按项目设置的，我在你的配置里没找到。我默认用 rebase，你平时的 rebase 次数（315）也比 merge（2）多得多。
  • 提交入口要不要做得和 WebStorm 一样完整（勾选部分文件、按段勾选）？你提交得少，我默认只做"全部提交"和"只提交已暂存的"，按段暂存放到以后。

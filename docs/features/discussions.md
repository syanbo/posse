# 讨论

用户在一个讨论里和多个 agent 成员交流：普通消息只是发言，@ 一个成员就为它排一轮执行，成员在自己的专用 worker 终端里做完，把完整回复发回讨论。讨论是长期记录，任务和终端只是执行载体。第一阶段是本机单用户；局域网多人见本文末尾。

## 数据

```text
internal/collaboration   安装身份 $POSSE_HOME/collab.json（Ed25519，0600、原子写入，与 mobile.json 无关），第一次建讨论时生成
internal/store/discussion.go
├── discussions      roomKey = <安装身份公钥 SPKI 的 SHA-256 指纹>/<128 位随机讨论 ID>；标题、描述、项目（ID、名字、路径快照）、默认工作区、归档、版本
├── disc_members     成员配置（名字、职责、agent、模型、思考深度、执行工作区、配置版本）、绑定的 worker 任务、队列暂停原因、接收位置
├── disc_messages    讨论内序号、作者快照、正文、引用、@ 的成员、附件、关键标记、客户端请求 ID 和源事件 ID（各自唯一）
├── disc_executions  每条 @ 一轮：状态、预分配的任务、worker、配置快照、冻结的上下文快照和接收确认、回复
└── disc_meta        全局变更序号
tasks.discussion_id      讨论成员专用 worker 的任务属于哪个讨论（roomKey）
```

- 讨论数据对项目、工作区、任务不建级联外键，存名字和路径快照：清理任务、移除成员、删项目后历史和关键结论照样可读。
- 消息、成员、执行每次改动都在事务里推进讨论版本（`rev`）和全局序号；界面轮询列表只看全局序号，打开的讨论按版本取增量（消息追加、执行状态、关键标记、成员变化都在增量里），历史按序号分页往前取。打开讨论只取最新一页消息和这页涉及的执行（加上没结束的），不全量加载；worker 终端的实时状态不推进版本，每次轮询都随详情带上（`live`）。
- 已发送的消息和回复不提供编辑、撤回、删除；更正用新消息引用原文。取消执行不删源消息。

## 一轮执行

```text
用户 @ 成员（discussion.post，客户端请求 ID 去重）
└── 消息和 queued 执行同一事务落盘
    └── 调度（discussion.go 的 dispatchAll：发消息、worker 空闲、用户确认时踢一次，3 秒兜底）
        ├── 同成员有进行中的一轮 → 等
        ├── 同一真实目录有别的讨论成员在执行 → held，等「仍然继续」「改用独立 worktree」或取消；冲突结束后自动回到队列
        ├── 没有 worker：queued → starting（条件更新，预分配任务 ID）→ 拉起专用 worker → 事务里登记任务、转 running、绑定成员
        └── 有 worker：上一轮 done 且回答结束（Codex 按同轮 Stop，其余按空闲） → 事务里重开任务、追加提醒、转 running；worker 已不在 → blocked
            └── worker：posse discussion read --execution X（分页，读完才算接收）
                ├── posse task ask <task> --execution X → 讨论里出现待回答的问题，群里或任务页回答（同一事务，只接受一次）
                └── posse task done <task> --execution X --body-file F → 完整回复进讨论，执行转 done/failed
```

- Codex 复用 worker 时，用 UserPromptSubmit 与 Stop 的 `turn_id` 对齐回答：上一轮已汇报（任务 done）且当前回答已结束（Stop，或 Esc 中断发的 Interrupt）才派下一轮，汇报后用户自己问的一轮结束同样放行；后台命令让 OSC 保持 working 不阻塞队列，也不改变终端的工作中显示。旧轮次的 Stop 不放行新轮次，Stop 若交了继续执行的提醒则仍等待。轮次状态随常驻进程交接保留；没有带轮次的 hook 时沿用空闲判断。
- 同一成员严格串行，不同成员可以并行。后来的 @ 排队，不经 `task.send` 往同一轮里追加。
- 讨论任务的 `done`、`ask`、`check` 必带 `--execution`；缺了或不是当前一轮都拒绝，报错给出 `posse discussion pending` 重新领取，不自动补成当前轮。迟到、重复的汇报结束不了下一轮：轮次校验和任务、讨论回复在同一事务里。
- 完整回复是 `--body`/`--body-file` 的正文（Markdown），`--summary` 可省（取正文第一行）；任务页照常显示摘要。
- 启动提示只带身份、轮次和领取命令；正文统一经 `discussion read` 领取：当前请求和引用在前，然后是关键消息，最后是成员还没接收过的讨论消息，每条带作者、序号、来源和附件的绝对路径，正文注明是讨论材料而不是系统规则。每次最多返回 32 KiB，附带续读命令；CLI 输出之后再确认接收（幂等），只有连续确认的部分推进成员的接收位置，没读完不能汇报完成。`discussion read <讨论> --from N --to M` 按序号补读，不算接收。
- 一轮进行中 worker 退出：这一轮记中断、成员队列暂停，等「重新启动并继续」（关掉旧 worker、新开一个接着做队列）。两轮之间 worker 不在了：下一轮受阻，同样要重新启动。工作区删了、agent 关掉、拉起失败：这一轮失败并写明原因，队列暂停，不自动循环重试；失败、中断、停止、取消的一轮可以「重试」，另排一轮并记下来源。 每一轮只能重试一次（`retry_of` 唯一）。同一轮同样内容的 `task done` 重跑（响应丢了）当作成功，不同内容拒绝，都不碰已经开始的下一轮。
- 停止进行中的一轮会关掉这个成员的专用 worker（丢掉它的对话上下文），下一个请求新开 worker；任务页的「关闭 worker」一样。
- 权限：读取、确认、汇报只接受这一轮 worker 自己的终端（终端之外的用户手动操作不限）。调用方 ID 由本机进程报，可以伪造，这是防误用，不是隔离恶意 agent 的安全边界。 反过来，讨论里用户的操作（建讨论、改成员、发言和 @、回答、关键标记、取消、停止、重试、确认、改用 worktree、归档）拒绝来自任务 worker 终端的调用：worker 只经 `task done/ask` 汇报，不能以用户身份发言或给别的成员排请求；窗口、终端之外和不是 worker 的终端照常。同样是防误用，不是安全隔离。

## 与任务的关系

- 成员第一次被 @ 才拉起专用 worker：一个 `DiscussionID` 不为空、派发方为空（用户）的任务，终端也出现在工作区里，可以从讨论打开。
- 任务页对讨论任务给「打开讨论」，不给追加；常驻进程拒绝讨论任务的 `task.send`，`task retry` 在 CLI 按 `DiscussionID` 拒绝并指向讨论。任务页可以回答讨论 worker 的问题，和讨论里是同一个答案。
- `task clear` 跳过成员当前绑定的任务（两轮之间它是 done/failed，还要接着用）；解绑后的可以清，讨论里的回复和执行快照不受影响。
- 讨论 worker 的问题和回复由讨论发系统通知（`posse-disc:<roomKey>`，点了打开讨论），任务不再为同一次汇报发通知。

## 成员

- 成员配置属于讨论：名字、职责、agent、模型、思考深度、执行工作区（讨论项目里的已有工作区，或新建 worktree；非 git 项目只能选已有目录）。同一家 agent 可以有多个成员。
- 改配置只对新 worker 生效，已有 worker 照旧（执行快照记实际用的配置）；「立即应用」要求成员没有进行中、排队的请求，关掉旧 worker（丢失上下文）。 检查请求、改配置、解开旧 worker 在一个事务里，有请求时什么都不改。
- 移除成员要先处理完它的请求，关掉它的 worker；历史署名不变。再添加是新的成员 ID，不接回旧 worker、队列和接收位置。
- 同目录检查只覆盖 Posse 知道的讨论执行，按路径解析符号链接比较，不是文件锁。独立 worktree 保留分支和改动，由用户审阅合并。

## 附件、关键消息、搜索、未读、归档

- 附件：用户选的本地文件和粘贴的图片在发送时复制到项目的 `.posse/discussions/<讨论 ID>/attachments/<附件 ID>/` 下（git 项目的 `.posse/` 在 info/exclude 里），库里存相对项目目录的路径，交给 agent 时按项目现在的目录给绝对路径。每条最多 10 个、单个最多 20 MiB，超限、读不到时报错。文件不在了显示不可用、上下文里标 missing。 粘贴图片写的临时文件在发出去、从草稿去掉或离开讨论时删掉。
- 关键消息：任何消息都能标星或取消，右边一栏列出、点了跳回原处；关键消息进成员的上下文，但不是执行指令，也不自动唤醒谁。
- 搜索限当前讨论（正文、附件名、作者），结果点了定位：不在读进来的那段里时取以它为中心的一页（不管多远），引用的原文按消息 ID 定位。读进来的消息最多 10 页（500 条），往前翻时丢掉最新的一头、往后翻时丢掉最早的一头，回复的 Markdown 缓存跟着放掉；看着更早的一段时新消息不接上来，底部给「加载更新的消息」和「跳到最新」。跳到最新、换讨论这类意图有代号：之前发出、晚到的轮询或翻页结果按代号或窗口判成过期丢掉，不会把窗口拉回旧的一段或把增量版本写回去。
- 未读按讨论记在 ui.json 的 `discRead`（看到的最新序号），只有你看到底部才推进；agent 读取上下文不影响未读。往上翻着时新消息不把列表拉到底，底部给「N 条新消息」。
- 归档：要求没有排队、等确认、受阻、启动中、进行中、等回答的请求（检查和发送、入队在同一事务边界里），否则列出要先处理的请求。归档后只读，不关任何终端；恢复不重跑旧请求。归档的讨论可以「清理附件」：列出文件和占的空间，确认后把每个附件的目录移到废纸篓（`attachments/` 空了也移走），消息和附件信息留着。

## 重启与交接

- 普通重启：进行中的一轮记中断，启动一半的记启动失败，排队的保留但成员队列暂停，等用户确认后继续。
- 升级交接：旧进程在交接开始后不再派发（失败才恢复）；新进程马上可以服务读取、提问和汇报，拿到 `possed.lock` 之后才对账和派发，免得把旧进程还在启动的一轮判成失败；交接过来的 worker、队列和待回答的问题照常继续。不往 handoffTerm 加讨论字段，也不改 handoffVersion。
- queued → starting 是带 `state='queued'` 条件的更新，交接空档里两代进程都来派发也只有一个改得动。

## CLI

`posse discussion list | create | show | add-member | update-member | remove-member | restart | post | answer | read | pending | search | key | cancel | stop | retry | confirm | isolate | archive | restore`，各自 `-h` 看用法。worker 用的是 `discussion read`、`discussion pending` 和带 `--execution` 的 `task ask/check/done`。

## 界面

侧栏「讨论」磁贴（等你回答时是琥珀色蜂巢格，否则写未读的讨论数）。左边讨论列表（进行中按最近消息排，归档的在后面），中间是顶栏（标题、项目、成员数、搜索、详情栏开关、更多）、消息区和输入区，右边可收起的一栏是详情、成员和关键消息，搜索结果也在这里。

- 输入区左上角的接收者标签一直写明发给谁：「所有人」（只是发言）或 @ 一位成员（作为请求执行），不另加说明文字，输入框的提示写「给 X 的请求」；引用、附件在输入框上面，⌘↩ 发送，回答问题时换成回答模式。在输入框里打 @（全角＠也算，前面紧挨英文字母、数字的不算）弹出候选：自己的 Agent、别人的 Agent、群里的人，上下键选、回车或 Tab 选中、Esc 关掉；候选靠图标分 Agent 和人，只有用不了的别人的 Agent 写一句「提醒 X 安排」。选能用的 Agent（自己的，和拥有者在访问设置里放开给你的）或人时，@ 和打的字从正文里去掉，换成接收者：Agent 作为请求执行，人只提醒；选没放开给你的别人的 Agent 时，名字留在正文里，接收者换成提醒它的拥有者。
- 每条请求下面是它的执行状态：结束了的（完成、取消、停止）和别人电脑上正常进行的收成一行小字，只写状态，后面跟「打开终端」「查看任务」文字链接；要处理的才是卡片。发给谁看消息上的 @ 标签，在哪台电脑、哪个工作区看右栏的成员，执行状态里不重复。卡片：状态（排队、待确认、受阻、启动中、进行中、等你回答、完成、失败、中断、停止、取消）、成员、工作区和原因，按状态给打开终端、查看任务、取消、停止、重试、仍然继续、改用独立 worktree、重新启动并继续。成员队列暂停时输入框上面给「重新启动并继续」。
- 自己发的发言、请求和回答靠右、不铺底色，最宽是消息区的八成，不写名字，最右边是自己的头像，标签和时间在正文上面一行；请求的执行状态跟在下面，也靠右。别人和成员的消息靠左。消息不铺底色：悬停只露出引用、标关键两个按钮，@ 你的消息靠「@你」标签，只有跳转到某条时高亮两秒。右栏没有描述时不写「没有描述」，没有关键消息时不显示这一节，成员行不重复写 agent 名（看图标）。
- 成员的回复按 Markdown 渲染，报告文件可点开；悬停一条消息给引用、标关键，右键复制。
- 图片附件（png、jpg、gif、webp）直接显示：等比放进 320×320 的框，小图不放大，同一条消息的图排成一行、放不下就换行；点击用默认程序打开，右键可复制图片、在访达中显示、用预览打开、复制路径。只解码看得见的（上下多算一段），解码前先读文件头：原图超过 24M 像素或文件超过 50 MB 就不解，显示成文件标签；缩略图按 2 倍屏限制像素，整个窗口最多留 24 张、每帧最多要 24 张、同时解两张，看不见的先被挤掉，尺寸留着，滚回来时占位块不跳。动图只显示第一帧。其他文件、不在了或解不开的图片照旧显示成文件标签。

## 局域网多人

房主（建讨论的那台电脑）在讨论里「在局域网分享」，生成一次性邀请交给对方；对方在「加入讨论…」里粘贴邀请、发出申请，房主批准后成为成员。每个人带自己电脑上的 Agent：默认只有拥有者能 @ 它，拥有者可以在它的设置里放开给所有人或指定的人；不管谁 @ 的，它都在拥有者自己的电脑上执行，问题和完整回复回到群里。没有云、中转和房主迁移；房主电脑停机时讨论离线。

```text
房主常驻进程（权威记录：消息、成员、执行、附件、版本）
├── 协作服务 internal/collaboration：TLS 1.3 + WebSocket /collaboration/v1，子协议 posse-collab.v1，端口 POSSE_COLLAB_PORT（默认 6791，开发包 6792）
│   ├── 握手：双方用安装身份（collab.json 的 Ed25519）的自签证书；加入者按邀请里的指纹固定房主，房主拿到对方指纹
│   ├── 陌生指纹只能 join（带邀请）和 join.status（查自己的申请）
│   └── hello（房间凭据）之后的每个请求都复核成员资格、代际、房间仍在分享
└── internal/daemon/collab.go：方法（sync、post、key、member.*、claim、cancel、retry、event、heartbeat、upload.*、download、leave）
加入者常驻进程（internal/daemon/collab_join.go，只往外连，不监听）
├── 本机缓存：discussions.mirror=1 的同一套表，ApplySync 按房主版本补齐
├── 授权意图 collab_intents：@ 自己的 Agent 先记下（客户端请求 ID、目标、配置版本、请求摘要），领取时要对上
├── 接受账本 collab_accepts：领取成功才记，本机调度只做账本里的轮次
└── outbox collab_outbox：自己执行的状态、问题、回答、回复，按（执行，序号）至少一次补发
```

- 身份与凭据：安装身份 ID 是公钥 SPKI 的 SHA-256；不同 POSSE_HOME 是不同的人，不按名字认人。房主存成员表（collab_people：指纹、名字、代际、状态），邀请只存凭据哈希、十分钟有效、单次使用（条件更新）；申请绑定 TLS 证明的指纹，批准时代际加一。房间凭据由房主私钥对（房间、指纹、代际）派生，不另存，同一申请重取得到同一份；加入者存在 `$POSSE_HOME/collab/<房间哈希>/credential.json`（0600），退出或被移除时删掉，缓存和本机结果留着。旧代凭据、旧代执行事件一律拒收。
- 个人资料（名字和头像）跟着安装身份走，存在 `collab.json`（`name`、`avatar` 摘要、`profileRev` 版本），本机所有讨论和配对的手机共用；在设置「个人资料」、讨论人员表里自己那行的右键、`posse profile set`（`posse collab name` 只改名）改，Agent 的名字和图标不受影响。头像是 PNG/JPEG 居中裁成正方形、缩到 256 像素的 JPEG，按内容摘要存在 `$POSSE_HOME/avatars/<sha>.jpg`。改了之后：房主的讨论直接改自己那行、按版本增量同步；加入的讨论先改本机那份，连上房主时交过去（`profile`，带头像字节），房主只改连接身份自己那行、核对代际，版本不比已有的新就不动（头像也不落盘），头像核对摘要、大小（256 KB）和尺寸再存；收下、换掉头像后和常驻进程启动时删掉自己和各讨论都没人在用的头像文件，成员反复换头像不会堆在房主磁盘上；没交上的同一版本这次连接不再重交，重连或再改资料时再交；只看资料不生成安装身份，保存时才生成；没交上的在设置里列出（房主离线、房主版本旧）。成员同步后向房主取讨论里有人在用、本机还没有的头像（`avatar`，房主只给这个讨论里的），取不到的显示首字。重新加入时资料版本清零、重新交。消息存着发送时的名字，显示时按身份取人员表里最新的（引用、关键消息、搜索结果一样），不改写历史消息和冻结的上下文。
- 加入申请先在本机落下（含邀请凭据），再交给房主：响应丢了按同一申请 ID 重交，不会用掉第二次邀请。邀请无效、过期、被用过时报错，不留下空讨论。地址可在加入框里手动改（换了网段、组播被挡）。
- 对账：常驻进程重启、交接时只对本机拥有的执行对账（别人电脑上的轮次在本机没有任务，由它的拥有者负责），房主重启不会把成员正在跑的一轮记成中断，成员重启也不碰缓存里房主的轮次。
- 同步：房主每次改动推进讨论版本，推一个 `changed` 给连着的成员，成员按游标取增量（每批约 200 条消息，同一版本不拆开；截断了就标「还有」，成员接着取，截断点之后只有成员、执行改动也不会漏）。连上之后先补齐一次增量才算连上、才派发。发给成员的记录去掉房主本机的项目路径、工作区、任务、终端、上下文快照；成员缓存里他自己 Agent 的工作区和 worker 不被覆盖。
- 发言：成员发言经房主写入，按「指纹:客户端请求 ID」去重（响应丢了重发不多一条，两个人的 ID 撞了也不串）。离线时报错、草稿留在输入框，不自动补发。@ 人（`--mention`）只发提醒，不调用他的 Agent。被 @ 的人：讨论列表在有没看过的 @ 时写「有人 @ 了你」（列表带着最近一条 @ 本机的序号 `mentionSeq`），消息带「@你」标记；没在看这个讨论时发系统通知，窗口不在前台时 Dock 图标跳一下。关键消息谁都能标，取消只由标记的人或房主。
- 执行：成员 @ 自己的 Agent → 房主落下 queued → 成员核对授权意图后 claim（房主 queued → claimed，核对指纹和代际）→ 本机账本记下 → 第一阶段的本机队列、worker、`discussion read`、`task ask/done` 照常 → 状态、问题、回答、回复写进 outbox 补交 → 房主幂等接收、写进讨论、推给所有人。房主伪造一条归属相同的请求，成员核对不上（没发过、目标或内容不同、配置变了）就记成拒绝执行，不领取。房主不调度别人的 Agent。
- 访问设置（`access`，界面「谁能 @ 它」，CLI `--access owner|all|人,…`）：只有我（默认）、所有人、指定的人（按指纹记；同一个人被移出后再加入，仍算在内）。它属于公开配置，只有拥有者能改，经房主同步给所有人，界面据此决定接收者菜单和 @ 候选里能不能选。别人 @ 时房主先查一遍：不允许就拒收，报「只能给自己的 Agent 和拥有者允许你用的 Agent 发请求」。拥有者电脑领取前，按本机确认过的那份（`own_config` 把访问算进摘要，访问为空时摘要和以前一样）再查：这个人被允许、请求确实发给这个 Agent、房主那份执行快照的配置和本机一致，对不上就记成拒绝执行。房主改过的访问设置会让拥有者那边按配置不一致暂停；同步里改本机 Agent 的拥有者、代际一律不接受（都不会变），删除标记也不能被同步清掉（加入的讨论里删除自己的 Agent，房主应答后本机马上记下，不等同步），加入的讨论里拥有者为空的 Agent 不在本机调度。收回访问只挡之后领取的请求，已经领取的照常执行。别人的请求不记授权意图。发言人由房主记录，房主冒充一个被放开的人发请求，这一层防不住。
- 只有拥有者能取消、停止、重试、确认、回答自己 Agent 的执行（别人放开使用发来的请求也一样）；房主和其他人只看状态。成员 15 秒一次心跳，房主 60 秒没收到就显示失联（只用于显示，不回收、不重派）。断开时已开始的一轮在本机做完，结果留在 outbox，重连后补交；已领取没开始的轮次暂停，拥有者「继续」后才开始（交接、退出时断开不暂停）。领取先记进账本（下载附件中），请求和引用的附件下完才进本机队列：拨号、hello、断线、房主内部错误、内容对不上都是暂时的，按退避重试（重新连上时马上再试），轮次一直留在「下载附件中」不启动、附件游标不前进，不会因为试的次数多就当成缺失；只有房主明确说没有这个文件（not_found）才记成不可用，请求照常执行，上下文里标 missing。转进队列时同一事务重查加入状态、代际、Agent 和执行状态，撤销和下载完成并发时不会复活。房主那边记着已领取、本机账本却没有时（账本丢了），界面要拥有者核实副作用后「放弃并重新发起」（`discussion retry --abandon`），旧一轮记中断但保留，迟到的结果仍补到它自己身上。
- Agent 的配置分两半：公开的（名字、职责、agent、模型、思考深度、拥有者、代际、配置版本）在房主；执行工作区只在拥有者电脑上（任选本机工作区）。没有本机工作区时暂停，提示选择，不猜路径。拥有者电脑以自己保存的那份为准（`own_config`）：同步来的房主那份对不上时不照搬，Agent 暂停并说明，拥有者「检查设置」保存一次就把本机这份交给房主、解除暂停。本机没有确认过的配置（刚同步下来、旧版本加的成员）不猜哪份可信，同样暂停到拥有者确认保存；「重新启动并继续」不解除这两种暂停。加自己的 Agent 带一个请求 ID：房主按「讨论、拥有者指纹、请求 ID」去重，应答丢了用同一个 ID 重试拿回已经加好的那个、确认本机配置，不加第二个；同一个 ID 换了设置、那个 Agent 已经移除、或者是这个人上一代资格加的，报冲突，不覆盖也不复活。拿回的成员这台电脑已经确认过时（上次其实成功了，或者之后改过设置），不再用旧请求的设置覆盖本机后来的工作区和配置；只有从没确认过的（应答丢了的那次）才确认。加入的讨论里先确认连着房主才在本机建 worktree（连不上时什么都不建）；为这次添加新建的 worktree 记在请求 ID 名下，同一个请求重试用回它，换了 worktree 名字报错；用户后来删了它，重试报错、不重建，在 Agent 的设置里选工作区或新开表单添加。之后出错时报错带上请求 ID 和 worktree（和「房主结果未知」分开说），CLI 据此提示用 `--client-id` 接着用它。窗口里的成员表单提交后留着、输入框禁用，成功且表单仍是发出去的那份才关；失败时表单和请求 ID 都在，原样重试即可，新开表单换 ID。去重要房主也是这个版本：旧版房主不认请求 ID，重试仍会加出两个（协议版本没变，没有能力协商）。CLI 的 `add-member` 在房主没回应时说明可能已经加上，给出 `--client-id` 让重试用同一个 ID。房主没回应时的报错写明结果未知（可能已经做了），没连上房主时写明什么都没发出去，不笼统说草稿已保留。授权意图记下发出时的配置内容（职责、agent、模型、思考深度），领取时房主那份执行快照和本机成员配置都要和它一致，重试、放弃重发一样。
- 附件：成员的附件按 64 KiB 分块上传，房主边收边写临时文件，长度和 SHA-256 对上才改名发布到项目的 `.posse/discussions/<讨论>/attachments/<附件>/`（文件名由房主收拾，不拼远端路径）；同样内容硬链接复用，附件记录各自独立。房主给成员的附件按附件 ID 分块下载到 `$POSSE_HOME/collab/<房间哈希>/attachments/<附件>/`，摘要对上才落地。成员上传的总量受房主配额限制（默认 1 GiB，`posse collab quota`，在传的也预留进去），超了拒绝、不删旧内容；去重前按旧文件实际的长度和摘要核对。连接断了没传完的上传（临时文件、记录、配额预留）马上作废，房主重启留下的半小时后清掉；同一条消息重发时房主放掉没用上的上传。附件走单独的连接，大文件不挡心跳和同步；成员按游标只下载新消息的附件。每人同时最多 2 个上传、每人 10 秒最多 20 条消息、同一地址一分钟最多 10 次加入申请；没绑定房间的连接 15 秒没请求就断，陌生身份总共 16 条、同一来源 4 条，已是成员的身份另有名额（每人 8 条），陌生连接占满时成员照样能重连（名额不给房间权限，进房间仍要凭据）。控制帧 1 MiB、正文 256 KiB；未发布的报告路径不同步给别人。
- 凭据文件丢了：按本机记着的申请 ID 向房主重取（同一持钥者、同一代），取不回才停在缓存上。
- 房主不在线时退出：本机马上停用并记住（不领取、不开始新轮次、重启也不恢复），本机已做完的结果连上房主后先交上去，再请房主撤销。
- 移除（房主）和退出（本人）同一个边界：撤销资格、断开连接、他的 Agent 标成已离开、没结束的执行记「访问已撤销」（不代表他电脑上的进程停了），之后他交来的事件拒收。他已经下载的内容收不回。再加入要新邀请和批准，是新的一代：旧 Agent 不复活、旧凭据和旧执行事件都不能借新资格进来。
- 关闭分享：成员断开但保留资格，重新分享后直接重连；关闭期间房主发的消息届时同步。归档只有房主能做，成员任何没结束的执行（含已领取、失联待核实）都挡归档，访问已撤销的不挡；归档后成员只能读。
- 交接：协作端口和到房主的连接在新进程拿到 `possed.lock` 之后才开，旧进程在交接开始时先停（失败再恢复），两代进程不会同时接受写入；游标、outbox、账本都在库里，重连接着补。
- 权限说明：连不上时系统不一定能区分没给「本地网络」权限和网络不通，界面给合并的排查提示，不猜原因。Bonjour 发现没有做（等两台真实 Mac 的权限试验），只靠粘贴邀请。

CLI：`posse discussion share | invite | people | approve | reject | remove-person | join | leave | resume`、`discussion post --mention`、`discussion retry --abandon`、`posse collab status | name | quota`。界面：讨论页顶栏「加入讨论…」，更多菜单「在局域网分享…」「邀请…」「退出讨论…」，右栏「参与的人」（申请的批准、拒绝，在线状态，房主右键移出），加入的讨论在输入区上面写明等批准、离线、被移除。

## 手机端

已配对的手机可从首页「讨论」操作这台电脑的本机及多人讨论，身份与这台电脑相同，沿用拥有者和房主权限。消息、成员、执行及协作操作复用原有处理函数，不增加调度器或手机协作身份。手机附件通过按设备隔离的暂存凭据接入；消息分页、草稿、已读和断线重试的行为见 [手机端说明](mobile.md#讨论)。

# 飞书多机器人网关

Posse 常驻进程原生托管多个本机 `lark-cli` profile 长连接（无需公网服务器或 Webhook），把飞书单聊与同事工作群映射为 Posse 讨论，实现**飞书、桌面 Posse、手机 Posse 三端互通**。

## 架构与存储

- **多机器人与单机器人按群分身配置**：存放在 `$POSSE_HOME/lark-bots.json`（`internal/lark/config.go`，由常驻进程 `cfgMu` 统一串行持久化与热加载），可同时启用多个飞书自建应用 profile，每个机器人独立配置默认工作区、默认 Agent、权限审批模式（`ask` / `skip`）、群聊会话粒度（`chat` 按群共享 / `thread` 按话题隔离）、触发白名单（`self` / `allowlist` / `group`）、群聊近期上下文条数（`groupContextCount`，默认关闭，可选 10/20/30 或 CLI 指定 0~50）与角色说明；同时支持在单个机器人下按 `chatId` 配置多个**群分身**（`chats[]`），独立覆写显示名、工作区、Agent、权限模式、会话粒度、触发权限、角色说明（支持继承/自定义/清空）以及免 `@` 直接触发（`noMention`，开启后无需 `@` 即可直发消息和暂存纯附件，但显式 `@` 他人时仍不插嘴；需飞书应用已开通全群消息权限）。修改群分身或上级默认配置中的工作区/Agent/角色/权限/会话粒度时，常驻进程自动退役该群旧活跃绑定并清理旧 worker 审批缓存，下一条消息按新配置开启新会话。
- **引用展开、单聊附件暂存、短文本防抖与群上下文**：回复飞书里的某条消息再 `@机器人` 时，网关自动通过 `im +messages-mget --download-resources` 拉取被引用消息的正文与图片/文件附件一并传给 Agent（即使回复里只打了 `@机器人` 也生效）；单聊（`p2p`）直接发送纯文件或纯图片时，网关不立即启动无指令执行，而是暂存附件（15 分钟有效，连续发多个附件自动合并到同一张暂存提示卡）并保留原始文件名，待用户紧接着发文字说明（或引用该文件回复）时一次合并提交且不重复下载，也可点击暂存卡的 `[立即发送]` / `[取消]` 按钮直接触发或清空；同一发送者在 1.5 秒静默窗内连发多条纯文本消息（最长合并 6 秒）会自动拼成一次 Agent 回合（快捷命令 `/...` 绕过防抖）；配置了 `groupContextCount > 0` 时，群聊 `@` 还会自动附带该群最近 N 条未撤回消息作为背景上下文（自动排除当前消息与已展开的父消息）。
- **本机私有表**（`internal/store/lark.go`，不进入局域网协作同步）：
  - `lark_bindings`：`(bot_id, chat_id, thread_key) → discussion_key` 与当前活跃成员、工作区、Agent、权限模式；
  - `lark_cards`：执行、提问、权限审批与飞书卡片消息 ID 的映射；
  - `lark_events`：按 `message_id` / `event_id` 持久化事件去重（自动清理 7 天前记录）。
- **长连接托管**（`internal/lark/cli.go`）：每个已启用机器人由常驻进程并发启动两个 `lark-cli --profile <p> event consume <key> --as bot` 子进程（分别消费 `im.message.receive_v1` 与 `card.action.trigger`），子进程自动拼接 `lark-cli` 所在目录与常见 Homebrew 路径进 `PATH`（避免 `.app` 环境找不到 `node`），等 `[event] ready` 握手，断线指数退避重连，退出时关闭 stdin 优雅退出（严禁 `kill -9`）。群聊按机器人自身的 `openId` 与 `appName` 精确识别 `@` 指向，开通全群消息权限时不会误抢 `@ 其他同事` 的发言。

## 卡片交互与权限审批

- **进度与结果卡（Card 2.0）**：收到 `@机器人` 后立即回复进度卡片（带耗时、实时工具/状态行与 `[停止]` 按钮；若当前讨论已有前序轮次在运行、本条处于排队态，额外提供仅主人可点的 `[中止前序并执行]` 按钮一键中止前序并拉起当前轮次），每 2.5 秒节流刷新；完成后始终优先原地将原进度卡更新为完整结果卡（空正文手动停止成功时保持安静不额外发提醒，原地更新失败时自动降级收拢旧卡并在底部发新卡片）；若期间该会话/话题插入了审批卡、提问卡或其他新发言（或群聊因无历史消息权限/查询超时无法确认未插队），则在对话底部补发一条轻量的普通文本引用消息指向该结果卡（超长自动截断并优先附 `.md` 文件附件，失败/停止带 `[重试]`；点击 `[重试]` 保留原失败卡片并新建进度卡）。
- **工具权限审批（优先 Antigravity `agy` + 兼容 Claude Code）**：
  - `internal/daemon/permission.go` 的 `permissionHub` 同时协调飞书与手机审批；
  - 飞书 `permissionMode == "ask"` 的 worker 启动时自动带 `POSSE_LARK_APPROVAL=1`（不改全局设置）。`agy` 挂载独立的飞书专用 hook 目录 `$POSSE_HOME/.posse-antigravity-lark-hooks`（与普通终端的 `.posse-antigravity-hooks` 隔离，普通终端不挂 `PreToolUse`），进程侧跳过内置二次确认弹窗由 `PreToolUse` 独占把关；CLI hook 与常驻进程共用 `internal/agent/readonly.go` 的安全只读判定：
    - **自动放行**：仅将「空白 + 反斜杠 + LF」续行规整为空格（拒绝紧贴字符续行、CRLF、裸换行、未加引号 `#` 注释、引号外任何 `$` 展开与双引号内非 `$POSSE_NOTES`/`$HOME` 变量展开、任何未加引号 glob `* ? [` / 花括号展开 `{...}` / 括号、非开头 `~`、裸赋值段与非白名单目录可执行文件路径），全部由安全段组成的命令——含本地只读排查命令（`ls`/`grep`/`file`（仅无选项或 `-b`/`-i`/`-L`/`-z` 短选项）/`rg`（禁 `--pre`/`--pre-glob`/`-z`）/`jq`/`git` 受限只读子命令（禁 `-c`、`diff/log/show` 禁 `--output*`/`--ext-diff`/`--textconv`、`branch` 禁无 `--list` 位置参数）/`sed -n '<地址|模式>p'`/`find`（禁 `-exec*`/`-ok*`/`-delete`/`-fprint*`/`-fls`）/`sort`（禁 `-o`/`--compress-program`/`-T`）/`du`/`df`/`tree`（禁 `-o`）/`xxd`（仅 `-l`/`-s`/`-c`/`-g`/`-p` 且至多 1 位置参数）/`od`/`strings`/`shasum`/`md5`/`column`/`plutil -p|-lint`/`unzip -l|-Z [-1]`/`tar -t[vzf]`（禁含 `:` 的归档参数）等，`sqlite3` 与 `awk` 不在自动放行名单）、`lark-cli` 单次无歧义帮助（`-h`/`--help`）、`schema`、单次无歧义 `--dry-run`（重复、带 `=` 赋值、相邻可能消费值的前一 flag 或出现组合/未知短选项均走审批）与显式白名单子命令（取消按动词推断；`base +record-list/+record-search` 因默认落盘 ndjson，须显式 `--format json`/`--json`、前序 `cd <安全目录> &&` 或指定安全新文件 `--output` 才放行；会写本地的 `base +record-download-attachment --output`、`drive +export --output-dir` 及其他显式白名单下载命令必须指向 `/tmp/...` 或 `$POSSE_NOTES/discussions/...`，`im` 带 `--download-resources` 固定落盘到 `./lark-im-resources/` 一律审批）、Posse 讨论协作与只读查询命令（含 `history show|search|list|brief`、`discussion list|show`、`task list|show|inbox|guide`、`terminal list`、`workspace list`、`project list`、`lark list|profiles|status`、`version` 及 `--` 前任意 `-h`/`--help`）、以及经 Clean 与最深已存在祖先 `EvalSymlinks` 校验（拒 `..` 路径段、拒已存在软链接/硬链接 `nlink!=1`/非普通文件、拒 `$POSSE_NOTES` 或 `discussions` 根本身为软链接，保留 `/tmp -> /private/tmp` 系统别名）落在 `/tmp` 或 `$POSSE_NOTES/discussions/` 内的目录创建/草稿写入/`tee [-a]` 及安全重定向（`>`/`>>`/`1>`/`2>`/`&>` 至上述目录或 `/dev/null`、`2>&1`、`<` 输入重定向）；
    - **排查查询只读扩展与机器人级策略**：
      - `glab`：放行 `glab api <path>`（无 `-X`/`--method` 或为 `GET`，仅允许 `--paginate` 与只读请求头 `Accept:`/`Content-Type:`（不含 `\r`/`\n`/`@`），拒绝 `--hostname`/`Host:`/`Authorization:`/`PRIVATE-TOKEN:`/`X-HTTP-Method-Override`、`-f`/`-F`/`--field`/`--raw-field`/`--input`、任何未知 flag 以及含 `://`/前导 `//`/`..`/`\`/`%` 或 `graphql` 段的路径）、按子命令正向 flag 白名单收紧的 `glab repo view`、`mr view|list|diff`、`issue view|list`、`release view|list`、`ci list` 与不带 `--live`/`--wait` 的 `ci status`（`glab ci view` 为交互式 TUI 且可触发/重试/取消流水线，一律走审批；全部拒绝 `--web`/`-w`、`--hostname`、未知选项与组合短选项）、`glab repo clone <repo> <dir> [-- <安全 clone 选项>]`（`<dir>` 须尚不存在且经最深祖先 `EvalSymlinks` 落在安全临时目录内）；前置 `GITLAB_HOST=<host>` 及 `-R`/`--repo`/`repo view`/`repo clone` 中的 `https://<host>/<path>` 仅当 `<host>` 命中机器人 `readOnlyHosts` 时放行（纯 `OWNER/REPO` 或多级 `GROUP/SUB/REPO` 名称不含 `..` 可直接放行，拒绝 `ssh://`/`git@`/`http://`）；
      - `aliyun` / `ossutil`：放行显式白名单的 `aliyun sls` 查询动作（`GetLogs`/`GetHistograms`/`ListProject`/`ListLogStores`/`DescribeLogstore` 等，前后全局与查询参数均走显式正向白名单并要求合法 profile 名，拒绝 `--endpoint*`/`--config*`/`--mode*`/`--header*`/`--force`/`-y`/`--access-key*`/`--sts*`/`--ram*` 及 `@...`/`file://...` 参数值）、显式正向选项白名单的 `aliyun oss|ossutil ls|stat` 与 `ossutil ls|stat`（至多 1 个 `oss://` 参数，拒 `--loglevel*`/`-e`/`-c`/`-o`/`--checkpoint-dir`/`--snapshot-path`）及同时显式指定安全临时目录下 `--output-dir` 与 `--checkpoint-dir`（支持已存在目录，拒绝普通文件）的 `oss://` 下载 `cp`（禁 `--encoding-type` 防止客户端本地文件名二次解码漂移；目标不得为已存在目录，带 `-r` 时目标须尚不存在）；`configure`/`ram`/`sts`/`rm`/`sync` 及本地上传至 `oss://` 一律审批；
      - `tccli`：仅放行显式白名单 `service + Action`（如 `cls SearchLog`/`DescribeTopics`/`DescribeLogsets`/`DescribeLogContext`、`cvm DescribeInstances`/`GetRegions`/`ListInstances` 等）与精确长选项白名单（禁止 Python `argparse` 前缀缩写、尾部缺值、路径形式 `--profile` 以及 `@`/`file://` 值）；
      - `curl`（Sentry 只读接口）：仅允许 `https`（拒 `http`、userinfo、非默认端口及 `{}`/`[]`/`\`/空白），URL 域名（含可选 `:port` 精确匹配）命中机器人配置 `readOnlyHosts`（存 `$POSSE_HOME/lark-bots.json`，默认空 = 拒绝全部 `curl`）且路径以 `/api/0/` 开头（不含 `..`/`\`/`%2e`/`%2f`/`%5c`）；仅允许独立参数形式（不支持 `--opt=...`）的 `-s`/`-S`/`-g`/`--globoff`/`-G`/`--get`/`--compressed`/`-m`/`--max-time`/`-f`/`--fail`/`-X GET`、白名单变量 `-w`/`--write-out`（仅普通可见 ASCII、`\n`/`\t` 与 `%{http_code}`/`%{response_code}`/`%{content_type}`/`%{size_download}`/`%{time_total}`，禁 `@` 与 `%output{}`）、至多 1 次不含 `#` 且目标非已存在目录的安全临时路径 `-o`/`--output`，以及白名单只读请求头 `Authorization:`/`Accept:`/`User-Agent:`（拒绝 `-L`/`--location` 重定向；`Authorization` 头整条命令至多出现 1 次，且含 `$SENTRY_AUTH_TOKEN` 时须精确匹配 `Authorization: Bearer $SENTRY_AUTH_TOKEN` 或 `${SENTRY_AUTH_TOKEN}`）；
      - 机器人级受信脚本 `trustedScripts` 与实时策略一致：每个机器人可在 `lark-bots.json` 配置显式信任的绝对脚本路径或目录（目录以 `/` 结尾），配置写入前强制校验合法性（拒绝相对路径、`..`、`:`/`$`/`~`/空白控制字符与 `/`/`/tmp`/`/private/tmp` 及其大小写/inode 别名），执行时经 `EvalSymlinks` 与 `os.SameFile` 结合大小写折叠对所有自动可写根（`/tmp`、`/private/tmp`、`TmpDir`、`NotesDir`、`DiscussionsDir`）做真实目录身份双向互斥；daemon 启动时即绑定 `SetRootsResolver`（交接空档与关闭网关不清空），worker 注入 `POSSE_LARK_BOT_ID` 供 CLI hook 实时读取 `$POSSE_HOME/lark-bots.json`（缺失 `POSSE_LARK_BOT_ID` 一律失效关闭不信启动环境，执行 `posse lark edit --clear-*` 后存活 worker 立即撤销权限）；
      - 环境变量全量打印（`env`、`printenv`）、`bsk`、`npx`/`uvx`/`pip`、`python -c` 与任何 GraphQL 均保持审批。
    - **人工审批与同类规则键**：其余写文件/改代码/MCP/非只读命令（含 `$()`、反引号、后台 `&`、越界重定向、`lark-cli` 写操作与 `rm`）挂起等待飞书审批；卡片提供 `[允许]`、`[本会话允许同类]`、`[拒绝]` 三个按钮，`deriveCommandRuleKeys` 与 CLI 共用严格展开校验，跳过已证明安全的只读段（含当前机器人 `trustedScripts`/`readOnlyHosts`）并仅记录裸命令名需审批段（`posse` 与 `lark-cli` 均记两级），若需审批段以带 `/` 的路径（绝对或相对）给出、属于通用解释器/包装命令或高风险排查工具未放行分支（大小写不敏感匹配 `bash`/`sh`/`zsh`/`fish`/`python`/`python3`/`node`/`deno`/`bun`/`ruby`/`perl`/`php`/`osascript`/`eval`/`sudo`/`xargs`/`npx`/`uvx`/`pipx`/`env`/`printenv`/`curl`/`glab`/`aliyun`/`ossutil`/`tccli`）、含任何重定向、无法可靠解析（含 glob/花括号）、前置环境变量或携带越界/隐式写盘输出目标，则整条命令不生成同类规则键（仅单次允许）；点「本会话允许同类」后当前工位内后续同类操作自动放行（不因桌面窗口聚焦/滚轮误取消）；3 分钟超时显式返回 `deny`（绝不自动放行）；Claude 通过 `PermissionRequest` 挂起最多 3 分钟，超时或桌面键入交回终端 TUI。
    - **边界与已知取舍**：命令经 shell 执行时依赖宿主 `PATH`/别名；`git` 读取仓库与用户配置（`core.pager`/`fsmonitor`/`diff.external`）、`rg` 的 `RIPGREP_CONFIG_PATH`、`~/.curlrc` 以及本机云 CLI（`glab`/`aliyun`/`ossutil`/`tccli`）既有配置均由主人环境决定（agent 修改这些配置本身需审批）；hook 预检查与真实写入分属两进程存在 TOCTOU 边界；daemon 侧跳过只读段读取常驻进程自身 `POSSE_NOTES` 环境（仅更保守）；飞书审批卡片摘要展示为既有行为。
- **选项问答**：worker 调用 `posse task ask --choice` 时自动发选项按钮 + 自定义输入表单卡片，点击或提交直接调用 `answerDiscussion` 并同步桌面/手机。
- **同事工作群安全边界**：
  - `[允许]` / `[拒绝]` 权限审批、`[停止]`、`[重试]` 与切换 Agent/工作区按钮强制校验 `operator_id == ownerOpenId`；
  - 反向同步规则：**群聊只将 Agent 的最终回复同步回飞书群，不把桌面/手机发给 Agent 的内部追问刷到同事群**；**单聊（`p2p`）双向全同步**。

## 飞书快捷命令与 CLI

- 飞书内支持 `/agent [name]`、`/ws [name]`、`/new`、`/status`、`/stop`、`/mention on|off`、`/role <text|clear|inherit>`、`/help`（所有修改会话、执行或配置的命令均强制仅限 Posse 主人执行）。
- CLI 管理：`posse lark profiles`、`posse lark list`、`posse lark add --profile <p> [--trusted-script PATH]... [--read-only-host HOST]...`、`posse lark edit <bot> [--trusted-script PATH]... [--read-only-host HOST]...`、`posse lark enable/disable <id>`、`posse lark rm <id>`。
- 桌面管理：「设置 › 飞书机器人」（支持自动通过 `im +chat-list --as bot` 拉取机器人已加入的飞书群一键点选配置群分身，支持在默认工作区直接选择任意本地文件夹并自动加入工作区）。

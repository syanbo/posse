# 手机遥控

`internal/mobile` 和 `mobile/` 的 Flutter 客户端。

- 手机遥控（`internal/mobile`）复用 Orca 的手机 App（App Store / GitHub 上的 APK），hive 扮演 Orca 桌面端，协议照 stablyai/orca 的 `mobile/` 和 `src/shared/` 实现：
  - 只做局域网/Tailscale 直连（Orca 的 local-only），不做云端中转和推送（推送只能经 Orca 的网关）。手机 App 在前台时每 3 秒轮询 `worktree.ps`，靠它看到"待处理"。
  - 配对码里的地址默认自动选（Tailscale 优先，其次局域网）；也可以自定义（配对对话框，或 `hive mobile pair --address`），规则照 Orca 的 `pairing-endpoint.ts`（`mobile.ResolveEndpoint`）：主机或 主机:端口 拼成 `ws://`，完整 URL 的 http/https 换成 ws/wss、路径保留，用于隧道或反向代理（服务端不看请求路径）。手机页的地址下拉列出自动、检测到的每个 Tailscale 和局域网地址（`mobile.LocalEndpoints`，取码时刷新）和用过的自定义地址；界面选的地址和用过的自定义地址存在 ui.json 的 `mobileAddress`、`mobileAddresses`（检测到的本机地址不记进列表）。配对码 JSON 另有 `endpoints`，Hive 手机客户端同时连其中所有地址、先握手成功的留下（`raceEndpoints`）：自动时是本机所有 Tailscale 和局域网地址，选了具体地址时只有它（带上别的地址，选的局域网或自定义地址会被先连上的挤掉）。Orca App 只读 `endpoint`，忽略这个字段。手机扫码、粘贴配对码连上后在底部提示连的是哪台电脑、实际走的哪个地址（`HiveLink.url`），电脑列表里当前那台也写实际地址。手机上的电脑按公钥加主地址认（`computerId`）：同一台电脑扫远程和局域网的码存成两项，可以来回切，没改过名的名字后面带地址区分（`labelOf`）；旧版只按公钥存的 ID 读出来时补上地址。权限按用到的时候要：国行 iPhone 打开 App 时弹「无线数据」（connectivity_plus 注册时就开始监听网络状态），点扫码要相机，扫到码第一次连局域网地址时弹「本地网络」。「本地网络」弹窗开着时连接直接失败，所以第一次配对（手机上还没存过电脑）连不上时每秒重试，App 在前台累计 30 秒才放弃，弹窗开着时 App 不在前台、不计时，点完允许就连上；放弃时提示检查电脑和这两项权限（`HiveAppModel._start`）。电脑明确拒绝（密钥不对、拒绝能力声明）不重试。配对过的电脑只连一次。
  - Hive 扩展：`runtime.clientCapabilities.update` 记在这条连接上，没声明能力的连接不收 Hive 扩展推送。带 `hive.permission.v1` 且正在订阅该终端对话时，Claude 的 PermissionRequest 走 `hook.permission.hold`：往这条对话流推 `type:permission`，等 `agent.permission.decide`；桌面有人键入或 30 秒到了就返回空 behavior。带 `hive.git.v1` 才能调只读 `git.status` / `git.diff`（拒绝绝对路径和 `..`；图片的 diff 另带 `images`：HEAD 里的旧图（改名的按 `orig` 读）和工作区的新图，base64，手机上下对照）；checkout、commit、push 不开放。带 `hive.history.v1` 才能调 `history.list`、`history.search`、`history.resume`（`internal/mobile/history.go`，经 `Host.History` 转给常驻进程同名的接口；resume 回终端 ID 和手机上的工作区 ID，报错换成中文）；看会话内容走 `nativeChat.readSession`（按会话文件读），手机上不能移到废纸篓。手机端（`mobile/lib/history`）首页顶栏的时钟进历史：列表按今天、昨天、最近 7 天、最近 30 天、1 个月前分组，搜索结果按相关度排、带命中摘要；点开只读看对话（和会话页同一套列表：倒着排，往上翻到头自动读更早的一页），底部"在电脑上继续"调 `history.resume`，提示里能直接在手机上打开那个会话。这两项在常驻进程里，不走窗口进程的 Git 界面。带 `hive.context.v1` 才能调 `session.context`（参数同 `nativeChat.readSession`，按 `history.ReadContext` 读会话最后一次请求的上下文，claude、codex 才有）：手机终端太窄，Claude 状态栏里的百分比常被截掉，会话页和终端页标题下面的状态行末尾写「上下文 N%」（`mobile/lib/chat/context_meter.dart`，每 15 秒和状态变化时重读，75% 起琥珀色、90% 起红色）。带 `hive.status.v1` 的连接在对话流里另收 `type:status`（`internal/mobile/status.go`）：终端一有输出，就从屏幕最后一行有字的往上 16 行里认出 agent 的状态行（Claude 的 `✻ Puzzling… (1m 54s · ↓ 9.5k tokens)`、Codex 的 `• Working (12s • esc to interrupt)`，都在第一列），去掉转圈符号、按键提示和"thought for"，变了才推，最多每 250ms 看一次屏幕，跳过的那次约好稍后补看；状态行消失时推空串。手机对话页（`mobile/lib/chat`）最后一行照着它写，没有时写正在用的工具。Claude 的回复整段写完才进会话文件（实测工具调用约晚 0.5 秒、思考约晚 3 秒），所以对话页靠状态行表示还在干活；发出去的话先画在末尾（`LocalEchoes`，发送中半透明、终端收下后写已发送），会话文件里新出现的用户消息按顺序认领最早的一条后撤掉（不比内容：图片换成了路径），斜杠命令不先画，5 分钟等不到也撤掉。
  - 延迟和断线检测：Hive 扩展 `runtime.ping`（电脑立刻回空结果，不用声明能力）。手机每 5 秒 ping 一次（`mobile/lib/protocol/latency.dart`，旧常驻进程没有它时改用 `status.get` 计时），会话页、终端页标题下面的状态行在上下文后面写最近 3 次中位数的信号格和毫秒数，不写单位（`LatencyLabel`：150 ms 内满格绿色，到 300 ms 两格灰色，300 ms 起一格琥珀色，没响应是带感叹号的红色空格加「无响应」）。首页顶栏同一个读数排在右边按钮那一组最前面、左右空出和图标按钮一样的间距（电脑胶囊用掉剩下的宽度、靠左，里面只有连接圆点和电脑名；胶囊变宽变窄它不挪），断线重连时不显示；右边的历史、新建、设置用紧凑尺寸（40）给它腾地方。同一条连接上的回复是一条条发的：一次 ping 期间连接上收发超过 64 KB（视频分段、图片、终端快照、上传）的样本是排队排出来的，不算。每次等 5 秒，超时又没收到任何请求的回复写红色「无响应」，并且马上补测；连续 3 次就 `PhoneRpc.drop` 交给重连，切网络、手机休眠后的半开连接 15–20 秒内发现（之前要等系统报错）。期间有别的回复回来（慢线路上分段下大文件）不算没响应；终端输出、标签这类推送不算：电脑那边这条连接处理请求卡住时推送照样在发，按字节算会一直"活着"、请求一直超时。状态行的状态、上下文、延迟共用 `statusLineStyle`（写明字重，不继承顶栏标题的粗体）。
  - 常驻进程在 `0.0.0.0:6788` 开明文 WebSocket（避开 Orca 的 6768，两边可同时开），安全靠 E2EE v2（X25519 + HKDF + secretbox，`e2ee_test.go` 有 Orca 的测试向量）和设备 token。没有配对过的手机时不监听，生成配对码时才开始。端到端测试用 `HIVE_MOBILE_PORT` 换端口，免得和日常的常驻进程冲突。发一条消息的写超时按大小算（`writeTimeout`：15 秒起，再按每秒 64 KB 加）：库在写超时时会关掉整条连接，手机上所有终端跟着掉线。不开 permessage-deflate：消息是密文的 base64，websocket 库写死的 BestSpeed 在 Go 1.27 下对它原样存储，压不动。
  - 主动断开：首页电脑胶囊打开的电脑列表里有"断开连接"（连着或正在连时才有），断开后配对留着、不自动重连（`disconnected`，只在这次运行里有效），胶囊写"电脑名 · 已断开"、灰点不转圈，首页列出配对过的电脑和台数，点一台就连，底下可以扫码添加。
  - 桌面侧栏「手机」行尾：有手机连着时一个绿点（不止一台时前面写台数），悬停写是哪几台。来自 `daemon.status` 的 `mobileOnline`（`Devices()` 里正连着的，同一台手机配对过几次只算一台），窗口每秒轮询照常拿到，不用打开手机页。
  - 主机密钥和配对的手机存在 `$HIVE_HOME/mobile.json`（0600）。手机按公钥认主机，换密钥等于所有手机重新配对。每扫一次码多一个设备 token；Hive 手机客户端每次握手在 `runtime.clientCapabilities.update` 里带 `phone`（安装 ID、型号、它存着的这台电脑的全部 token，`pairing.identify`）：同一台手机的 token 合成一项、名字换成型号，它不再存着的 token（重新扫码换掉、手机上删掉的）作废，没认领的旧 token 在它手里就归过来。Orca App 和旧版客户端不报，手机页收在"其他配对"里，可以全部移除。配对码在侧栏「历史」下面的「手机」页、「新建」菜单（侧栏底栏最左边的 +）或 `hive mobile pair`。
  - 映射：项目 → repo，工作区 → worktree（ID 是 `<项目 ID>::<工作区 ID>`），运行中的终端 → 标签（手机只认 UUID 形状的 leaf，由终端 ID 派生；标签名依次取桌面改的名字、会话标题、终端标题）。手机首页每个工作区下面，agent 会话和普通终端都各占一行（`_sessions`），普通终端的副标题写"终端"，点开进终端页、长按关闭。agent 状态 waiting → `waiting`（行状态 `permission`），working/starting → `working`，idle → `done`。
  - 手机看终端时终端按手机屏幕排版（`Terminal.HoldSize`），界面这时的尺寸变化先记下，手机全部离开后恢复；手机接入不接管终端查询的应答（`Watch`）。flterm 每次布局都按算出来的格子数改本地终端，页面推入、键盘动画途中一瞬间很小的尺寸也改，备用屏幕（Claude Code 的全屏界面）缩小时裁掉的格子回不来，agent 又只重画变了的格子；所以本地尺寸变过（哪怕缩到太小没订阅、又回到原来的大小）就重新订阅拿快照（`ResizeGate`）。推入页面、从后台回来重新布局时会连着报几个尺寸，尺寸停止变化 150ms 后才订阅一次，免得电脑上的终端跟着连改几次、agent 连着重画。键盘弹出、收起不改终端尺寸（`resizeToAvoidBottomInset: false`）：终端按键盘收起时的高度排，快捷键栏贴着键盘上移，终端整体往上挪到最后一行内容（最后一行有字或铺了底色的行和光标所在行取靠下的，flterm 渲染时报出来，见 `third_party/flterm/HIVE.md`）露在快捷键栏上方，最多挪键盘盖住的高度，挪出顶端的部分裁掉（`mobile/lib/terminal/keyboard_lift.dart`）；shell 刚开、内容在上半屏时不挪。提示、复制按钮和上传进度浮在看得见的那块上，不跟着挪。电脑布局按静止时的格子算，上下拖动照常平移。flterm 回答尺寸查询时不再刷新控制器自己的渲染状态（会清掉终端上的行脏标记，渲染器漏画 Claude 改尺寸后重画的行，见 `third_party/flterm/HIVE.md`），推入动画结束、回到前台、agent 从工作中停下来时也重取一次。终端输出走 Orca 的 16 字节头二进制帧，按 UTF-8 字符边界切块。终端被手机占着尺寸时 `terminalInfo.phoneSized` 为真，窗口在终端上方显示一行提示和"改回电脑尺寸"（`terminal.reclaimSize` → `Terminal.ReclaimSize`，放掉所有手机的占用、按界面最后要的尺寸重排；手机的订阅还在，离开时不再改尺寸，重新打开这个终端才会再占）：手机切到后台时连接常常还挂着，不然电脑上一直是窄的。手机终端的"更多"里有"电脑布局"（`AppSettings.deskLayout`）：订阅时不带手机尺寸，终端保持电脑的列数和行数（快照开头的元数据里带着）。手机把这块格子缩进屏幕宽度（`deskZoom` 默认 1，双指放大吸到 0.5–2 的固定档后再滑），不改 PTY 尺寸。安卓 release 构建的混淆规则在 `mobile/android/app/proguard-rules.pro`：shared_preferences_android 2.5 起经 package:jni 按名字和签名调 Kotlin，插件没带保留规则，不保住这些类名（含 jni 用到的 Kotlin 协程类）冷启动就读不出存着的配对和设置；升级 shared_preferences 或 jni 后要在真机上确认冷启动能自动连上。手机的等宽字体回退链带 App 自带的 Symbols Nerd Font Mono（`mobile/assets/fonts`，MIT），starship 等提示符里 Nerd Font 的私有区图标（如分支 U+E0A0）不再是缺字方框。手机终端里轻点链接：网址交给系统浏览器，指向工作区里文件的路径（含 `file://`）在文件页里打开，工作区外的提示打不开（`mobile/lib/terminal/link_target.dart`）。
  - 文件页（`files.go`）：`files.readDir`（按目录读，手机优先用它，没有才退回 `files.list`）、`files.list`、`files.searchPaths`、`files.read`、`files.readPreview`、`files.stat`，只读，路径相对工作区、拒绝绝对路径和 `..`，限制照 Orca（文本 512 KB 截断、图片 10 MB、清单 5000 个）。视频（mp4、mov、m4v、webm）由 Hive 扩展 `files.readRange` 分段（每段 1 MB，同时 2 段：电脑那边回复是一条条发的，同时要得多只会让排在后面的白等）下载到手机临时目录再用 video_player 播放，按路径、大小、修改时间缓存，超过 500 MB 不下（`mobile/lib/files/video.dart`）。安卓上用平台视图（`VideoViewType.platformView`）播：默认的纹理把解码器接到 Flutter 的 Surface 上，华为麒麟 9010 的海思解码器在这种 Surface 上配不出输出缓冲区（`UnsupportedSetting`，关掉 Impeller 也一样）；iOS 仍用纹理。每段等 60 秒（经跨境隧道晚高峰可能只有几百 KB/s），超时再试两次；没下完时留着 `.part`，错误页的"接着下载"或下次打开从断处接着下。音频、编辑保存、在桌面打开没做。文件页的 Markdown 用 flutter_markdown_plus 渲染（`mobile/lib/files/markdown_doc.dart`，Google 停维护的 flutter_markdown 的官方接手版，解析器同为 `markdown` 包）：表格按内容宽排、太宽左右滑，任务列表画勾选框，嵌套列表逐层换圆点，代码块沿用对话页的 `markdownCodeBlock`；相对链接和图片按 md 文件所在目录算，工作区里的文件在文件页打开、图片经 `files.readPreview` 向电脑要（最近 24 张留在内存里），网址交给浏览器。对话页的气泡仍用自己的 `MarkdownView`。两边解析用同一套 `markdownExtensions`：GitHub 风格，但网址自动识别不把 `]` 算进网址（markdown 7.3.1 会把 `[打开 https://a.com](https://a.com)` 的后半截吞成一个网址，外面的链接就坏了）。看源码、看 diff 和 Markdown 代码块（对话页、文件预览共用）在手机上本地着色（`mobile/lib/ui/highlight.dart`，re_highlight，配色同桌面编辑器的 GitHub 深浅两套）：按文件名或围栏语言认，认不出不着色、不自动猜；diff 两边各自接成一段着色再对回每行；16 KB 起放到后台 isolate，超过 256 KB 不着色。
  - 图片与视频（Hive 扩展，带 `hive.media.v1` 才有，`internal/mobile/media.go`）：会话页、终端页的"更多"里"图片与视频"，内容和桌面的图片面板一样（找图找视频的逻辑在 `internal/media`，两边共用）。`session.media`（参数同 `nativeChat.readSession`）列出 agent 生成的（最近 40 项）和粘贴的；`session.mediaThumb` 给 480 像素宽的 JPEG 缩略图（视频取第一帧），一次只做一张，免得常驻进程因为手机翻得快涨内存；`session.mediaRead` 按段读原图或视频（同 `files.readRange`，每段 1 MB）。手机只能按列表给过的 ID 读，读不到别的文件；各会话的扫描进度记在常驻进程里（最多 8 个会话），再列只读会话文件新增的部分。手机端（`mobile/lib/chat/media.dart`）两列网格，开着时每 3 秒重列；点开图片下原图（是 agent 当时看到的样子）双指放大，视频和文件页走同一套分段下载和播放（`fetchChunked`、`VideoView`），按会话和 ID 缓存。
  - 存到手机（`mobile/lib/files/save.dart`）：文件页、图片与视频页看大图或视频时顶栏右边有按钮，原文件取到手机上之后才能点（视频要等下完）；文件列表长按文件、图片与视频网格长按一格，弹出面板，现下（带进度、可取消、断了接着下）再存，任意文件都行，超过 500 MB 不下。按格式定存到哪（`saveTarget`）：jpg、jpeg、png、gif、webp、heic、mp4、mov、m4v 用 gal 存进相册的「Hive」相簿（安卓在 `Pictures/Hive`）；其余格式（webm、bmp、文本等）和相册拒收的，安卓存进「下载/Hive」（`MainActivity.kt` 的 `hive/downloads`，安卓 10 起经 MediaStore 不要权限，9 及以下运行时要写存储权限，重名时改成 `x (1).md`），iOS 弹系统分享面板（里面有"存储到文件"）：安卓的分享面板没有存到本机的去处，小米、华为的"文件管理"都是存到云空间。长按的面板在第一行之外再给一行"分享"，发给别的 App。缓存里的文件名是哈希，存之前复制一份改回原名（会话里粘贴的图片没有扩展名，按文件头补）。放进单独的相簿要相册的读写权限（iOS 的 `NSPhotoLibraryUsageDescription`，选"限制访问"也行；安卓 10 及以下要 `WRITE_EXTERNAL_STORAGE`）。同一个文件同时只有一个在下（`fetchChunked` 按 key 排队），边看视频边点存不会两边往一个 `.part` 里写。
  - 终端页点终端（含电脑布局里格子外的空白）只在键盘收着时弹出，弹着时不收（`TerminalView.onTap`，见 `third_party/flterm/HIVE.md`）：输入框就在终端里，键盘弹着时点一下多半是在挪光标、点选项。收起键盘用快捷键栏最前面的键盘键，它照旧切换。点链接不动键盘。点发送图片先放下键盘再选图。
  - 终端页键盘上方的快捷键栏（`mobile/lib/settings/custom_keys.dart`，设置里可排序、加自己的键）内置键在 `termKeys`：Esc、Tab、Enter、立即发送（键帽 ⌃↩）、⇧Tab、^C、方向键。立即发送是 Claude Code 的 `chat:sendNow`：干活时排着队的消息马上交给模型。键帽照它的默认键 Ctrl+Enter 写成 ⌃↩（带 U+FE0E，不被画成 emoji），但 Ctrl+Enter 要 kitty 键盘协议，手机终端发不出，实际发的是同样绑定的 Ctrl+X Ctrl+S；存过的快捷键栏里缺的内置键（新版本加的）插在默认顺序里它前面那个键后面，不补在最后（`normalizeBarKeys`）；立即发送刚加时被补在了最后，所以没有 `barKeysVersion` 的旧设置里它一律回到 Enter 后面，存成旧名字"立即发送"的也一样（`renamedBuiltins`），之后自己挪的位置照存。方向键、Home、End（内置和自定义）按程序当前的光标键模式编码：开着应用模式（DECCKM）时发 ESC O A，htop 这类 ncurses 程序只认这种（`cursorKeysApp`）；`hive terminal send --key` 也一样。全屏程序跟踪鼠标时，手指滑动换成的滚轮报在手指所在的格子（Codex 不理会落在第一行的滚轮）；不跟踪鼠标时，只在程序开着 1007 时换成方向键，和桌面一致（flterm 的改动见 `mobile/third_party/flterm/HIVE.md`）。
  - 进会话页、历史页（含历史会话）、工作区页、图片与视频、打开文件和 diff 时，第一份数据等推入动画结束再上屏（`routeSettled`）：数据常在滑入途中到达，那一帧要建整页、排一屏文字，动画会顿一下。历史列表和改动列表按需建行（`SliverSection`、`DecoratedSliver`），不再一次全建；Markdown 预览自己滚动（flutter_markdown_plus 的 `Markdown`），只排看得见的块；工作区页的改动和文件两页，没切过去的那页先不建。源码和 diff 不再把整份内容排成一段文字，按行只建看得见的（`CodeLines`），宽度按最长一行的格数估（宽字符两格、tab 四格，宁宽勿窄）；每行末尾带 `\n`、只画第一行，选中复制时行之间还有换行。
  - 加载动画（`mobile/lib/ui/loading.dart`，设计稿 `design/loading/concepts.png`）：整页加载是七格蜂巢（`HiveLoader`），外圈六格顺时针逐格亮、后面拖一段渐暗；按钮里、行尾的小转圈是六边形描边（`HexSpinner`），亮段占两条边、用扫描渐变由淡到亮。扫码页的相机画面等弹出动画结束才上屏（视图先在 `Offstage` 里建好，相机照常启动）：平台视图跟着滑动时 iOS 每帧都要重新合成它。历史页还没有内容时整页是蜂巢，已有结果再读时转圈在搜索框里，不在列表上面加进度条。系统开了减弱动态效果时停在一帧上。上下文用量的圆环、视频下载和上传的进度条仍用 Material 的。首页不能下拉刷新（工作区列表每 3 秒自己刷新一次），历史页、Git 页可以。手机 App 图标是描边六边形加 `>_`（和桌面端同一张 `design/icon-art.png`，缩放进 iOS 的 AppIcon、安卓的 mipmap 和首页用的 `mobile/assets/icon.png`）。
  - 闪屏（`mobile/lib/ui/splash.dart`，设计稿 `design/splash/concepts-3.png` 的 H）：系统闪屏（iOS LaunchScreen、安卓 `launch_background` 和 12 起的 `windowSplashScreenAnimatedIcon`）是 `#1A1A19` 底、居中的标志和底部的「All your agents. One hive.」（安卓 12 起是 `windowSplashScreenBrandingImage`，iOS 和旧安卓照它放在离底边 60 的 200×80 里），接着 Flutter 在同样位置画同样的标志和 slogan 图、铺满蜂巢格，零星几格按 agent 状态色（琥珀、陶土、绿）陆续亮起；Flutter 第一帧等 slogan 图解码好才上屏（最多等 300ms，期间原生闪屏还盖着，切过来底部不会空一两帧）；本地设置和电脑列表读完且显示满 0.7 秒后用 0.2 秒淡出，首页一直在下面建好。动画只放 0.6 秒，之后不重绘。标志图和 slogan 图（原生各端和 Flutter 的 `assets/splash_slogan.png` 共用，字是 macOS 自带的 Avenir Book，各端系统字体不同所以用图）由 `HIVE_SPLASH_EXPORT=1 fvm flutter test test/splash_assets_test.dart` 导出，改了底色、标志、文字要重新导出。iOS 会缓存启动屏，改了以后真机要重启手机才看得到。闪屏不跟主题，浅色主题也是暗底：系统闪屏在 App 读到主题设置之前就显示了。
  - 手机上传的图片存成 `$TMPDIR/hive-mobile-*`，App 再把路径输入终端。按 256 KB 的 base64 分块传，浮在列表或终端底部显示第几张和百分比（`UploadBar`，不占布局，终端不因此改尺寸）。

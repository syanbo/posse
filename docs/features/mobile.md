# 手机遥控

`internal/mobile` 和 `mobile/` 的 Flutter 客户端。

- 手机遥控（`internal/mobile`）复用 Orca 的手机 App（App Store / GitHub 上的 APK），posse 扮演 Orca 桌面端，协议照 stablyai/orca 的 `mobile/` 和 `src/shared/` 实现：
  - 不经 Orca 的云端中转（Orca 的 local-only），也不做推送（推送只能经 Orca 的网关）；Posse 手机客户端可以经自己的 UDP 中转走 QUIC，见下面。手机 App 在前台时每 3 秒轮询 `worktree.ps`，靠它看到"待处理"。
  - 配对码里的地址默认自动选（Tailscale 优先，其次局域网）；也可以自定义（配对对话框，或 `posse mobile pair --address`），规则照 Orca 的 `pairing-endpoint.ts`（`mobile.ResolveEndpoint`）：主机或 主机:端口 拼成 `ws://`，完整 URL 的 http/https 换成 ws/wss、路径保留，用于隧道或反向代理（服务端不看请求路径）。手机页的地址下拉列出自动、检测到的每个 Tailscale 和局域网地址（`mobile.LocalEndpoints`，取码时刷新）和用过的自定义地址；界面选的地址和用过的自定义地址存在 ui.json 的 `mobileAddress`、`mobileAddresses`（检测到的本机地址不记进列表）。配对码 JSON 另有 `endpoints`，Posse 手机客户端同时连其中所有地址、先握手成功的留下（`raceEndpoints`）：自动时是本机所有 Tailscale 和局域网地址，选了具体地址时只有它（带上别的地址，选的局域网或自定义地址会被先连上的挤掉）。Orca App 只读 `endpoint`，忽略这个字段。iOS 的配对页和首页的「添加电脑」可以扫码（`mobile/lib/pair/scan.dart`，原生 `QrScanView.swift` 只认二维码）：扫到不是配对码的码相机不关，认到配对码才关相机去连；拒绝相机权限或开不了相机时回到配对页粘贴。安卓只能粘贴配对码。手机扫码、粘贴配对码连上后在底部提示连的是哪台电脑、实际走的哪个地址（`PosseLink.url`），电脑列表里当前那台也写实际地址。手机上的电脑按公钥加主地址认（`computerId`）：同一台电脑扫远程和局域网的码存成两项，可以来回切，没改过名的名字后面带地址区分（`labelOf`）；旧版只按公钥存的 ID 读出来时补上地址。权限按用到的时候要：国行 iPhone 打开 App 时弹「无线数据」（connectivity_plus 注册时就开始监听网络状态），点扫码要相机，扫到码第一次连局域网地址时弹「本地网络」。「本地网络」弹窗开着时连接直接失败，所以第一次配对（手机上还没存过电脑）连不上时每秒重试，App 在前台累计 30 秒才放弃，弹窗开着时 App 不在前台、不计时，点完允许就连上；放弃时提示检查电脑和这两项权限（`PosseAppModel._start`）。电脑明确拒绝（密钥不对、拒绝能力声明）不重试。配对过的电脑只连一次。
  - QUIC（只有 Posse 手机客户端）：手机服务在 WebSocket 同一个端口号上开 UDP 的 QUIC（`internal/mobile/quic.go`，传输层两端共用 `internal/mquic`）。一条连接只开一条双向流，上面跑和 WebSocket 一样的文本、二进制消息（u8 类型、u32 长度），握手、E2EE、RPC 全部照旧：加密计数器要求按顺序到达，所以不按终端拆流。TLS 只当 QUIC 的传输加密，证书每次启动自签、手机不验，身份靠 E2EE，和局域网里的 `ws://` 一样。关闭时排在正在写的消息后面发关闭帧（u16 关闭码加原因）再关流、等对方关连接，之后的写入直接报错：直接关 QUIC 连接会丢掉还没发出去的数据（比如拒绝认证前那条报错）。电脑读手机的消息上限 4 MB，和 WebSocket 一致。`$POSSE_HOME/desk.json` 配了中转时（和看桌面同一个 `tools/deskrelay`），每台手机第一次调 `posse.quic` 时 Mac 给它开一个绑物理网卡的 UDP socket，用这台手机（设备 ID）的令牌每 10 秒向中转登记。令牌存在 mobile.json 的设备记录里（`relayToken`，设备列表不给出），常驻进程重启、交接都不变：中转一个令牌只记一台手机的地址，共用会互相抢包。解除配对时关掉，换了中转地址全部重开，开不了下次调用再试。手机每次连上都调 `posse.quic`，拿到端口、本机的 Tailscale 和局域网地址、中转地址和这台手机的令牌（每次调用都重读 desk.json，改了不用重启），换成 `hquic://主机:端口`（中转的带 `?relay=令牌`）并发拨号，地址存进这台电脑的记录（`SavedComputer.quic`），冷启动直接拨，在外面不用先经隧道连上 WebSocket；这次走的是 WebSocket 时并发拨号，先握手成功的换掉 WebSocket（`PosseLink._learnQuic`），都不通就留在 WebSocket。经隧道的 WebSocket 只剩兜底：第一次配对，和 UDP 不通的网络。经中转连上后在后台打洞（`PosseLink._punch`）：手机新开一个 socket，向中转发探测包问出它的公网地址，经 `posse.punch` 交给 Mac；Mac 从这台手机的中转出口问出自己的公网地址回给手机，同时从这个出口向手机的地址连发 4 秒打洞包（每 50ms 一个）；手机也从新 socket 向 Mac 的地址连发打洞包并拨 QUIC（`mquic.Prepare`、`Prepared.Dial`）。出口上本来就有 QUIC 在听，3 秒内握手成功就换过去（显示「直连 · QUIC」），旧的中转连接照样等订阅迁走再关；打不通（比如两边都是对称 NAT）留在中转。直连的地址不存：断了按存着的地址先连中转，再重新打洞。换过去时旧连接不马上关：等页面在新连接上订阅好、退掉旧订阅，进行中的请求也回完（至少 0.5 秒、最多 10 秒，`PhoneRpc.closeWhenIdle`），否则电脑先看到断开，把终端改回电脑尺寸再改回手机尺寸。之后的重连 QUIC 地址先连，WebSocket 晚 2 秒起跑兜底（`quicHeadStart`）。经中转时手机先登记、等到回执才握手，中转不应答 1.5 秒就失败，之后每 5 秒重发登记。手机上的 QUIC 是编进 App 的 Go 库（`mobile/packages/posse_quic`：构建钩子 `hook/build.dart` 按目标平台调 `go build`，iOS 先编静态库再用 clang 链成动态库；Dart 经 FFI 调用，结果由 `NativeCallable.listener` 回调送回），iOS、安卓都用这一份；电脑列表和连上的提示里写「地址 · QUIC」或「经中转 · QUIC」。Orca App 不认 `posse.quic`，照旧走 WebSocket。
  - Posse 扩展：`runtime.clientCapabilities.update` 记在这条连接上，没声明能力的连接不收 Posse 扩展推送。带 `posse.permission.v1` 且正在订阅该终端对话时，Claude 的 PermissionRequest 走 `hook.permission.hold`：往这条对话流推 `type:permission`，等 `agent.permission.decide`；桌面有人键入或 30 秒到了就返回空 behavior。带 `posse.git.v1` 才能调只读 `git.status` / `git.diff`（拒绝绝对路径和 `..`；图片的 diff 另带 `images`：HEAD 里的旧图（改名的按 `orig` 读）和工作区的新图，base64，手机上下对照）；checkout、commit、push 不开放。带 `posse.history.v1` 才能调 `history.list`、`history.search`、`history.resume`（`internal/mobile/history.go`，经 `Host.History` 转给常驻进程同名的接口；resume 回终端 ID 和手机上的工作区 ID，报错换成中文）；看会话内容走 `nativeChat.readSession`（按会话文件读，claude、codex、grok、cursor 都认；cursor 的记录只有用户的话、助手的话和工具调用，没有工具结果，时间只有用户消息开头的 `<timestamp>`），手机上不能移到废纸篓。手机端（`mobile/lib/history`）首页顶栏的时钟进历史：列表按今天、昨天、最近 7 天、最近 30 天、1 个月前分组，搜索结果按相关度排、带命中摘要；点开只读看对话（和会话页同一套列表：倒着排，往上翻到头自动读更早的一页），底部"在电脑上继续"调 `history.resume`，提示里能直接在手机上打开那个会话。这两项在常驻进程里，不走窗口进程的 Git 界面。带 `posse.context.v1` 才能调 `session.context`（参数同 `nativeChat.readSession`，按 `history.ReadContext` 读会话最后一次请求的上下文，claude、codex 才有）：手机终端太窄，Claude 状态栏里的百分比常被截掉，会话页和终端页标题下面的状态行末尾写「上下文 N%」（`mobile/lib/chat/context_meter.dart`，每 15 秒和状态变化时重读，75% 起琥珀色、90% 起红色）。点它弹框问要不要压缩，确认后先清空输入框（同快捷键栏的清空），再往终端发 `/compact` 和回车（Claude、Codex 都认；清空、命令、回车之间各隔 300ms，见 `sendAgentCommand`）。带 `posse.status.v1` 的连接在对话流里另收 `type:status`（`internal/mobile/status.go`）：终端一有输出，就从屏幕最后一行有字的往上 16 行里认出 agent 的状态行（Claude 的 `✻ Puzzling… (1m 54s · ↓ 9.5k tokens)`、Codex 的 `• Working (12s • esc to interrupt)`，都在第一列），去掉转圈符号、按键提示和"thought for"，变了才推，最多每 250ms 看一次屏幕，跳过的那次约好稍后补看；状态行消失时推空串。手机对话页（`mobile/lib/chat`）最后一行照着它写，没有时写正在用的工具。Claude 的回复整段写完才进会话文件（实测工具调用约晚 0.5 秒、思考约晚 3 秒），所以对话页靠状态行表示还在干活；发出去的话先画在末尾（`LocalEchoes`，发送中半透明、终端收下后写已发送），会话文件里新出现的用户消息按顺序认领最早的一条后撤掉（不比内容：图片换成了路径），斜杠命令不先画，5 分钟等不到也撤掉。
  - 延迟和断线检测：Posse 扩展 `runtime.ping`（电脑立刻回空结果，不用声明能力）。手机每 5 秒 ping 一次（`mobile/lib/protocol/latency.dart`，旧常驻进程没有它时改用 `status.get` 计时），会话页、终端页标题下面的状态行在上下文后面写最近 3 次中位数的信号格和毫秒数，不写单位（`LatencyLabel`：150 ms 内满格绿色，到 300 ms 两格灰色，300 ms 起一格琥珀色，没响应是带感叹号的红色空格加「无响应」）。首页顶栏同一个读数排在右边按钮那一组最前面、左右空出和图标按钮一样的间距（电脑胶囊用掉剩下的宽度、靠左，里面只有连接圆点和电脑名；胶囊变宽变窄它不挪），断线重连时不显示；右边的历史、新建、设置用紧凑尺寸（40）给它腾地方。同一条连接上的回复是一条条发的：一次 ping 期间连接上收发超过 64 KB（视频分段、图片、终端快照、上传）的样本是排队排出来的，不算。每次等 5 秒，超时又没收到任何请求的回复写红色「无响应」，并且马上补测；连续 3 次就 `PhoneRpc.drop` 交给重连，切网络、手机休眠后的半开连接 15–20 秒内发现（之前要等系统报错）。从后台回到前台（经过 hidden 或 paused，拉下控制中心只到 inactive 不算）时不等这一轮：马上 ping 一次，2 秒内没有任何回复就断开重连（`PosseLink.wake`）；本来就断着、正在两次重试之间等的，不等退避马上连。期间有别的回复回来（慢线路上分段下大文件）不算没响应；终端输出、标签这类推送不算：电脑那边这条连接处理请求卡住时推送照样在发，按字节算会一直"活着"、请求一直超时。状态行的状态、上下文、延迟共用 `statusLineStyle`（写明字重，不继承顶栏标题的粗体）。输入框发来的文字（`terminal.send` 的 `text`）带换行、程序又开着括号粘贴（DECSET 2004，Claude Code、zsh 都开）时，包在 `ESC[200~`、`ESC[201~` 之间当成一次粘贴送进去（`pasteText`，文字里的结束标记去掉），否则第一个换行会被当成回车，前半段先提交、后半段留在输入框；Claude Code 会把它显示成「[Pasted text #1 +N lines]」，回车照旧隔 120ms 单独发。终端页粘贴（快捷键栏的粘贴、系统菜单的粘贴、听写这类一次插进好几个字又带换行的输入）都按一次粘贴送进去（开着括号粘贴就包起来），不拆成字和回车，末尾的换行去掉（`trimPastedNewlines`），粘贴完停在输入框里、不直接发出去；选区复制时也去掉末尾的换行。电脑按顺序处理同一条连接的请求：要读盘、调 git、等索引或联网的（`files.*`、`git.status`、`git.diff`、`history.*`、`session.context`、看图看视频、`usage.refresh`、打洞）各开 goroutine，不挡按键和 ping；发送整条串行，等发送锁或写一条超过 1 秒记日志（`mobile: send N bytes waited … for the lock, wrote in …`），分得清是排在大消息后面还是线路慢。一条消息写了 3 秒还没写完、手机也有 10 秒没发任何东西来（Posse 手机每 5 秒 ping、Orca App 前台每 3 秒轮询，活着的不会这么安静），就当连接已死马上断开，手机随即重连，不等写超时（至少 15 秒）占着发送锁；只看写得久会误伤积着大块数据的慢线路。大块数据走二进制帧（`posse.bulk.v1`，`internal/mobile/bulk.go`）：文本帧是 JSON 加密后整帧 base64，里面的文件内容又是 base64，约为原始数据的 1.78 倍。声明了这个能力的连接上，`files.readRange`、`files.readPreview` 的图片、`session.mediaThumb`、`session.mediaRead`、`git.diff` 的图片两边，这些结果里的字节字段先拆成 64 KB 的二进制帧发（每块单独拿一次发送锁，按键回显和 ping 的回复能插在块之间），JSON 回复里只写 `blobs: {字段路径: 编号}`，手机按编号拼回（`PhoneRpc._fillBlobs`，调用方用 `rpcBytes`，旧电脑的 base64 也认）。帧头 8 字节：`0x62`、版本 1、操作、0、u32 编号（小端），和 Orca 终端流的 `0x74` 区分。上传大图时 `clipboard.startImageUpload` 带上 `expectedBytes`，新电脑回一个编号，手机把原始字节按 64 KB 的二进制帧连续发完再 `commitImageUpload`，不用每段等一次回复；旧电脑不回编号，照旧一段段传 base64（攒在内存里，最大 32 MB）。二进制帧上传电脑边收边写临时文件，最大 1 GB，视频、文件也走它（手机从文件流式读，不整个读进内存）：带 `name`（手机上的文件名）的放进新建的临时目录 `posse-mobile-*/原名`（只留文件名本身，去掉目录和控制字符），没带的按开头的字节认扩展名（jpg、gif、webp、heic、mov、mp4，认不出当 png）。Orca App 不声明这个能力，收发都和以前一样。
  - 常驻进程在 `0.0.0.0:6788` 开明文 WebSocket（避开 Orca 的 6768，两边可同时开），安全靠 E2EE v2（X25519 + HKDF + secretbox，`e2ee_test.go` 有 Orca 的测试向量）和设备 token。没有配对过的手机时不监听，生成配对码时才开始。发一条消息的写超时按大小算（`writeTimeout`：15 秒起，再按每秒 64 KB 加）：库在写超时时会关掉整条连接，手机上所有终端跟着掉线。不开 permessage-deflate：消息是密文的 base64，websocket 库写死的 BestSpeed 在 Go 1.27 下对它原样存储，压不动。
  - 主动断开：首页电脑胶囊打开的电脑列表里有"断开连接"（连着或正在连时才有），断开后配对留着、不自动重连（`disconnected`，只在这次运行里有效），胶囊写"电脑名 · 已断开"、灰点不转圈，首页列出配对过的电脑和台数，点一台就连，底下可以扫码添加。
  - 桌面侧栏「手机」行尾：有手机连着时一个绿点（不止一台时前面写台数），悬停写是哪几台。来自 `daemon.status` 的 `mobileOnline`（`Devices()` 里正连着的，同一台手机配对过几次只算一台），窗口每秒轮询照常拿到，不用打开手机页。
  - 主机密钥和配对的手机存在 `$POSSE_HOME/mobile.json`（0600）。手机按公钥认主机，换密钥等于所有手机重新配对。每扫一次码多一个设备 token；Posse 手机客户端每次握手在 `runtime.clientCapabilities.update` 里带 `phone`（安装 ID、型号、它存着的这台电脑的全部 token，`pairing.identify`）：同一台手机的 token 合成一项、名字换成型号，它不再存着的 token（重新扫码换掉、手机上删掉的）作废，没认领的旧 token 在它手里就归过来。Orca App 和旧版客户端不报，手机页收在"其他配对"里，可以全部移除。配对码在侧栏「历史」下面的「手机」页、「新建」菜单（侧栏底栏最左边的 +）或 `posse mobile pair`。
  - 映射：项目 → repo，工作区 → worktree（ID 是 `<项目 ID>::<工作区 ID>`），运行中的终端 → 标签（手机只认 UUID 形状的 leaf，由终端 ID 派生；标签名依次取桌面改的名字、会话标题、终端标题）。手机首页每个工作区下面，agent 会话和普通终端都各占一行（`_sessions`），普通终端的副标题写"终端"，点开进终端页、长按关闭。agent 状态 waiting → `waiting`（行状态 `permission`），working/starting → `working`，idle → `done`。

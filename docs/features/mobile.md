# 手机遥控

`internal/mobile`（常驻进程里的手机服务）和 `mobile/` 的 Flutter 客户端（Posse 手机客户端）。

## 连接与配对

- 只服务 Posse 手机客户端。握手、方法名和帧格式沿用 Orca 手机协议（stablyai/orca 的 `mobile/` 和 `src/shared/`），Posse 自己的扩展以 `posse.*` 能力声明；Orca 自己的手机 App 已改成从电脑下载网页包运行的壳，连 Posse 会提示"更新电脑上的 Orca"，不再兼容。
- 常驻进程在 `0.0.0.0:6788` 开明文 WebSocket（避开 Orca 的 6768，两边可同时开），安全靠 E2EE v2（X25519 + HKDF + secretbox）和设备 token。没有配对过的手机时不监听，生成配对码时才开始。
- 分帧在握手时定（hello 的 `framing`，格式见 `internal/mobile/e2ee.go`），只认 3：都走二进制帧，帧是 1 字节类型加 secretbox 的标签和密文，nonce 两端按计数器各自算、不上线，每帧固定开销 17 字节，JSON 不 base64。编号沿用 Orca 协议的分帧表，2 是 Orca App 的文本帧分帧（JSON 加密后整帧 base64，每帧开销 82 字节），电脑不再接受。手机只报 3，要求电脑端同步升级：旧版电脑读完 hello 以 4001 关连接，手机提示在电脑上更新 Posse。手机端的 secretbox 在 `posse_quic` 的 Go 里做（纯 Dart 的 TweetNaCl 在 iPhone 12 Pro 上慢约 4.7 倍；基准见 `mobile/benchmark`）。
- 配对码在侧栏顶上的「手机」磁贴、「新建」菜单（侧栏底栏最左边的 +）的「连接手机…」或 `posse mobile pair`：
  - 地址默认自动选（Tailscale 优先，其次局域网）；也可以自定义（配对对话框，或 `posse mobile pair --address`），规则照 Orca 的 `pairing-endpoint.ts`：主机或 主机:端口 拼成 `ws://`，完整 URL 的 http/https 换成 ws/wss、路径保留，用于隧道或反向代理（服务端不看请求路径）。
  - 手机页的地址下拉列出自动、检测到的每个 Tailscale 和局域网地址（取码时刷新）和用过的自定义地址；选的地址和用过的自定义地址存在 ui.json 的 `mobileAddress`、`mobileAddresses`。
  - 配对码 JSON 另有 `endpoints`：Posse 手机客户端同时连其中所有地址，先握手成功的留下。自动时是本机所有 Tailscale 和局域网地址，选了具体地址时只有它；`endpoint` 是其中的主地址。
- 配对页和首页的「添加电脑」可以扫码（iOS 用 AVFoundation，安卓用 CameraX 加 ZXing，不依赖 Google Play 服务），只认二维码，安卓深色底的反色码也认：扫到不是配对码的码相机不关，认到配对码才关相机去连；拒绝相机权限或开不了相机时回到配对页粘贴。
- 连上后底部提示连的是哪台电脑、实际走的哪个地址，电脑列表里当前那台也写实际地址。手机上的电脑按公钥加主地址认：同一台电脑扫远程和局域网的码存成两项，可以来回切，没改过名的名字后面带地址区分。
- 权限按用到的时候要：国行 iPhone 打开 App 时弹「无线数据」，点扫码要相机，第一次连局域网地址时弹「本地网络」。第一次配对（手机上还没存过电脑）连不上时每秒重试，App 在前台累计 30 秒才放弃（弹窗开着时不计时，点完允许就连上），放弃时提示检查电脑和这两项权限。电脑明确拒绝（密钥不对、拒绝能力声明）不重试；配对过的电脑只连一次。
- 配对的手机和主机密钥一起存在 `$POSSE_HOME/mobile.json`（0600），手机按公钥认主机（换密钥见 AGENTS.md）。每扫一次码多一个设备 token；Posse 手机客户端每次握手在 `runtime.clientCapabilities.update` 里带 `phone`（安装 ID、型号、它存着的这台电脑的全部 token）：同一台手机的 token 合成一项、名字换成型号，它不再存着的 token（重新扫码换掉、手机上删掉的）作废，没认领的旧 token 在它手里就归过来。旧版客户端不报，手机页收在"其他配对"里，可以全部移除。
- 桌面侧栏「手机」磁贴右上角：有手机连着时一个绿点（不止一台时前面写台数），悬停写是哪几台。来自 `daemon.status` 的 `mobileOnline`（同一台手机配对过几次只算一台），不用打开手机页。
- 主动断开：首页电脑胶囊打开的电脑列表里有"断开连接"（连着或正在连时才有）。断开后配对留着，这次运行里不自动重连；胶囊写"电脑名 · 已断开"、灰点不转圈，首页列出配对过的电脑和台数，点一台就连，底下可以扫码添加。
- 连不上：一开始就没连上（冷启动、切电脑、点重试都失败），手机不在后台重连，页面中间是报错和「重试」，胶囊写"电脑名 · 连不上"、红点不转圈。只有连上过之后断线才在后台一直重连，胶囊才是琥珀色的「连接断开，正在重连…」。
- 电脑列表弹窗：标题和底下的断开连接、扫码添加电脑固定，电脑多了只滚中间的列表；弹窗不到 360 高（横屏）时整张一起滚，免得列表被压没。

## QUIC 与中转

旧版客户端不调 `posse.quic`，照旧走 WebSocket。

- 手机服务在 WebSocket 同一个端口号上开 UDP 的 QUIC。一条连接只开一条双向流，上面跑和 WebSocket 一样的文本、二进制消息（u8 类型、u32 长度），握手、E2EE、RPC 全部照旧。TLS 只当传输加密，证书每次启动自签、手机不验，身份靠 E2EE。关闭时先发关闭帧（u16 关闭码加原因）再关流，排在正在写的消息后面。电脑读手机的消息上限 4 MB，和 WebSocket 一致。
- 手机每次连上都调 `posse.quic`，拿到端口、本机的 Tailscale 和局域网地址、中转地址和这台手机的令牌，换成 `hquic://主机:端口`（中转的带 `?relay=令牌`）存进这台电脑的记录，冷启动直接拨。这次走的是 WebSocket 时并发拨号，先握手成功的换掉 WebSocket，都不通就留在 WebSocket。之后的重连 QUIC 先连，WebSocket 晚 2 秒起跑兜底。经隧道的 WebSocket 只剩第一次配对和 UDP 不通的网络。
- 中转：`$POSSE_HOME/desk.json` 配了中转（和看桌面同一个 `tools/deskrelay`）时，每台手机第一次调 `posse.quic` 时 Mac 给它开一个 UDP socket，用这台手机的令牌每 10 秒向中转登记。令牌存在 mobile.json 的设备记录里（`relayToken`，设备列表不给出），一台手机一个，常驻进程重启、交接都不变。常驻进程开手机服务时、改了中转设置时，给拿过令牌的手机都开好出口，不在局域网的手机不用先调 `posse.quic` 就能经中转连回来。解除配对时关掉，换了中转地址或密钥全部重开。手机经中转时先登记、等到回执才握手，中转 1.5 秒不应答就失败。
- 中转的鉴权和邀请（协议见 `internal/deskrelay/auth.go`）：服务器带 `--secret` 启动时只认带签名的 Mac 登记，没签名、签名不对、时间差 5 分钟以上、名字在 `--revoked` 名单里的都回拒绝；手机不带密钥，只能加入 Mac 已经开好的会话（令牌只有配对过的手机知道）。每个人的密钥由主密钥和名字算出：管理员在服务器上用 `deskrelay admin-code` 取管理员码，贴进自己的 Mac，这台 Mac 存着主密钥，能给别人生成邀请码（名字只用来停用）；对方把邀请码贴进自己的 Mac。停用是在服务器的名单里加上名字，10 秒内生效，这个人开的会话立刻关掉。一个名字最多同时开 16 个会话（一台 Mac 每台手机一个，看桌面时再多一个），免得一个人占满服务器的 64 个名额。码是 `posse-relay:` 加 base64url，地址和密钥打在一起，不直接露出地址。
- 设置在手机页的「外网中转」一栏（`posse mobile relay` 同样能查看、设置、清除、邀请）：没配时贴邀请码；配了显示「外网中转 · 已就绪」或出了什么问题（邀请码无效、已停用、时间不准、中转不应答），不显示中转地址。状态是向中转发检查包（不开会话）问来的，手机页开着时 30 秒问一次。没带 `--secret` 的服务器谁都能用，`desk.json` 只有地址、没有密钥时照常登记。
- 打洞：经中转连上后在后台打洞。手机新开一个 socket，向中转发探测包问出它的公网地址，经 `posse.punch` 交给 Mac；Mac 从这台手机的中转出口问出自己的公网地址回给手机，同时从这个出口向手机的地址连发 4 秒打洞包；手机也从新 socket 向 Mac 的地址连发打洞包并拨 QUIC。3 秒内握手成功就换过去（显示「直连 · QUIC」），打不通（比如两边都是对称 NAT）留在中转。直连的地址不存：断了先连中转，再重新打洞。
- 换连接时旧连接等页面在新连接上订阅好、进行中的请求回完再关（0.5 到 10 秒），电脑上的终端不会被改回电脑尺寸再改回手机尺寸。
- 电脑列表和连上的提示里写「地址 · QUIC」或「经中转 · QUIC」。手机上的 QUIC 是编进 App 的 Go 库（`mobile/packages/posse_quic`，构建见 `mobile/README.md`），iOS、安卓共用。

## Posse 扩展协议

- `runtime.clientCapabilities.update` 声明的能力记在这条连接上，没声明能力的连接不收 Posse 扩展推送，也调不到要能力的方法。它还带 `locale`（手机界面的语言，BCP 47），电脑给这条连接的报错和说明按它翻译，没带的按中文。
- `runtime.ping`：不用声明能力，电脑立刻回空结果。
- 对话照 Orca 协议的 `nativeChat.readSession`、`nativeChat.subscribe`、`nativeChat.unsubscribe`：会话文件解码在 `internal/history/chat.go`（文本块截到 64000 字，工具输出截到 4000 字），订阅按 `subscriptionId` 登记，每 500ms stat 一次会话文件（文件还没出现时从 500ms 翻倍到 5s），追加推 `appended`，变短或换了 inode 推 `replacement`。`terminal.send` 的回复带 `writeSettlement`。
- `posse.permission.v1`：正在订阅某个终端对话时，Claude 的 PermissionRequest 走 `hook.permission.hold`：往这条对话流推 `{type:permission, requestId, terminal, tool, input}`，等 `agent.permission.decide`；桌面有人键入或 30 秒到了就返回空 behavior，`posse hook` 不输出、TUI 照常弹框。没有带这项能力的手机订阅着时立刻放行。为了挂得住，Claude 设置里 PermissionRequest 的 hook 超时是 40 秒（其余事件 5 秒），`posse hook` 等这次 RPC 35 秒（其余 2 秒），常驻进程交接打断时到新进程上再挂。
- `posse.git.v1`：只读的 `git.status`（文件带 `submodule`）、`git.diff`（拒绝绝对路径和 `..`；图片的 diff 另带 `images`：HEAD 里的旧图和工作区的新图，base64）。commit、push 不开放，切换分支见 `posse.git.v3`。手机的 Git 方法都在常驻进程里，不走窗口进程的 Git 界面。
- `posse.git.v2`：工作区下有几个仓库时（找法和项目的"识别多个 Git 仓库"开关同桌面，见 `git.md`），`git.status` 回 `repos`，每个仓库一项：`repo`（仓库根目录相对工作区的路径，工作区在仓库里时是 `..`，`git.diff` 带回来指定仓库）、`name`、`dir`（仓库在工作区下面时的路径）或 `sub`（工作区在仓库里的路径），手机按它们把仓库里的路径换成工作区里的路径去打开文件；外层仓库报成未跟踪的嵌套仓库不列。一个仓库读失败时只这一项带 `error`。图片 diff 的新图按解析软链后的路径读，不在仓库里的不读（指向外面文件的软链）。只声明 v1 的旧版 App 拿第一个仓库，`git.diff` 不带 `repo` 时也用第一个仓库。常驻进程按工作区缓存找到的仓库：工作区目录的修改时间变了、或过了一分钟才重找（撞了扫描上限的不按时间重找），手机每 3 秒一次的读改动不重扫。
- `posse.git.v3`：切换分支。`git.branches {worktree, repo}` 回 `head`、`operation` 和 `branches`（本地和远端分支，各带 `current`、`upstream`、领先落后、最后提交的 `time`；在别的 worktree 检出着时带 `elsewhere`（那个目录），那里是 Posse 工作区（工作区目录本身，或工作区里找到的一个仓库：多仓库的项目目录、多仓库的 worktree 工作区；项目目录里别的工具建的 worktree 不算）时再带 `workspace`（手机上的工作区 ID）；远端分支看检出时用的同名本地分支）。`git.checkout {worktree, repo, name, remote, force}` 走桌面同一个 `gitx.Checkout`（远端分支检出成同名的本地跟踪分支，本地已有就切过去）：在别的 worktree 检出着的报 `checked_out`，合并、变基进行中报 `conflict`；工作区里有 agent 正在工作、又没带 `force` 时不切，回 `confirm: <agent>`，手机问过再带 `force` 重发。切换（含失败的）记进桌面 Git 日志的操作记录，名字写"手机 · <手机名>"：常驻进程写进 `git-trace.jsonl`（`source: mobile`、`device`、`err`），窗口照终端命令的记录取回。多仓库的 worktree 工作区也能单独切一个仓库；记下的共用分支不跟着改，合并、删除照旧按它。
- 改动页的分支卡点了从底部弹出分支面板（多个仓库时点工作区名的卡片，先选仓库），顶上是搜索框，分"本地""远程"两组：本地的当前分支在最前，其余和远程的都按最近提交排；本地已有同名分支的远端分支不列（切过去就是那个本地分支）。点一个就切过去，成功后收起面板、提示"已切换到 …"并马上重读改动和首页列表；失败的报错留在面板里、重读分支；手机最多等 150 秒（电脑上切换最长 2 分钟），超时、断线这类不知道切没切的，重读后已经在目标分支上就当切换成功。别的 Posse 工作区检出着的写"在 <工作区> 里检出着"，点了换到那个工作区的改动页；Posse 外的 worktree 检出着的点不了。合并、变基进行中时面板顶上说明、分支点不了。电脑是旧版时面板里提示更新电脑端。
- 改动页有几个仓库时照桌面按仓库分组：只列有改动、停在合并或变基中、读失败的仓库，标题写仓库名、文件数、进行中的操作、分支和领先落后，点标题收起这个仓库。
- `posse.history.v1`：`history.list`、`history.search`、`history.resume`，转给常驻进程同名的接口；resume 回终端 ID 和手机上的工作区 ID，报错是中文。看会话内容走 `nativeChat.readSession`（按会话文件读，claude、codex、grok、cursor 都认；cursor 的记录没有工具结果，时间只有用户消息开头的 `<timestamp>`）。手机上不能移到废纸篓。
- `posse.context.v1`：`session.context`（参数同 `nativeChat.readSession`），读会话最后一次请求的上下文，claude、codex 才有。
- `posse.status.v1`：对话流里另收 `type:status`。终端一有输出，就从屏幕最后一行有字的往上 16 行里认出 agent 的状态行（Claude 的 `✻ Puzzling… (1m 54s · ↓ 9.5k tokens)`、Codex 的 `• Working (12s • esc to interrupt)`），去掉转圈符号、按键提示和"thought for"，变了才推，最多每 500ms 一次；状态行消失时推空串。
- `posse.draft.v1`：对话流里另收 `type:draft`，是 agent 正在写、会话文件里还没有的那段回复（只做 claude、codex），空串表示撤掉。和状态行共用同一次读屏和 500ms 节流，变了才推；接着上次推的往后长时只推新加的部分（`append`），换了一块、缩回去、撤掉时推全文（`text`）。agent 在干活（hooks 报 working，或屏幕上有状态行：两家流式写正文时都不画状态行）时，从输入框往上找最后一块：Claude 是第一列 `⏺` 开头、下面没有 `⎿` 的块（只有一行 `⏺ Reading 1 file…` 这类以省略号结尾的是刚开始的工具），Codex 是第一列 `•` 开头、不是 `Ran`、`Explored`、`Working` 这类条目的块，截到 `└ Tip`、`Worked for` 之前。两家都整屏重画、回滚区里没有回复（Claude 每次重画连回滚区一起清掉，Codex 在备用屏幕上），回复一长开头就滚出屏幕：每帧只取看得见的部分，在上一帧拼好的行里找这一帧的第一行、后面的行也对得上就从那里接上（正在写的末尾 6 行可以不同，空行不比，Codex 写下一段时才在两段间补空行），接不上时中间写一行 `⋯`。去掉续行缩进，按终端宽度判断折行接回上一行（下一行第一个词接在上一行后面会超宽才算折行，列表项不接），两边都是中日韩文字或全角标点时直接拼、否则补空格；空行保留成段落分隔，框线表格和代码行原样。草稿只当纯文本（TUI 已经吃掉了 `**`、反引号和代码围栏）。会话文件里最近一条助手正文规范成只剩字母数字后包含草稿时不推；同一块缩回去（Codex 写完一段重排时偶尔有一帧画错）最多按住 4 帧。agent 停下、最后一块不是正文、终端不在了时推空串。规则靠录下来的真实屏幕回放测试（`internal/mobile/testdata/draft`，录法见 `docs/plans/chat-draft.md`），Claude、Codex 升级后重录。
- `posse.bulk.v1`：大块数据走二进制帧。`files.readRange`、`files.readPreview` 的图片、`session.mediaThumb`、`session.mediaRead`、`git.diff` 的图片，这些结果里的字节字段拆成 64 KB 的二进制帧先发，JSON 回复里只写 `blobs: {字段路径: 编号}`，手机按编号拼回。帧头 8 字节：`0x62`、版本 1、操作、0、u32 编号（小端），和终端流的 `0x74` 区分。上传时 `clipboard.startImageUpload` 带 `expectedBytes`，电脑回一个编号，手机把原始字节按 64 KB 的二进制帧连续发完再 `commitImageUpload`；电脑边收边写临时文件，最大 1 GB，视频、文件也走它。带 `name`（手机上的文件名）的放进新建的临时目录 `posse-mobile-*/原名`，没带的按开头的字节认扩展名（jpg、gif、webp、heic、mov、mp4，认不出当 png）。
- `posse.media.v1`、`posse.tools.v1`、`posse.desk.v1`：见下面「图片与视频」「技能与工具」「看 Mac 桌面」。
- 映射：项目 → repo，工作区 → worktree（ID 是 `<项目 ID>::<工作区 ID>`），运行中的终端 → 标签（手机只认 UUID 形状的 leaf，由终端 ID 派生；标签名依次取桌面改的名字、会话标题、终端标题）。agent 状态 waiting → `waiting`（行状态 `permission`），working/starting → `working`，idle → `done`。
- 电脑按顺序处理同一条连接的请求；要读盘、调 git、等索引或联网的（`files.*`、`git.*`、`history.*`、`session.context`、看图看视频、`usage.refresh`、打洞）各自并发，不挡按键和 ping。一条消息写了 3 秒还没写完、手机也有 10 秒没发任何东西来，就当连接已死马上断开，手机随即重连。
- 输入框发来的文字（`terminal.send` 的 `text`）带换行、程序又开着括号粘贴（DECSET 2004）时，包在 `ESC[200~`、`ESC[201~` 之间当成一次粘贴送进去，Claude Code 显示成「[Pasted text #1 +N lines]」；回车隔 120ms 单独发。
- 新加的字段和方法旧常驻进程没有时，手机按缺省处理：不显示这一项，或退回 Orca 协议里的做法。

## 延迟和断线

- 手机每 5 秒 `runtime.ping` 一次。会话页、终端页标题下面的状态行在上下文后面写最近 3 次中位数的信号格和毫秒数：150 ms 内满格绿色，到 300 ms 两格灰色，300 ms 起一格琥珀色，没响应是带感叹号的红色空格加「无响应」。首页顶栏左边是电脑胶囊（用掉剩下的宽度，里面只有连接圆点和电脑名），同一个读数排在右边按钮组最前面，断线重连时不显示。一次 ping 期间连接上收发超过 64 KB 的样本不算。
- 等 5 秒没回、期间也没收到任何请求的回复，写「无响应」并马上补测；连续 3 次就断开重连，切网络、手机休眠后的半开连接 15–20 秒内发现。终端输出、标签这类推送不算活着。
- 安卓在首页按返回键只退到后台、不关 Activity，和 iOS 一样连接留着（安卓 16 的预测性返回不经过 App，Activity 照样被关掉）。Activity 关掉时 Flutter 引擎跟着销毁、进程还在，Go 里的 QUIC 连接再调回调就崩溃（小米会冻住后台进程，回到前台解冻时必现），所以 `MainActivity.onDestroy` 先经 JNI 调 `hq_reset`：不再回调、断开所有连接、等正在进行的回调调完；新引擎第一次连接前再调一次兜底。
- 从后台回到前台（拉下控制中心不算）时马上 ping 一次，2 秒内没有任何回复就断开重连；正在两次重试之间等的马上连。连着的话马上拉一次首页列表，不等 3 秒一轮的轮询。
- 常驻进程退出（重启、交接）时逐条关掉 QUIC 连接、通知手机：新进程紧接着听同一个端口，手机收不到端口不可达，不通知要等上面的 15–20 秒。手机每换上一条新连接（重连、换到 QUIC 或打洞直连）都马上拉一次首页列表。
- 首页会话行和会话顶栏的状态照桌面侧栏：常驻进程在会话里另给 `posseStatus`（启动中、工作中、待处理、本轮完成、等待任务、完成没看、未恢复），`state` 照旧按 Orca 协议的取值给。等待任务是陶土色波形，完成没看是陶土色铃铛（每 2.4 秒摇一轮），减少动态效果时都不动；看过的本轮完成和桌面一样不画、只留位置（顶栏不留，文字仍写「本轮完成」），也不进汇总；收起的项目行汇总时次序同桌面（待处理、没看、工作中和等待任务、启动中）。完成没看和桌面共用一份（见 `ui.md` 完成未读）：手机开着这个会话的终端页或会话页就算看过，看着时完成的也不提醒。上一个常驻进程留下、还没恢复的终端也列出来，写「未恢复，点开时拉起」，点开订阅终端时常驻进程才拉起它。
- 断线时首页按没有状态显示：会话行写「等连上电脑」，等你处理的横幅、收起的项目行上的状态都不显示。

## 终端页

- 尺寸：手机看终端时终端按手机屏幕排版，界面这时的尺寸变化先记下，手机全部离开后恢复（行数变多见 AGENTS.md「界面接入终端」），手机的流随后重发快照。手机接入不接管终端查询的应答。手机本地尺寸变过就重新订阅拿快照，尺寸停止变化 150ms 后才订阅一次。
- 改回电脑尺寸：终端被手机占着尺寸时 `terminalInfo.phoneSized` 为真，窗口在终端上方显示一行提示和"改回电脑尺寸"（`terminal.reclaimSize`：放掉所有手机的占用、按界面最后要的尺寸重排；手机的订阅还在，重新打开这个终端才会再占）。要它是因为手机切到后台时连接常常还挂着，电脑上会一直是窄的。
- 电脑布局：终端的"更多"里有"电脑布局"，订阅时不带手机尺寸，终端保持电脑的列数和行数，手机把格子缩进屏幕宽度（双指放大吸到 0.5–2 的固定档后再滑），不改 PTY 尺寸。上下拖动照常平移。
- 键盘：弹出、收起不改终端尺寸。快捷键栏贴着键盘上移，终端整体往上挪到最后一行内容（有字或铺了底色的最后一行和光标所在行取靠下的）露在快捷键栏上方，最多挪键盘盖住的高度；shell 刚开、内容在上半屏时不挪。提示和上传进度浮在看得见的那块上。点终端（含电脑布局里格子外的空白）只在键盘收着时弹出，弹着时不收；收起键盘用快捷键栏最前面的键盘键。点链接不动键盘。
- 画面：弹出、收起键盘或从后台回来后，Claude Code 改尺寸重画时不变的行（分隔线、状态栏）照常画出；程序的同步更新（mode 2026）结束才出帧，最多等一秒，Claude Code 重画时不会画出半截、整屏上下跳；推入动画结束、回到前台、agent 从工作中停下来时重取一次画面；第一份快照到之前终端区域中间显示加载动画，这期间推入动画结束、尺寸没变的布局都不重新订阅，免得丢掉正在路上的快照、空白多等一个来回。终端输出走 Orca 协议的 16 字节头二进制帧，按 UTF-8 字符边界切块。等宽字体回退链带 App 自带的 Symbols Nerd Font Mono（MIT），提示符里 Nerd Font 的图标能显示。
- 选区：长按选中词（不震动），两端有把手，松手后拖把手改范围，点终端空白取消；宽字符按整字选。选区上沿有「复制」和「全选」（放不下就改到这一行下面），全选扩到当前段落（上下遇到空行停下）。复制不带末尾的换行。
- 粘贴：快捷键栏的粘贴、系统菜单的粘贴、听写这类一次插进好几个字又带换行的输入，都按一次粘贴送进去（开着括号粘贴就包起来），去掉末尾的换行，粘贴完停在输入框里、不直接发出去。
- 链接：轻点网址交给系统浏览器，指向工作区里文件的路径（含 `file://`）在文件页里打开，工作区外的提示打不开。
- 滚动：全屏程序跟踪鼠标时，手指滑动换成的滚轮报在手指所在的格子；不跟踪鼠标时，只在程序开着 1007 时换成方向键，和桌面一致。
- flterm 的改动见 `mobile/third_party/flterm/POSSE.md`。

### 快捷键栏

- 最前面是切换系统键盘的键盘键；后面的键在设置里可排序、加自己的键。内置键默认顺序：发送文件、粘贴、（自己加的键）、Esc、Tab、Enter、立即发送（键帽 ⌃↩）、⇧Tab、^C、清空、Exit、方向键。新版本加的内置键插在默认顺序里它前面那个键后面。
- 发送文件（回形针）：先放下键盘，再从相册选照片或视频、拍照、或从「文件」App 选，传到电脑后把路径当一次粘贴打进终端、不回车，路径里的空格、括号等加反斜杠（和把文件拖进 macOS 终端一样）。
- 清空：agent 终端里删掉整个输入框（Ctrl+E、Ctrl+U、退格逐行删，最多 40 行），不用 Esc、^C（干活时是打断）；shell 终端只删当前行。Cursor Agent 把一次读到的几个按键当成一段输入、控制字符原样插进输入框，给它的按键经 `terminal.send` 的 `rawKeys` 由电脑隔 20ms 一个一个写，最多 20 行。
- Exit：清空输入框后写上 `/exit`（Claude Code、Codex、Grok、Cursor 都认），隔 300ms 再写命令，不回车，由用户自己发送；不发 Ctrl+D，免得多出来的一次把 shell 也关了。没在运行 agent 的终端只提示。
- 立即发送：Claude Code 的 `chat:sendNow`，干活时排着队的消息马上交给模型。实际发的是同样绑定的 Ctrl+X Ctrl+S（Ctrl+Enter 要 kitty 键盘协议，手机终端发不出）。
- 方向键、Home、End（内置和自定义）按程序当前的光标键模式编码：开着应用模式（DECCKM）时发 ESC O A，htop 这类 ncurses 程序只认这种；`posse terminal send --key` 也一样。

## 对话页与历史

- 会话页、终端页标题下面的状态行：agent 状态（照 `type:status` 写，没有时写正在用的工具）、「上下文 N%」、延迟（见「延迟和断线」），延迟后面写这条连接是「中转」还是「直连」（局域网、Tailscale、打洞都算直连）。上下文每 15 秒和状态变化时重读，75% 起琥珀色、90% 起红色；点它弹框问要不要压缩，确认后先清空输入框，再往终端发 `/compact` 和回车（Claude、Codex 都认）。
- Claude 的回复一块写完才进会话文件，Codex 要等一轮结束；这期间对话末尾、状态行上面画「正在输出」的草稿（`posse.draft.v1`）：纯文本，以空白开头的代码行和框线表格用等宽字体、不折行、太宽左右滑；收到空草稿、会话文件里来了新的助手正文、对话流结束或断线时撤掉。草稿变长时停在底部就跟着长，往上翻着看时画面不动、底部出「新消息」。发出去的话先画在末尾（发送中半透明、终端收下后写已发送），会话文件里出现对应的用户消息后撤掉；斜杠命令不先画，5 分钟等不到也撤掉。
- 选图面板：相册可以多选照片和视频，另有剪贴板和「文件」。照片先预览、发送时传，视频和文件选了就传（存到电脑的 `$TMPDIR/posse-mobile-*`，见 `posse.bulk.v1`），路径一个一行接在输入框后面。上传时列表或终端底部浮着第几张和百分比，不占布局，终端不改尺寸。
- 历史：首页顶栏的时钟进历史。顶栏是返回键、搜索框和分组按钮，没有页标题；下面一行小标签照桌面按 agent 筛选（全部、Claude、Codex、Cursor、Grok，列表和搜索都带 `agent` 交给电脑，每次进来从全部开始）。列表默认按今天、昨天、最近 7 天、最近 30 天、1 个月前分组，顶栏右边的分组按钮（图标是当前的分组：时钟或文件夹，点一下换另一种；搜索时不可点）可以换成按文件夹分组（规则同桌面：归到目录所在的项目，项目和它的工作区、worktree 取最长匹配，都不在的用目录名，组按其中最近的会话排；选择记在手机设置里）；组名右边是条数和箭头，点组名展开收起，进来时只展开第一组，换筛选或分组方式后也回到只展开第一组；搜索结果按相关度排、不分组、带命中摘要；点开只读看对话（往上翻到头自动读更早的一页），底部"在电脑上继续"调 `history.resume`，提示里能直接在手机上打开那个会话。
- 项目历史：首页项目行右边的圆按钮（和会话页、终端页顶栏的文件夹按钮）进的工作区页分「改动 | 文件 | 历史」三页（分段放在顶栏里、返回键右边；工作区名、分支写在改动页最上面的分支卡上，多个仓库时卡上写工作区名和路径），历史页只列这个工作区目录（含子目录）里的会话，列表和搜索都带 `cwd` 交给电脑；搜索框在最上面，agent 筛选、点开和在电脑上继续同历史页，只按时间分组、没有分组按钮。

## 文件与媒体

- 文件页：`files.readDir`、`files.list`、`files.searchPaths`、`files.read`、`files.readPreview`、`files.stat`，只读，路径相对工作区、拒绝绝对路径和 `..`，限制照 Orca（文本 512 KB 截断、图片 10 MB、清单 5000 个）。音频、编辑保存、在桌面打开没做。文件树、搜索结果和改动页的图标照桌面按类型画（改动页删除的文件图标变灰，子模块和嵌套仓库画成目录）；改动页和桌面一样不写状态字母，文件名按状态上色（修改和重命名蓝、新增绿、删除灰加删除线、未跟踪和冲突红）（见 `files.md`，Xcode 的包目录也换成各自的图标）：图形、颜色和按文件名、扩展名认类型的表由 Go 测试 `TestMobileFileIcons` 从 `internal/app/fileicons.go` 生成到 `mobile/lib/ui/file_icons_data.dart`，桌面改了表不重新生成测试就失败（`POSSE_GEN=1 go test ./internal/app -run TestMobileFileIcons`）；按前后缀认的几条（`kindByAffix`）和符号链接的图标也一起生成。符号链接照桌面是带拐弯箭头的文件夹和纸（`files.readDir` 的 `isSymlink`）。
- 视频（mp4、mov、m4v、webm）由 Posse 扩展 `files.readRange` 分段下载（每段 1 MB，同时 2 段，每段等 60 秒、超时再试两次）到手机临时目录再播放，按路径、大小、修改时间缓存，超过 500 MB 不下。没下完时留着 `.part`，错误页的"接着下载"或下次打开从断处接着下。
- 从文件树点开图片或视频时，同目录的其他图片、视频按树里的顺序排成一组，左右滑切换，顶栏的文件名和存到手机跟着换（搜索结果、Git 页、链接打开的只看这一个）。
- Markdown：表格按内容宽排、一列最宽 220、太宽左右滑，任务列表画勾选框，嵌套列表逐层换圆点；相对链接和图片按 md 文件所在目录算，工作区里的文件在文件页打开、图片向电脑要（最近 24 张留在内存里，`/` 开头的按工作区根目录找，去掉 `?raw=true` 这类后缀），网址交给浏览器。文件页照桌面（`files.md`）解释正文里的 HTML（`mobile/lib/files/markdown_html.dart`，对话页不解释）：`align` 居中、靠右，`<img>` 的 `width`、`height`（像素或百分比），`<a>` 包着的图片点了打开链接，行内标签，`<table>`（格子里只有一段文字、第一行是 `<th>` 的照 Markdown 表格画，否则格子里能放块、列宽照百分比分），`<details>` 点 `<summary>` 展开，`<td>` 之间空了行写的 Markdown 挂回格子，`<script>` 这类连内容一起丢掉。网上的图手机自己下载（20 秒超时，最大 20 MB），`data:` 地址直接解，SVG（含 shields.io 这类带文字的徽章）用 flutter_svg 画，位图最长边按 1600 像素解码。文件页和对话页用同一套 GitHub 风格的解析规则。语言是 `mermaid` 的代码块画成图（和桌面同一套排版，见 `files.md`）：排版在编进 App 的 Go 库里（`posse_quic` 的 `renderMermaid`，后台 isolate 调，不经过电脑），Dart 先用 App 的字体量好源码里的字和 ASCII 的宽度交过去，图形用 flutter_svg 画，文字用 App 的字体自己画；画好之前照代码块显示，语言栏右边可以切回源码，写错的上面一行红字报错；比屏幕宽就等比缩小，点图全屏、双指放大看。
- 源码、diff 和 Markdown 代码块在手机上本地着色（配色同桌面编辑器的 GitHub 深浅两套）：按文件名或围栏语言认，认不出不着色；超过 256 KB 不着色。源码和 diff 按行只建看得见的，选中复制时行之间有换行。

### 图片与视频

- 带 `posse.media.v1` 才有：会话页、终端页的"更多"里"图片与视频"，内容和桌面的图片面板一样。`session.media`（参数同 `nativeChat.readSession`）列出 agent 生成的（最近 40 项）和粘贴的；`session.mediaThumb` 给 480 像素宽的 JPEG 缩略图（视频取第一帧），一次只做一张；`session.mediaRead` 按段读原图或视频（同 `files.readRange`，每段 1 MB）。每项的 `label` 是文件名、工具名或 `#序号`，没有名字的一类改发 `tag`（`generated` 生成的图片、`codeOutput` 代码产出、`pasted` 没有序号的粘贴），手机按界面语言写出叫法。手机只能按列表给过的 ID 读。会话文件被重写后按旧偏移读不到时回「会话文件里没有这张图片了」。
- Codex 工具返回的内嵌图片也列在生成组，和桌面一样保留会话里的快照、以工具名显示；只隐藏生成目录中的相同内容副本，不合并多次查看，不收工具文本中的图片路径。
- 手机上两列网格，开着时每 3 秒重列；点开图片是原图（agent 当时看到的样子），双指放大，视频和文件页走同一套分段下载和播放。左右滑切到前一项、后一项（顺序同网格：先生成的、再粘贴的，副标题末尾写第几项），翻走的页释放（视频停下、缩放不留）。原大时单指翻页，放大后单指平移。

### 技能与工具

- 带 `posse.tools.v1` 才有：会话页、终端页的"更多"里"技能与工具"，内容和桌面的技能与工具面板一样（识别规则见 `ui.md`）。`session.tools`（参数同 `nativeChat.readSession`）由常驻进程读会话文件（`history.UsageScanner`，每个会话记住读到哪，最多记 8 个，再列只读新增的部分），回 `found`（会话文件找到没有）和 `skills`、`mcp`、`cli`、`web`（按域名）、`searches`（网页搜索次数）、`events`（技能和 MCP、命令行程序、网址各留最近 300 次调用；网址、搜索的记录带 `url` 或 `query` 和 `via`）。窗口关着也能看。
- 手机上开着时每 3 秒重读。顶上是筛选（全部 / 技能和 MCP / 网址，存在手机上的 `tools.filter`，所有会话共用，和桌面各记各的），然后是技能、MCP 服务的次数，命令行程序按 Homebrew、其他命令行、系统自带分组，网址按域名，下面是时间线（连着调同一个工具合成一项）。点名字复制；时间线里的命令行程序长按看最近一次的完整命令，网址点一下复制完整网址，长按看完整网址、复制或用浏览器打开。

### 存到手机

- 文件页、图片与视频页看大图或视频时顶栏右边有按钮，原文件取到手机上之后才能点（视频要等下完）；文件列表长按文件、图片与视频网格长按一格，弹出面板，现下（带进度、可取消、断了接着下）再存，任意文件都行，超过 500 MB 不下。面板另有"分享"，发给别的 App。
- 按格式定存到哪：jpg、jpeg、png、gif、webp、heic、mp4、mov、m4v 存进相册的「Posse」相簿（安卓在 `Pictures/Posse`）；其余格式和相册拒收的，安卓存进「下载/Posse」（重名时改成 `x (1).md`），iOS 弹系统分享面板（里面有"存储到文件"）。存的文件用原名（会话里粘贴的图片按文件头补扩展名）。
- 权限：相簿要相册的读写权限（iOS 选"限制访问"也行；安卓 10 及以下要写存储权限）。
- 同一个文件同时只有一个在下，边看视频边存不冲突。

## 推送通知

只有 iOS 版（方案见 `docs/plans/push.md`），安卓没有。

- 什么时候推：agent 进入等待你处理，或从工作中停下、记成完成没看（`internal/daemon/push.go`）。等 4 秒还是这个状态、仍没看才推；同一个终端 30 秒内只推一次，通知按终端折叠，后一条换掉前一条。这台手机开着 App 连着电脑（报过在前台、12 秒内收到过它的包）、Mac 60 秒内有键鼠输入（HID 空闲时间）时不推。派了任务在等结果的不推。
- 注册（`posse.push.v1`）：手机每换上一条新连接调 `posse.push.register`，带 APNs token、推送密钥（App 第一次用时生成 32 字节，存在 App Group `group.com.neolabsapp.posse.mobile`）、是否沙盒、两类开关；两项都关或没给通知权限时 token 为空，电脑删掉注册。注册按手机安装 ID 存在 mobile.json 的 `push`，一台手机一条，这台手机的配对都移除时一起删。App 切到后台、回到前台时调 `posse.push.presence`。
- 发送：内容（种类、agent、项目、工作区、标签名、消息、电脑公钥、工作区 ID、终端 ID）用推送密钥 AES-256-GCM 加密，经 `desk.json` 的外网中转交给 APNs（中转上配了 `--apns-key`；包格式、去重和限流见 `internal/deskrelay/push.go`），没配中转的电脑推不出去。中转 1.5 秒没回执重发，最多 3 次，最多等 12 秒；APNs 说 token 失效时删掉注册。内容太长时先缩短消息和标签名，不整条丢掉。手机开着 App、Mac 在用、没配中转而没发出去的，不占同一终端 30 秒的间隔。APNs 上的明文只有兜底文字和角标（等待处理加完成没看的会话数）。
- 手机：通知扩展 `ios/PushService` 解密，按 App 里选的界面语言写标题（「Claude 等待你处理」「Claude 已完成」）、副标题（项目 · 工作区 · 标签名）和正文（agent 的消息），解不开时写「有会话需要你处理」。点通知按电脑公钥找到存着的电脑（连着的优先，不是就切过去），等会话列表里有这个终端就打开它。App 在前台时也显示横幅；角标在首页列表刷新时按同一口径更新。
- 设置页「通知」：「agent 等你处理时」「agent 完成时」两个开关和一行状态（已开启、电脑没配外网中转、系统里没允许通知、电脑太旧等）。第一次连上电脑时弹系统的通知权限框，只弹一次；拒绝后回到前台会再检查一次权限。

## 看 Mac 桌面

iOS 和安卓。收包、解密、补发、拆 RTP、硬解都在原生插件里，解出的帧直接交给 Flutter 纹理，不经 Dart；两端各一份、包格式和统计口径一致（`mobile/ios/Runner/DeskSession.swift`、`DeskPlugin.swift`，安卓是 `mobile/android/app/src/main/kotlin/com/neolabsapp/posse/mobile/` 下的同名 `.kt`）：iOS 用 VideoToolbox 解码，安卓用 MediaCodec 异步解码、直接画进 Flutter 纹理的 Surface，开了低延迟模式（高通另加它的低延迟开关）；海思解码器在纹理的 Surface 上配不出输出缓冲区，改画在平台视图（SurfaceView）上，别的解码器在纹理上一帧没出就坏了也换过去。手机不能硬解 HEVC 时不订阅。安卓的 UDP 包都不在主线程发（安卓不让主线程收发网络）。安卓退到后台时 Surface 会被收回，回来后重建解码器、要一张关键帧。安卓的横屏用原生方向锁（`SENSOR_LANDSCAPE`，不受自动旋转开关限制）；没有延后边缘手势的开关，靠沉浸模式（边缘第一下只唤出系统栏）。取舍记录见 `docs/plans/phone-desktop.md`，界面调研见 `docs/plans/phone-desktop-ui.md`。

- 入口：设置「看桌面」开着（默认开）时，首页电脑胶囊打开的菜单第一行是「看桌面」。
- 订阅：`desk.subscribe`（能力 `posse.desk.v1`，带屏幕像素、能解的编码（现在只有 hevc）和上次看的屏 `display`）是一个流：先回 `ready`（端口、编码、nonce；配了中转时带中转地址和令牌；支持补发时带 `nack: true`，认密码事件时带 `password: true`），之后推 `state`（辅助功能有无、锁屏与否、密码打完 `password_typed`）、`displays`，结束时推一条 `end`（`stopped`、`unsubscribed`、`no_report`、`capture_failed`）。UDP 的密钥用这条连接的会话密钥做 HKDF（`posse-desk/v1`）。`desk.unsubscribe` 或连接断开都会停掉采集。
- 同一时间只有一台手机能看，第二台订阅得到 `busy`（「另一台手机正在看」）。
- 锁屏：锁着屏照常看（ScreenCaptureKit 采得到锁屏界面），采集子进程报状态，常驻进程推 `state` 事件 `locked`、`unlocked`，观看不断。子进程每次启动都报一次当时锁没锁，常驻进程只在变了时推给手机：解锁那一刻系统常把采集停掉、子进程重启，旧子进程收不到解锁通知，靠新子进程的这一报把手机从锁屏放出来。开始看时 Mac 已锁屏，子进程声明一次用户活动（屏幕熄了会点亮）并原地挪一下指针，唤出密码框。锁屏期间手机打的字按当前键盘布局逐个按键注入（密码框认按键），距上次唤出超过 5 秒先再唤一次。只看一个窗口时锁屏期间改看主屏，解锁后换回那个窗口（锁屏期间手机选了别的屏就不换回）。手机在画面上方显示「Mac 已锁屏」和「输入密码」，密码在底部弹层里输入，发送前 Mac 已经解开了就不发。密码作为一条单独的输入事件（`EventPassword`，`ready` 带 `password: true` 的 Mac 才发）交过去：Mac 当场查锁屏（`CGSSessionScreenIsLocked`，不看通知更新的缓存），没锁就整条丢掉、只记一行不含密码的日志；锁着时按键和回车只投给这个用户的 loginwindow（`CGEventPostToPid`），逐字之间、回车之前都再查一次，中途解开就停，不会落进解锁后最前面的 App。直接投给进程的按键唤不出密码框，所以先按上面的办法唤一次，屏幕熄着时等它亮了再打；整串打完、按了回车才推 `password_typed`。防连发：手机发出后 3 秒内（Mac 报解锁就提前结束）按钮显示「正在解锁…」、不再发；Mac 打完一条后 2 秒内再来的密码整条丢掉（loginwindow 还在验证上一条，打进去会接在后面多算一次输错）。连不认密码事件的旧 Mac 时不发密码，点「解锁」或「输入密码」提示先更新电脑上的 Posse（手机键盘照常能往密码框打字）。弹层里可以「记住密码」：发出后 15 秒内 Mac 报解锁才存（输错的不记；还要先收到 `password_typed`，密码被丢掉、Mac 由别的途径解开的不存），按电脑的主机公钥存在 iOS 钥匙串里（手机解锁时可读、只在这台手机、不进备份；安卓用 Android Keystore 里导不出的密钥加密，存在不进备份的目录）；记着时胶囊上是「解锁」，一点就发，旁边的钥匙按钮重新输入或忘掉。打开「看桌面」后，设置的「看桌面」里写着记了几台电脑的密码，「全部忘掉」清空。
- 授权：没允许屏幕录制时订阅得到 `permission_screen`；没开辅助功能时能看不能操作，画面上有提示，在 Mac 上打开后提示自动消失。Mac 的手机页在有人看或缺授权时多一张「看桌面」卡片（`daemon.status` 的 `deskViewer`、`deskMissing`）：写哪台手机正在看，「停止」（`desk.stop`）断开它的画面和操作；缺哪项授权各一行说明和「打开系统设置」。
- 线路：
  - 连接的主机是局域网、Tailscale 或本机回环时，UDP 直接发到它。走隧道时从同一台电脑存着的其他地址里挑第一个能直连的，订阅仍走当前连接；5 秒没出画面提示手机和 Mac 不在同一个局域网。
  - 一个都没有、Mac 在 `desk.json` 配了中转时，手机同时发往直连候选和中转，Mac 从哪条路收到就从哪条回，直连还通时不换到中转；10 秒没出画面提示直连和中转都不通。中转也没配时退订，提示在同一个 Wi-Fi 下扫这台 Mac 的局域网码或改用 Tailscale。
  - 画面经中转到了之后打洞，流程同「QUIC 与中转」，区别是手机用收画面的 socket 问公网地址、经 `desk.punch` 交给 Mac；打通了改发直连，打不通留在中转。调试面板的「线路」显示直连、中转或打洞直连。
- 弱网：
  - 3 秒没收到手机的报告先暂停发画面，20 秒内回来就接着发，20 秒还没回来才以 `no_report` 结束。切网络、进电梯断几秒不用手动重连；手机被强退时 Mac 的录屏和防休眠最多多留 20 秒。
  - 起始码率：直连照 Moonlight 的默认值（按像素数插值，1080p60 是 20 Mbps，1920×1246 约 24 Mbps），上限 40 Mbps；经中转按画面大小从小的起步（1920×1246 是 8.6 Mbps），上限 20 Mbps。手机的 hello 常比画面配置晚到，开头按中转起步，认出直连再放开；换线路时跟着换。
  - 网络变差时先降码率（最低 400 kbps），再把帧率上限依次降到 30、15、10，15 帧及以下时画面长边减半；好转后码率先快后慢地回升，帧率和尺寸跟着升回。排队延迟要一秒里至少 3 条报告都带着才算数：画面静止时只来一个大帧，它自己发得久不算堵。
  - 丢包时手机按序号点名要补发（`ready` 带 `nack: true` 时），Mac 从最近发过的包里补；补不回来才丢掉这一帧，停在上一帧等关键帧，不显示花屏。
- 画面停住后补清楚：Mac 的屏幕采集画面不变就不交新帧，停下前那帧是动着时按每帧的预算编的。停住 100 ms 后按采集节奏把最后一帧再编 40 遍，编码器每遍对着上一遍的结果补残差（实测 6 Mbps 下亮度 PSNR 从 37 dB 升到 48 dB，共约 300 KB），有新画面就停。
- 采集出错：采集子进程出错退出（ScreenCaptureKit 停了流、编码连着失败 3 次）或 10 秒既没心跳也没画面时，常驻进程重新拉起它，接着看原来那块屏，码率、帧率和尺寸照旧，手机这一路不断，画面从新的关键帧接上；只看一个窗口时回到整块屏。重建前等 0.5、1、2 秒，一分钟内重建 3 次还不行就以 `capture_failed` 结束。没出新帧是画面没动，不算出错。
- 画面：选屏和只看一个窗口都在悬浮球的「画面」里，电脑报了屏就出现（一块屏也有）。面板上面是整块屏（多块时只画按真实排布的缩略图，名字和分辨率写在各块里，点哪块看哪块；一块屏时是一行名字和分辨率），下面是窗口列表，每个窗口前面是它所属 App 的图标（Mac 按 App 给一份 64 像素的 PNG，取不到时画通用的窗口图标）。面板高度固定，内容在里面滚。
  - 多块屏（取舍见 `docs/plans/phone-desktop-displays.md`）：开始时、切屏后、拔插或改分辨率后，订阅流里推 `{type:"displays", current, displays}`（每块屏的 ID、名字、全局坐标里的点、像素，哪块是主屏）。点哪块屏经 `desk.display {id}` 切过去，缩放回到 1 倍。选的屏按电脑记住，下次订阅带上，那块屏不在就看主屏；看着的屏被拔掉回主屏。
  - 只看一个窗口（取舍见 `docs/plans/phone-desktop-windows.md`）：窗口列表在面板打开时经 `desk.windows` 现要（当前空间看得见的普通窗口，最前的在前面，去掉太小的、没有名字的）。点了经 `desk.window {id}` 只采这个窗口（别的窗口盖着也不进画面），画面是窗口的像素大小，Mac 上把窗口提到最前。点击、滚动按窗口当前的位置换算，按下前窗口被盖住或它的 App 不在最前时先提到最前。窗口改大小时画面跟着变；关掉、最小化或切到别的空间了回到所在的整块屏，displays 事件带 `gone`，手机提示几秒。只看窗口时 displays 事件带 `window`（ID、App、标题），面板里给它打勾。窗口不记，下次观看照旧从记着的屏开始。
- 悬浮球：有画面后沉浸显示，只留一个悬浮球。上下左右都能拖，松手吸到最近的左边或右边；竖屏默认在右上角，横屏默认在没有刘海的那一侧中间。键盘和快捷键栏弹出时球留在它们上面。横竖屏各记各的位置，离开页面回到默认。收起时是连接质量的信号格（颜色和格数同延迟读数）和帧率（上一整秒解码出的帧数，照 Moonlight 每秒换一次读数，第一帧后满 1 秒才有数；Mac 只在画面变了时出帧，1 秒没新帧写「静止」），点开是返回、横竖屏（图标画当前的方向，点一下切到另一个）、键盘、快捷键、调试、断开；放大后双指缩回 1 倍，4 秒不碰收起；还没画面时一直展开。
  - 返回离开页面（左缘拖动是平移画面，不触发页面返回）；断开停掉这一路画面并留在页上，已经停了再点是重新连接。
  - 调试显示帧率（解码出的和收到拼成整帧的，差得多是解码跟不上）、码率、解码耗时（这几项和悬浮球的帧率一样每秒换一次）、丢包、已发和已确认的输入序号，可以改 UDP 地址。码率照 Moonlight：只算视频本身（不含 RTP 头、加密开销和重复的补发），按 250 ms 分桶、取最近 2 秒的平均，括号里换成 MB/s，另写 10 秒内的峰值。
  - 连不上或结束时画面中间是一张卡片：原因、要做什么，能重来时带「重试」或「重新连接」。
- 横屏：横竖屏按钮锁住方向，选择记住、下次进来照做。离开页面时手机不是横着拿就转回竖屏。横屏时画面铺满安全区的宽度，左右让开刘海。
- 键盘和快捷键栏：快捷键栏默认不显示，点悬浮球的键盘或快捷键才出现，系统键盘弹出时贴在键盘上方；横屏时半透明、更矮。它们盖在画面上，画面不缩；最后单击的那一处会被盖住时，画面整体上移到它露出来，收起后回原位。修饰键点一下只管下一个键、长按锁住。系统键盘打的字只发新打的，删掉的每个字发一次退格。快捷键栏在方向键后面多「◀ 空间」「空间 ▶」「调度中心」（⌃←、⌃→、⌃↑）。Mac 端注入方向键、Home、End、翻页、向前删除时照真键盘带上小键盘和 Fn 标志，调度中心这类系统快捷键才认。
- 手势：单指轻点单击（400ms 内附近再点递增击数）、双指轻点右键、长按 300ms 后拖动（触控板模式见下条）、单指拖平移视口、双指拖滚动（滚动落在手指下面的窗口，带惯性，内容贴着手指走）、捏合缩放到 4 倍，双指手势按头 10 像素的移动定性，三指以上不认（触控板模式的三指拖动除外）。长按进入拖动、双指右键各有一次轻触感。第一次进页面有手势提示（按当前模式列出每种操作的手势，点任意处关掉）；悬浮球里的「手势」（问号）随时再打开，内容按当前模式。看桌面时屏幕顶边和底边的系统手势延后，离开页面恢复。
- 触控板模式（默认；设置「看桌面」里可以换成「直接点按」，换了以后下次进页面再提示一次手势）：单指滑动按相对位移移 Mac 指针（手指慢时 1:1，快了加速到 2.5 倍，放大时按看得见的画面换算），点按、双指右键、滚动都落在指针上；拖动是三指滑动，或轻点后 400ms 内再按住滑动，不用长按（手指放上去停一下再滑是移指针）；第二下按住超过 200ms 没滑就抬起算没拖成，不发双击（标题栏上双击会缩放窗口）。开始拖动有一次轻触感，拖动中几根手指都按中点走、不加速；全部松手后左键再按住 1 秒，期间放回手指（几根都行）滑动接着拖（屏幕小也能拖远），轻点一下或等过去才松开。指针从画面中间开始（Mac 不报指针位置），换了在看的屏或窗口（手动切、窗口没了退回整块屏、锁屏改看主屏）回到中间；画面上在手机算出的指针位置画一个圈，跟手，左键按着时是实心，松手等续拖时慢慢变淡、淡完松开，画面里的指针晚一个来回。放大后指针离边缘不到 36 像素视口跟着挪，点按、右键、拖动、滚动之前指针在视口外（捏合缩放后）也先挪到看得见，不再单指平移；捏合照旧。手指下面不画点。
- 输入经 UDP 发给电脑，必达事件没确认会重带。退到后台先把按着的键松开再退订，回到前台重新订阅。

## 更新

- iOS 的 Ad Hoc 包和安卓的发布包查更新：`scripts/ios-adhoc.sh`、`scripts/android-release.sh` 打包时用 `--dart-define` 写进版本号和构建号（`POSSE_VERSION`、`POSSE_BUILD`），构建号是 0（调试包、自己编的包）不查。两端共用版本号和 `mobile/CHANGELOG.md`，构建号都是提交数加 8（见 `docs/release.md`，安卓写成 versionCode）。
- App 启动时读 `https://posse.shaoyan.uk/ios/latest.json`（安卓读 `android/latest.json`；版本、构建号、大小、`mobile/CHANGELOG.md` 里这个版本的条目、安装链接：iOS 是 itms-services 链接，安卓是 APK 的地址），回到前台时距上次超过 6 小时再读；网络不通不提示，下次再查。线上构建号比自己的大就算有新版本。
- 首页列表最上面一条提示「新版本 x（构建号）· 大小」：点开是更新内容和「更新」按钮，× 之后这个构建不再提示（记在手机设置里），更新的构建照常提示。设置「关于」写当前版本和构建号，有新版本时多一行「更新到 …」，提示关了也能在这里更新；没有时是「检查更新」，点了不管 6 小时的间隔立即查，查着时行尾转圈，查完写「已是最新」或「检查失败，稍后再试」，查到新版本这一行换成「更新到 …」（构建号是 0 的包没有这一行）。
- 「更新」打开 itms-services 链接，系统弹安装确认，确认后 App 关闭、覆盖安装，配对不丢。系统要过好几秒才弹框，期间按钮转圈、点不动；在系统弹框里取消的话 App 收不到消息，15 秒后按钮恢复。安装页的按钮同样处理，页面上写着版本、大小和更新内容。
- 安卓的「更新」在 App 里下载 APK（按钮显示进度，先写 `.part`、大小对上再改名，断流 30 秒算失败），下完经 FileProvider 交给系统安装器，确认后覆盖安装，配对不丢；在安装器里取消回到弹窗，按钮恢复。Posse 还没有「安装未知应用」权限时先跳到系统设置的这个开关页，允许后回到 App 自动弹安装器，没允许就在弹窗里提示。下载的包放在缓存目录 `update/`，文件名带构建号，App 启动时删掉不比自己新的。第一次安装从 `https://posse.shaoyan.uk/android/index.html` 下载。
- 安卓发布包用自己的证书签（`~/Library/Application Support/Posse/android/`，不进仓库，`scripts/android-release.sh` 第一次运行时生成），找不到时 gradle 退回调试证书，发布脚本拒绝上传这样的包。调试证书签的包和发布包不能互相覆盖安装，换着装要先卸载、重新配对。

## 外观

- 加载动画：整页加载是七格蜂巢，外圈六格顺时针逐格亮、后面拖一段渐暗；按钮里、行尾的小转圈是六边形描边。历史页还没有内容时整页是蜂巢，已有结果再读时转圈在搜索框里。系统开了减弱动态效果时停在一帧上。上下文用量的圆环、视频下载和上传的进度条用 Material 的。设计稿 `design/loading/concepts.png`。
- 进会话页、历史页、工作区页、图片与视频、打开文件和 diff 时，第一份数据等推入动画结束再上屏；扫码页的相机画面也等弹出动画结束才上屏。
- 首页、历史页、改动页都不能下拉刷新：工作区列表每 3 秒自己刷新一次，改动页看得见时每 3 秒读一次（切到文件页、上面盖着 diff 页时不读，切回来马上读），历史页改搜索词、筛选时重读。
- 首页项目行首的图标照桌面侧栏（`ui.md` 的自定义图标）：手机上不能改。常驻进程每次 `worktree.ps`、`repo.list` 时读 `$POSSE_HOME/project-icons/icons.json`，设了图标的项目带上 `repoIcon`（`{"text"}` 或 `{"image": 文件名}`，没设不给，`repo.list` 里叫 `icon`），桌面改了下一次轮询就变，不用重启常驻进程；图片经 `posse.projectIcon`（`{"name"}`，回 base64 的 PNG，只认图标目录里的 PNG 文件名）取，文件名每次导入都不同，手机按名字缓存在内存里，没取到时先画文件夹。
- 首页的项目和工作区照桌面侧栏命名：只有项目目录的项目行是项目名；有多个工作区时项目目录写「主工作区」，posse 建的 worktree 和同目录的工作区写工作区名，加进来的 worktree 写当前分支（游离时写工作区名），名字由常驻进程给（`displayName`），图标用桌面侧栏的描边图标（`lib/ui/line_icons.dart`）：项目默认文件夹，主工作区房子，worktree（含加进来的，`isWorktree`）分支，同目录的工作区文件夹。逐级等距缩进：工作区和只有一个工作区时的会话对齐到项目名下面，工作区下的会话对齐到工作区名下面；会话的 agent 方块和工作区图标一样大。工作区行的分支和名字一样时不再写一遍。项目行和（有多个工作区时的）工作区行都是点这一行展开收起下面的内容、点右边的圆按钮进工作区页，下面没有会话时点这一行也进；收起的行上显示里面最需要注意的会话状态；收起的项目和工作区按电脑分别记在手机上（`collapsed`、`collapsedWorkspaces`）。用量条下面是「项目 | 运行中」的切换（存在手机设置里，`homeByStatus`）：「运行中」和桌面侧栏的同名看法一样（见 `ui.md` 侧栏一条），所有项目的 agent 会话（含空闲）平铺在一张卡片里，状态前面写「项目 · 工作区」；切进来时按状态排一次，之后新会话插到同状态那一段末尾、已有的不挪；断线时（含重连后还没拉到新会话列表时）先照项目的先后排，拉到新列表后再按状态排一次。顺序只在内存里，换电脑、重开 App 时重排。设置「首页」里「项目显示分支和路径」「工作区显示分支」和桌面设置的同名开关一样，关了只留名字，存在手机设置里（`projectMetaHidden`、`workspaceMetaHidden`）。
- 新建会话面板只列电脑上能用的 agent（装了、又没在设置里关掉的，`preflight.detectAgents`，顺序照电脑给的），最后是普通终端；列表每条新连接拉一次、打开面板时再拉一次，电脑上刚改的开关打开面板就生效。默认选第一个 agent，用户没点过时跟着列表变，选中的被关掉了也换成第一个。
- App 图标和桌面同一张原图（`design/icon-art.png`，描边六边形加 `>_`）。
- 终端区域的颜色（前景、底色、16 色）照电脑窗口里这个终端在用的那套，不跟手机的深浅色：程序按电脑的颜色配色（Codex 只在启动时查一次底色），手机换成另一套时浅底上的深色块、diff 的底色都会变味。外围（顶栏、快捷键栏）照旧跟手机主题，终端外露出的空白接着终端底色。横屏时终端让开刘海和圆角那两侧（两边露出终端底色），其他页面的正文也一样让开，页面底色、顶栏和底栏照样铺满。窗口每秒轮询 `daemon.status` 时带着它终端在用的配色，常驻进程变了就换到所有终端上（内核照它应答程序的颜色查询，窗口关掉后也是，交接时带过去），窗口开着时新终端也按它起。手机声明了 `posse.termcolors.v1` 才收配色（旧版客户端不收）：订阅时 `subscribed` 带 `colors`，变了推 `{"type":"colors"}`。连着不给配色的旧版常驻进程时，终端底色跟手机，字色和底色不到 3 倍对比度的往黑或白里调到刚够，保留色相。
- 闪屏（设计稿 `design/splash/concepts-3.png` 的 H）：系统闪屏是 `#1A1A19` 底、居中的标志和底部的「A posse of agents.」，接着 Flutter 在同样位置画同样的标志和 slogan、铺满蜂巢格，零星几格按 agent 状态色（琥珀、陶土、绿）陆续亮起，动画只放 0.6 秒；本地设置和电脑列表读完且显示满 0.7 秒后用 0.2 秒淡出到首页。标志和 slogan 是图，导出方法见 `mobile/README.md`。闪屏不跟主题，浅色主题也是暗底：系统闪屏在 App 读到主题设置之前就显示了。

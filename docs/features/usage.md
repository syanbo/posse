# 套餐用量和防休眠

各 agent 套餐用量的读取和显示，以及防休眠。

- 套餐用量（`internal/usage`，常驻进程 `internal/daemon/usage.go`，界面 `internal/app/planusage.go`）：只在 agent 运行时顺带更新，不轮询。
  - Claude：用量只在 statusLine 的输入里（`rate_limits` 的 five_hour、seven_day）。`claude-hooks.json` 总是注入 `posse statusline`，经 `usage.report` 转给常驻进程，自己不输出；`--settings` 的 statusLine 会盖掉项目和用户配的，所以沿用用户 statusLine 的其余字段（`refreshInterval` 等），由 `posse statusline` 按 Claude 的顺序（项目优先，再用户）替它跑原来的命令、输出原样交回。用户设置文件读不出来时不注入。Stop 时读 Claude 自己缓存的 `/usage` 结果（`~/.claude.json` 的 `cachedUsageUtilization`，用户看 `/usage` 才更新）：按模型的周额度（Fable）、本周用量用在哪、额外用量。
  - Codex：Stop、PostToolUse 时读会话文件末尾 `token_count` 的 `rate_limits`；重置卡本地没有，Stop 后拉起 `codex app-server` 调 `account/rateLimits/read`（Codex 用自己的登录，至少隔 5 分钟）。Grok：标题变化时增量读 `~/.grok/logs/unified.jsonl` 的 `billing: fetched credits config`（它的运行日志，不是对外接口）。Cursor：本地没有，常驻进程启动时和 stop 后用钥匙串里 cursor-agent 的 token（经 `/usr/bin/security` 只读、不续：cursor-agent 用它写这一项，访问控制只放行它，经 Security 框架读会弹授权窗）调 `DashboardService/GetCurrentPeriodUsage`、`GetPlanInfo`，至少隔 5 分钟；没登录就跳过，读钥匙串超时（弹了授权窗）后这次常驻进程运行期间不再试。Codex、Cursor 两项查询在设置页的「套餐用量」卡片里可关（`usage.json` 的 `codexOff`、`cursorOff`）。
  - 一家的读数里总额度窗口取最新的一份，分池窗口（`Window.Name`：Fable、Auto、API）、按需用量、用量分布、重置卡各带读数时间、各取最新，statusLine 的读数不会冲掉缓存里的 Fable；较新的读数不带套餐名时也沿用旧的。套餐名：Claude 取 `~/.claude.json` 的 `oauthAccount`（`organizationType` 加限额档位里的倍数，写成"Max 5x"，`claudePlan`），随读缓存一起更新；Codex 的 `plan_type`（plus、pro）写成首字母大写，手机显示时也首字母大写（`planName`）。过了重置时间的窗口按 0 显示。常驻进程启动时从本地记录取一次（Claude 缓存、最近的 Codex 会话、Grok 日志末尾），Cursor 向它查一次。
  - Cursor 照它的控制台（Magpie 同样）只显示两池：Auto 是"Cursor 模型"（含 Composer、Cursor Grok），API 是"其他模型"，状态栏和手机卡片取用得多的一池；`totalPercentUsed`（按 Auto 池折算，远低于两池）照样存，界面不显示（`planWindows`、手机的 `shownWindows`）。两池下面一行是套餐内用量的金额（`totalSpend / limit`，按 API 价折算，Ultra 月费 $200、含 $400，就是 Cursor 提示里的"已用 N% 的套餐内用量"），套餐名后面带 `GetPlanInfo` 的月费。
  - 刷新：详情右上角的按钮调 `usage.refresh`，常驻进程不管间隔把各家都取一次（Claude 重读缓存、Codex 读最近的会话文件再问 app-server、Grok 读日志、Cursor 查接口，设置页关掉的不查），都做完才回，期间按钮是转圈。
  - 桌面：主区域底部的状态栏（和侧栏底栏同高同色，`footHeight`、`footShade`），每家一段，图标加一个窗口（有 5 小时就是它）的百分比；点开是各家详情，标题旁切换已用和剩余（ui.json 的 `usageRemaining`）。手机：`posse.usage.v1` 的 `usage.get`，首页工作区列表上面的卡片（`mobile/lib/usage`；详情顶栏的刷新调 `usage.refresh`，和桌面的刷新一样各家马上取一次，在单独的 goroutine 里做，不挡同一连接后面的请求；电脑端太旧时提示更新；详情的滚动区铺到屏幕底边，内容底下垫出安全区），点开详情，切换存在手机上。每台电脑最近一次的读数存在手机上（`usage.cache.<电脑>`），打开 App、正在连接时先显示它，连上取到新的原地换数，卡片不会在项目列表出来之后再插进去把列表顶下去；断线、超时保留上次的读数，只有电脑端没有这个接口时收起卡片并删掉缓存。
- 防休眠照 Orca 的 agent-awake（Magpie 同样）：常驻进程按档位起 `/usr/bin/caffeinate -i -s -w <常驻进程 pid>` 托住系统不睡，屏幕照常熄灭，合盖仍会睡（`internal/daemon/awake.go`）。档位存在 `$POSSE_HOME/awake.json`，默认 auto：只要常驻进程在跑就托住，不看 agent 在不在工作；display 同样只要常驻进程在跑，另加 `-d` 屏幕也不熄（照 Magpie 的 Screen on too：屏幕熄了会跟着锁屏）；off 不管；档位给 on 时按 auto 处理。窗口关掉也有效，常驻进程退出（`posse daemon stop`）才放开。每 30 秒重算一次，caffeinate 意外退出也在这时补上；`-w` 让常驻进程被强杀时它跟着退出。状态随 `daemon.status` 的 `awake` 给界面，`awake.set` 改档位。主区域状态栏（终端下面那条）最右边是防休眠按钮：咖啡杯加当前档位文字（左边挨着终端和内存按钮，`internal/app/awake.go`），托住时图标是强调色，点开选档位；常驻进程没给 `awake` 时按钮变灰、写"不可用"。

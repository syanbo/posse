# 套餐用量和防休眠

- 套餐用量（`internal/usage`，常驻进程 `internal/daemon/usage.go`，界面 `internal/app/planusage.go`）：agent 运行时顺带更新，Codex 在启动和用量详情打开时也查询，不在后台持续轮询。
  - Claude：用量只在 statusLine 的输入里（`rate_limits` 的 five_hour、seven_day）。`claude-hooks.json` 总是注入 `posse statusline`，经 `usage.report` 转给常驻进程，自己不输出；`--settings` 的 statusLine 会盖掉项目和用户配的，所以沿用用户 statusLine 的其余字段（`refreshInterval` 等），由 `posse statusline` 按 Claude 的顺序（项目优先，再用户）替它跑原来的命令、输出原样交回。用户设置文件读不出来时不注入。Stop 时和 statusLine 上报时（至少隔 5 秒，文件没改不读）读 Claude 自己缓存的 `/usage` 结果（`~/.claude.json` 的 `cachedUsageUtilization`，用户看 `/usage` 才更新；看 `/usage` 不触发 Stop，靠之后的 statusLine 上报带出来）：按模型的周额度（Fable）、本周用量用在哪、额外用量。
  - Codex：Stop、PostToolUse 时读会话文件末尾 `token_count` 的 `rate_limits`；常驻进程启动、Stop 后和用量详情打开时使用 Codex 登录直接查询 ChatGPT 的 `/backend-api/wham/usage`（至少隔 1 分钟），重置卡有剩余时另查明细取得最早过期时间；不再拉起 `codex app-server`。使用 `$CODEX_HOME/auth.json`（默认 `~/.codex/auth.json`）中的 ChatGPT 登录；收到 401 先重读，再向官方登录服务续期，保存时锁定并比较原文件，避免覆盖 Codex 刚更新的凭据。目前只支持默认或 `file` 登录存储，`keyring`、`auto`、`ephemeral`、API key 登录会明确提示不能查询；自定义 OAuth 来源不自动续期。打开详情时先显示上次读数，后台查询完成后换成新值。Grok：标题变化时增量读 `~/.grok/logs/unified.jsonl` 的 `billing: fetched credits config`（它的运行日志，不是对外接口）。Cursor：本地没有，常驻进程启动时和 stop 后用钥匙串里 cursor-agent 的 token（经 `/usr/bin/security` 只读、不续：cursor-agent 用它写这一项，访问控制只放行它，经 Security 框架读会弹授权窗）调 `DashboardService/GetCurrentPeriodUsage`、`GetPlanInfo`，至少隔 5 分钟；没登录就跳过，读钥匙串超时（弹了授权窗）后这次常驻进程运行期间不再试。Codex、Cursor 两项查询在设置页的「套餐用量」卡片里可关（`usage.json` 的 `codexOff`、`cursorOff`）。
  - 总开关：设置页「套餐用量」卡片的「显示套餐用量」（`usage.json` 的 `off`，`usage.set` 改）。关掉后常驻进程什么都不读、不查：启动时不读本地记录，hook 和 grok 标题变化不触发读取，`usage.report` 收到的 statusLine 输入直接丢掉（`posse statusline` 仍照常替用户跑原来的 statusLine），`usage.refresh` 不取直接回；`daemon.status`、手机的 `usage.get` 给空列表加 `off: true`，桌面状态栏不显示用量按钮，手机不显示卡片。已存的读数留在 `usage.json` 里，重新打开时先显示它们，再像启动时一样读取本地记录并补查 Codex、Cursor。
  - 跟着 agent 开关：设置页「Agent」卡片里关掉的 agent（`agents.json` 的 `disabled`）同样不读、不查，读数不随 `daemon.status`、`usage.get` 给出，桌面状态栏和手机都不显示；它的查询开关（Cursor 用量、Codex 套餐用量）在设置页里也不列。常驻进程每次给读数时看一眼 `agents.json`，发现有 agent 重新打开就像启动时一样读取本地记录并补查 Codex、Cursor。
  - 一家的读数里总额度窗口取最新的一份，分池窗口（`Window.Name`：Fable、Auto、API）、按需用量、用量分布、重置卡各带读数时间、各取最新，statusLine 的读数不会冲掉缓存里的 Fable；对某一类完整的读数（Cursor 接口的分池和按需用量；Claude 缓存里 `limits`、`spend`、`seven_day_breakdown` 键在的那几类）里没有这一项时，比它旧的旧项去掉（取消了分池、关了按量付费），不完整的来源（statusLine、Codex 会话文件）没有时照旧沿用；较新的读数不带套餐名时也沿用旧的。套餐名：Claude 取 `~/.claude.json` 的 `oauthAccount`（`organizationType` 加限额档位里的倍数，写成"Max 5x"，`claudePlan`），随读缓存一起更新；Codex 的 `plan_type`（plus、pro）写成首字母大写。Codex 过了重置时间的窗口标为未知（`Window.Unknown`，只改变返回值、不写回读数），桌面和手机显示“待更新”、进度条留空，不把新窗口推成剩余 100%；其余 agent 沿用到期按 0 显示。常驻进程启动时从本地记录取一次（Claude 缓存、最近的 Codex 会话、Grok 日志末尾），Codex、Cursor 向各自服务查一次。
  - Cursor 照它的控制台（Magpie 同样）只显示两池：Auto 是"Cursor 模型"（含 Composer、Cursor Grok），API 是"其他模型"，状态栏和手机卡片取用得多的一池；`totalPercentUsed`（按 Auto 池折算，远低于两池）照样存，界面不显示（`planWindows`、手机的 `shownWindows`）。两池下面一行是套餐内用量的金额（`totalSpend / limit`，按 API 价折算，Ultra 月费 $200、含 $400，就是 Cursor 提示里的"已用 N% 的套餐内用量"），套餐名后面带 `GetPlanInfo` 的月费。
  - 刷新：详情右上角的按钮调 `usage.refresh`，常驻进程不管间隔把各家都取一次（Claude 重读缓存、Codex 读最近的会话文件再直接查 ChatGPT、Grok 读日志、Cursor 查接口，设置页关掉的不查），都做完才回，期间按钮是转圈。Codex 同时到达的查询共用一个请求，手动刷新也等它完成；一个调用方取消等待不打断其他等待者，联网本身有超时。`usage.refresh` 可传 `{agent:"codex", force:false}`，只补查 Codex 并保留一分钟间隔；无参数仍是强制刷新所有家。Codex 的查询中、失败状态经 `codexReading`、`codexError` 给桌面和手机；主额度查询失败不改上次成功读数与时间，界面提示更新失败；仅重置卡明细失败或超时时仍更新已取到的主额度，卡片沿用原读数与时间，并明确提示是重置卡读取失败。接口回复缺少主窗口时拒绝整份读数，不清空已有额度；回复有主窗口但缺少重置卡字段时保留原卡，明确返回数量为零时才更新成零。Codex 成功读数超过 5 分钟标为旧值，设置里关闭在线查询时，桌面和手机都写明显示的是上次读数，手机不再自动补查；手机对需要重新登录、登录存储不支持和重置卡明细失败分别给出本地化提示。桌面用量浮层打开期间每分钟补查一次；手机打开详情时补查一次。
  - 桌面：主区域底部的状态栏右边、内存按钮左边（分支和 Git 日志放在标签栏时在状态栏左端）（和侧栏底栏同高同色，`footHeight`、`footShade`），每家一段，图标加一个窗口（有 5 小时就是它）的百分比；点开是各家详情，标题旁切换已用和剩余（ui.json 的 `usageRemaining`）。手机：`posse.usage.v1` 的 `usage.get`，首页工作区列表上面的卡片（`mobile/lib/usage`；详情顶栏的刷新和桌面一样调 `usage.refresh`；电脑端太旧时提示更新），点开详情，切换存在手机上。每台电脑最近一次的读数存在手机上（`usage.cache.<电脑>`），打开 App、正在连接时先显示它，连上取到新的原地换数，卡片不会在项目列表出来之后再插进去把列表顶下去；断线、超时保留上次的读数，只有电脑端没有这个接口时收起卡片并删掉缓存。
- 防休眠照 Orca 的 agent-awake（Magpie 同样）：常驻进程按档位起 `/usr/bin/caffeinate -i -s -w <常驻进程 pid>` 托住系统不睡，屏幕照常熄灭，合盖仍会睡（`internal/daemon/awake.go`）。档位存在 `$POSSE_HOME/awake.json`，默认 auto：只要常驻进程在跑就托住，不看 agent 在不在工作；display 同样只要常驻进程在跑，另加 `-d` 屏幕也不熄（照 Magpie 的 Screen on too：屏幕熄了会跟着锁屏）；off 不管；旧的 on 档按 auto 处理。窗口关掉也有效，常驻进程退出（`posse daemon stop`）才放开。每 30 秒重算一次，caffeinate 意外退出也在这时补上；`-w` 让常驻进程被强杀时它跟着退出。状态随 `daemon.status` 的 `awake` 给界面，`awake.set` 改档位。主区域状态栏最右边是防休眠按钮：咖啡杯加当前档位文字（左边挨着终端和内存按钮，`internal/app/awake.go`），托住时图标是强调色，点开选档位；常驻进程没给 `awake` 时按钮变灰、写"不可用"。

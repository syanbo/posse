# SSH 远程工作区

最左侧全局导航栏（本机 `>_` 下方）与快捷键 `⌃⌥H` 已接入本机和配置里的 Mac：可添加、编辑、连接、查看、自动或显式接管、释放和断开。连接使用 SSH 认证、远端 Posse 发现、自动推送无头服务端、Unix socket 转发和实际 daemon 能力检查；桌面文件与 Git 读写、文件夹批量上传下载、远端终端复制/拖入文件上传及阶段 5 设备归属均已接入目标服务，自动 Fetch 仅在持有控制且当前工作区显示时执行，任何未迁移的本机 Git 闭包仍由 `git.write` 门禁拦截。

## 配置与诊断

目标 Mac 只需开启系统「远程登录」（SSH），**不再要求目标机预先安装或打开 `Posse.app`**。主 Mac 在主机菜单点击远端主机、或通过 CLI 执行 `posse remote install <host>` / `posse remote check <host> --install` 时，若目标 Mac 尚未安装 Posse，会复用同一条已认证的 SSH 连接自动推送轻量无头服务端（`posse` + `libghostty-vt.dylib`）到目标机 `$POSSE_HOME/server/versions/<版本>-<摘要>/`、原子切换 `current` 符号链接并拉起常驻进程；已安装 `Posse.app` 的目标机继续直接复用。

```sh
posse remote add office office-mac
posse remote add studio user@studio.local --port 22 --home '~/.posse' --executable '/Applications/Posse.app/Contents/MacOS/Posse'
posse remote list
posse remote install office [--file build/server/posse-server-0.1.54-darwin-arm64.tar.gz] [--launchd]
posse remote check office [--start] [--install]
```

目标可以是 `~/.ssh/config` 的 Host 别名，沿用系统 OpenSSH 的 IdentityFile、ssh-agent、Keychain、known_hosts 和 ProxyJump。Posse 默认不转发 ssh-agent，不执行配置中的额外 LocalForward/RemoteForward 或 LocalCommand。未知主机显示 SSH 的指纹确认，主机密钥变化直接失败；密码和私钥口令仅经过本次连接的私有认证通道，不写入配置或日志。

`remote check` 默认只探测、不启动也不安装远端 daemon；加 `--start` 在未运行时拉起；加 `--install` 在目标机未安装 Posse 时自动推送无头服务端并拉起（也可通过 `--file` 指定本机压缩包，或通过 `scripts/build-server.sh` 离线构建）。`remote install` 显式推送安装或热升级远端无头服务端：目标 daemon 已在运行时自动执行 `daemon.handoff` 无损交接（终端不断线）；附加 `--launchd` 时会在目标 Mac 写入 Aqua 会话 `LaunchAgent`（也可在目标 Mac 本机用 `posse server install/status/uninstall --launchd` 管理；卸载自启不停止运行中的 daemon）。未运行 daemon 时 `--launchd` 优先由 Aqua 会话拉起以访问登录钥匙串；若目标 Mac 尚未进行图形登录（`fdesetup authrestart` 仅跳过 FileVault 解锁，不自动建立 Aqua 会话），plist 会保留待下次图形登录加载，本次仍回退经 SSH 启动。`--batch` 禁止认证提示，适合已有密钥认证和信任记录的检查。Ctrl-C 取消建连。

诊断结果来自隧道内的 `daemon.info`，包含实际运行的版本、构建、构建形态（`edition`: `full` / `headless`）、特性集（`features`）、home、实例 ID 和已实现的能力；CLI 版本不会代替 daemon 能力。当前 daemon 宣布 `rpc.v1`、`terminal.stream.v1`、`desktop.control.v1`、`files.v1` 和 `git.v1`；桌面窗口建连时要求完整能力集，`remote check` 仍只要求 `rpc.v1` 以输出远端实际能力诊断。托管的 `headless` 节点若缺少必需能力，或重连时检测到更新版本（或本地新构建 commit），带自动安装的建连会自动推送新版并热交接（绝不降级，离线或升级失败时若原 daemon 健康仍保留连接）；完整 `Posse.app` 节点不自动换包。

检查结束关闭本次 SSH master，不停止远端 daemon 或终端。每次连接使用 Posse 自己的私有目录、control socket 和转发 socket，不复用或关闭用户其他工具的 master。一个连接内的发现命令、普通 RPC 和二进制流复用同一 SSH master。

窗口主机菜单使用连接管理器：切主机或离开时取消正在进行的认证和建连，迟到的成功连接会被关闭；已连接的 master 最多保留三台空闲主机，每台五分钟后回收。复用要求保存的主机配置一致，并重新查询实际 daemon 的 home 和所需能力；复用失败不会自行发起新的认证。主动断开、master 退出和最终关闭会回收自有进程与私有目录，不停止目标 daemon。缓存仅保留传输，不恢复桌面控制权。

窗口认证弹窗使用独立队列，由连接协调器调用：密码及私钥口令用遮蔽输入，保留原始空格和空值；主机密钥确认默认聚焦取消，明确点击「信任并连接」才接受。安全密钥触摸通知不要求填写答案，SSH 结束该通知时自动移除对应提示，不关闭后来排队的提示。用户取消会取消整次建连，切换显示的主机及窗口最终退出也会结束等待；被未保存文档拦住的退出不提前关闭认证。弹窗标明所连接的主机，回答不进入 UI 状态文件。

窗口连接协调器已把传输、认证和 `desktop.status` 握手串在一起：主动连上无人控制且未主动释放的远端时自动接管，已有他人控制或目标正忙时降级为查看；切换立即取消旧尝试并保留视图数据，迟到的握手不能恢复旧主机。轮询先保活桌面身份，失败或 SSH 退出会独立更新断线状态，断线后不重放写操作。主动断开先等待有限时的控制权释放，再回收对应传输；期间同一主机已重连时，旧清理不关闭新连接。窗口真正退出时取消轮询、认证和在途建连，收拢释放请求后关闭连接池；本机 daemon 启动等待也可取消，已经启动的 daemon 独立运行。本机 `Run` 建立唯一的主机会话并接入轮询；远端连接失败或 SSH 退出后保留已断开的主机视图并显示错误，不在后台重连，须在主机菜单再次连接。

主机配置存于本机 `$POSSE_HOME/hosts.json`，权限 0600；每项有稳定 ID。用 `remote add ... --id <ID>` 更新现有项；`remote rm <名称或ID>` 仅忘记配置，不删除远端数据。重名时用 ID。配置可指定用户名、端口、远端 home 和可执行文件，路径必须绝对或以 `~/` 开头。

未指定程序路径时依次寻找目标 home 的 `server/current/posse`、`bin/posse`、系统和用户 Applications 下的 Posse.app、Homebrew 常用位置与 `~/.local/bin/posse`；全部未找到时返回 `POSSE_REMOTE_MISSING:<os>:<arch>` 以便自动推送安装。目标 home 默认 `~/.posse`。发现输出使用独立标记行，允许 shell 启动时有其他输出。远端 socket 当前要求绝对路径、不超过 100 字节，且不含冒号、方括号、百分号、反斜杠或美元符号，避免 OpenSSH 转发语法改变路径。目标 home 在远端解析符号链接后参与身份核对。

## 窗口主机入口与管理

最左侧全局导航栏中，本机工作区（`>_`）正下方平级列出配置里的每台远端 SSH 主机（1–2 字首字母磁贴，可拖动排序存本机 `ui.json` 的 `hostOrder`；右键提供连接/重连/取消连接、接管/释放、断开、编辑和移除）。顶栏不再显示主机菜单；快捷键 `⌃⌥H`（或随处搜索「切换主机」）在当前主机磁贴旁弹出切换菜单，未配置任何远端主机时直接打开「添加 SSH 主机」弹窗。底部状态栏内存按钮左侧提供轻量状态芯片，仅在无主机（「添加 SSH」）、连接/自动部署进度、查看中或已断开时显示。左下 `+` 新建菜单也常驻「添加 SSH 主机…」。弹窗直接通过 `remote.Put` / `remote.Remove` 与 CLI 共享 `$POSSE_HOME/hosts.json`（文件锁互斥），窗口每秒 `stat` 其修改时间同步变化。

主动连接无人控制的远端主机时自动接管；已有其他控制者时先进入查看，显式点击「接管」会显示对方名字并确认，切主机或控制代次改变后旧确认失效。「释放控制」立即变为查看并向目标释放租约，同时将该实例记为阻塞自动接管（再次连接同一实例仍保持查看，直到显式接管）；「断开连接」仅用于远端，先释放租约再关闭传输，停留在已断开的主机视图（首次连接无数据时主区域展示加载/失败卡片）。处于远端主机时，工作区、聊天、任务、历史四个模块侧栏标题下方显示主机归属行。

本机第一次成功读取新 daemon 实例的状态且无人持有时自动接管。主动释放后同一实例保持查看，直到显式接管或出现新的空闲实例；切到远端再回来也不取消这条限制。切回本机可以再次自动接管空闲实例，但心跳失败和接管回复丢失后不借切回恢复控制。切回前尚未完成的旧释放只针对捕获的旧租约，不能撤销后来取得的控制。

切主机沿用各自视图上下文：离开时释放控制并作废旧确认和预览，各主机的未保存文档与草稿保留。讨论、协作和讨论附件仍归本机，浏览远端时也只使用不带 Desktop 的本机 base client。已接受的保存、废纸篓、Fetch、Push、更新与分支操作不因切换撤销，回复丢失只查询原操作，不重发。

## 桌面控制基础（本机窗口已接入）

本机窗口使用自己的 base client 建连，持有控制时由轮询心跳续租，窗口真正退出时释放捕获的那一代租约。保存、移到废纸篓、手动及自动 Fetch、Push、更新与分支操作使用带桌面身份的目标入口，保留版本冲突检查；回复丢失只查询原操作，不重发，取消不等于回滚。尚未取得控制时不会回退到直接写盘或本机 Fetch。讨论、协作及讨论附件始终使用本机 base client，不携带桌面身份，查看远端工作区时也一样。

`desktop.status/take/heartbeat/release` 提供当前 daemon 内的控制会话。接管携带实例 ID 和预期代次，成功后换代；心跳租期为 15 秒，释放或过期使旧身份失效。本机初次自动申请仅在无人控制时成功，显式接管才替换已有控制者。

带桌面身份的 `terminal.attach` 根据控制状态选择读写或查看。查看只接已有 live 终端，不启动待恢复记录、不改 PTY 尺寸、不交出内核的查询应答权；输入帧和尺寸帧在服务端丢弃。PTY 尺寸变化时查看流断开，重新接入取得对应网格的快照；手机原有 Watch 不受影响。桌面输入写入期限为 250 毫秒，写满或取消后断开当前输入连接，不重放未确认的按键，也不更改手机/CLI 写入的期限。接管、释放和租期过期会关闭旧控制订阅，使旧按键、尺寸和查询回复不能继续写入。无身份的旧版窗口在有人控制时拒绝接入；CLI 和手机的独立操作入口保持现有语义。

终端插件在首份快照前读取连接的实际网格与查看状态，快照到齐前丢弃输入，整帧回放期间禁止窗口改网格。查看端按远端网格显示，小窗口缩小字号以显示完整屏幕，窗口尺寸变化不重排快照；保留选择、复制与本地滚动，程序开启鼠标跟踪时也能直接选字。键鼠输入、自动查询应答、焦点报告、粘贴和程序剪贴板请求均受插件门禁约束，粘贴不会触发应用的图片回调。普通终端视图从固定请求的 Client 接入，控制身份变化后不按相同终端 ID 复用旧视图；重建当前终端时保留查找词，迟到的退出回调不能清掉新订阅。技能命令从确认时起固定创建与接入身份，切主机或失去身份只释放其显示连接并撤掉隐藏标记，已经接受的命令回到普通终端列表继续运行。窗口的连接生命周期与顶栏接管入口已接入，未迁移的写操作继续受自绘菜单和执行入口的门禁约束。

已接受的终端恢复不会因控制转移而取消，但恢复完成前 handoff 返回 `busy`；接过来的 daemon 取得 home 锁前也不接受新的恢复。窗口自动升级遇到 `busy` 延迟五秒再尝试，其他失败仍不自动重复；手动更新遇到忙碌时保留提示，由用户稍后重试。远程 Client 不会在隧道中断时本地创建 home 或启动 daemon，也不会用本机程序路径升级远端。

普通桌面请求经 `desktop.call` 携带固定实例、客户端与控制代次。项目/工作区创建、修改和删除，以及终端、任务和历史恢复等已登记的写入口，在服务端同一把控制锁内接受；迟到的旧身份拒绝。接受后由 daemon 持有，断开请求连接和换控制端不会撤销它；完成前阻止 handoff，正常停止先取消并等待这些操作，再关闭终端和存储。CLI 与 hooks 的独立入口不借用桌面身份。

写请求带窗口进程内递增的序号；同一身份、序号和参数取得已有结果，参数不同则拒绝。参数比较忽略 JSON 排版空白，保留字段顺序，避免结构体解码的大小写别名覆盖被误判为同一次操作。`desktop.operation` 查询指定请求，`desktop.operations` 列出当前实例内的操作摘要；换控制端仍能看到旧端已接受的工作。结果最多保留 128 条、总计 4 MiB、每条 256 KiB、十分钟，运行中记录不回收，接受前为结果预留空间。当前控制代次的序号窗口阻止已回收请求再次执行；过旧序号、缓存消失或实例变化均按结果未知处理。客户端断线只返回包含原身份和序号的 `outcome_unknown`，不自动重发。

查看读取使用明确清单：终端 show/read/wait 只查 live 终端，不隐式恢复；工作区快照不执行 Git；用量快照不触发后台认证或网络查询；配色只接受当前控制者上报。历史列表、搜索和详情已经核对并开放：可维护目标端的派生索引，不改原会话、不恢复终端；强制索引、会消费消息或修改源记录的接口不按名称推定只读，尚未适配的入口拒绝。带桌面身份的 Client 不可通过通用 Open 绕到独立写入口，远程 Client 缺身份时只允许发现与控制协议。

窗口接入的主机状态层为每个目标保留独立连接代次和固定身份 Client。本机窗口在第一次成功读取实例状态、且无人持有控制时自动申请一次；状态读取失败不消耗机会。同一实例主动释放和普通断线重连从查看开始；显式切回本机可自动申请空闲实例，但主动释放、心跳失败和接管回复丢失的实例仍保持查看。daemon 换成新实例且无人控制时，可以再自动申请一次。远端连接和实例更换都不自动接管。心跳失败后降为查看，即使状态查询仍显示原控制者也是自己，也不自动恢复写入。离开主机立即使旧快照、确认回调和排队中的连接失效；迟到的接管结果只释放其取得的那一代租约。接管回复丢失不重发，限时查询状态，只释放仍属于本端且比请求时更新的租约；网络仍不可达时由服务端租期回收。远端主机入口见上文。

窗口动作已开始绑定固定请求上下文：终端创建、关闭、清屏和项目/工作区创建、移除、重定位在派发协程或打开确认框前捕获 Client 与控制代次，旧确认不能借用后来取得的身份。轮询与动作结果在主线程实际应用时再次核对来源；换身份后的首轮强制提交，避免已失效的排队结果压掉新状态。远端轮询不按本机路径清理工作区，也不查本机 HEAD 或用远端 PID 统计本机进程；移除远端项目不按本机目录是否存在判断仓库丢失。添加远端项目与重定位工作区使用目标目录选择弹窗，不打开本机选择器：可输入绝对路径、进入子目录或返回上级，只列目标目录（包括目录链接）；添加项目从 `/` 开始，重定位从原路径的父目录开始。成功加载当前目录后才允许选择，权限或不存在错误留在弹窗中，输入修改后须重新加载；读取和最终选择均绑定原主机及控制身份，取消、切换主机或换控制身份使旧回调失效。只有选定后才调用目标项目/工作区写入口。输入中的 `link/..` 由目标文件系统按软链接实际指向解析，添加项目不提前清理父目录段；普通软链接项目仍保留链接显示路径。讨论轮询固定使用本机 Client：查看远端工作区时仍每秒更新本机讨论列表和未读，详情仅在本机讨论页需要时获取；所有讨论与局域网协作请求、附件路径都留在本机，远端工作区轮询不携带讨论数据。终端改名、收回手机尺寸和恢复历史会话也已绑定固定请求：查看状态拒绝修改，尺寸标记等成功回复才改变；改名输入与串行队列不借用后来取得的控制权，带身份的改名失败或结果未知不自动重发，也不套用旧 ui.json 的待交名字。历史恢复的添加项目确认与后续恢复仍使用原主机、路径和身份，迟到结果不切换工作区。其他页面动作仍须接入，当前这些保护通过模拟 Unix RPC 验证。

历史列表、搜索和详情读取已固定请求身份，防抖等待、轮询、排队到主线程的结果及错误都会核对主机和查询序号；同一会话重新打开也不接受较早的详情。详情按需返回目标端的上下文用量，远端字段缺失时不回退读取同路径的本机文件。远端会话目录不作为本机访达链接。历史删除经 `history.trash` 在目标端接受控制身份、核对会话路径、复查运行状态，并与 Posse 恢复入口串行；使用无需窗口的 macOS 废纸篓适配，刷新删除后的索引，部分失败保留真实错误。恢复请求也携带文件路径，重复 ID 不再选错文件。助手 Markdown 图片已接入目标资源服务，根是绝对的会话 Cwd，否则用会话文件父目录；加载器固定主机、会话路径和详情请求代次，换会话、换主机或新详情到来会取消旧读取并丢弃迟到解码，不读本机同路径。工具文本仍按纯文本展示，会话媒体由现有图片面板提供。

聊天目录已由目标端发现和创建：`daemon.status.chat` 返回目标配置的路径和已有工作区 ID，发现不会建目录；`chat.ensure` 在桌面写入门禁内核对预期路径、创建目录并登记项目，已有聊天直接复用，同名项目时选目录名。同一实例的重复请求沿用普通操作结果缓存，不自动重做。远端窗口不读取本机聊天配置，不在本机建目标目录；查看可进入已有聊天，创建、启动与转为项目使用目标控制身份，迟到结果不跳转。远端聊天菜单不提供本机访达打开路径，目录设置仍在目标 Mac 修改。主机入口尚未开放，这些链路通过隔离目录及模拟 RPC 测试。

主机视图上下文各自持有稳定对象，切换只更换当前对象，保留文件编辑器缓冲区、标签、分栏和选中工作区；退出检查所有上下文的未保存文档。切换释放终端显示连接和旧控制租约，不发送关闭终端请求，切回也不恢复旧确认的有效性。窗口主题、字体和快捷键共用，本机 `ui.json` 保持原位置；其他主机的界面状态写在本机 home 下的 `host-ui/<主机ID摘要>/ui.json`，不写目标 Mac 的路径。保存未保存文档时按原对象归属核对连接，可写的本机文档即使隐藏也能保存；已失效或失去控制的文档保留修改，远端文件服务尚未接入时拒绝用本机路径代替。隐藏文档的覆盖确认显示在当前页面，仍绑定原保存请求。设置和更新页面固定本机，语言选择与 Dock 角标由窗口共用；切换清除待补报的已读缓存，切回后可重新上报。导航把工作区目标与当前显示页面分开：讨论、全局技能、手机、设置固定本机，浏览其他主机期间入口与页面标题标明「本机」；工作区、聊天、任务、历史恢复所选主机。进入本机页面不会覆盖原主机的标签和选择，关闭本机页面可返回原主机工作区。远端任务不提供本机「打开讨论」，相同讨论 ID 不跨主机解释。全局新建菜单的项目、工作区和任务动作先显示所选主机，手机入口固定本机；聊天右键菜单仅在选中动作时显示聊天所属主机，收集菜单项不切换页面。当前窗口 `Run` 只注册本机，测试通过内部切换入口和离屏界面验证保留与隔离，尚无可操作的主机切换入口。

这些接口目前用于后续窗口接入与测试，尚未宣布完整的桌面控制能力。窗口主机切换、本机窗口的控制身份、历史与设备入口适配、文件/Git 服务和跨入口写入协调仍须继续接入，不能把当前基础当成完整的查看/接管模式。

## 写入协调基础

目标 daemon 已把项目/工作区的创建、删除、合并、重定位和任务创建 worktree，以及手机切分支接入共享资源协调。路径按实际软链目标解析，目录操作与子路径写入互斥；同一 Git common-dir 的多个 worktree 共用仓库键。多资源一次取得，冲突请求按排队顺序执行，不冲突的资源可并行；等待可取消，释放或取消后不保留空闲锁记录。取得锁后重查项目/工作区登记、实际路径和仓库身份，变化时返回冲突。手机切分支只占用实际仓库路径与 common-dir，对项目登记持共享键，同项目的独立仓库可并行，无关损坏 worktree 不阻断操作；项目登记修改持独占键，与这些共享占用互斥。手机在取得锁后重新读取工作区、分支、未完成的 Git 操作和 agent 状态。项目添加和重定位取得锁后再次确认目标目录存在，原路径软链失效仍可清理登记或重定位。

独立 CLI 和手机工作区写入也登记在交接/退出门禁内，排队中的写入阻止 handoff；交接的新 daemon 取得 home 锁前拒绝这些写入。正常退出取消并收拢已登记的工作，随后才关闭存储。它们仍是独立操作，不需要桌面控制权；桌面已接受的请求继续由已有执行器持有，不重复登记。创建 worktree 的检查、建目录、登记与失败回滚在同一次资源占用内；setup 脚本在释放资源锁后运行，避免脚本反向调用 Posse 等待自身，生命周期仍保留到脚本退出。

这层协调只覆盖同一 daemon 的参与入口；agent、外部编辑器和 setup 脚本直接写盘不受其约束。条件保存 `files.save` 已通过桌面执行器接入该协调，基线与提交摘要校验成功后才原子替换；只保留写入版本和编辑 revision，已接受操作在断线后继续执行，旧身份不能提交新保存。窗口带桌面身份的文件保存与移到废纸篓已迁到目标服务；后者通过 `files.entry` 读取所选条目身份、确认后经 `files.trash` 锁内复查并调用无界面废纸篓适配，链接只移动链接本身。保存除实际路径外还共享占用途中经过的软链条目，取锁后重新发现；删除链接及其父目录与经过该链接的保存互斥，共用链接的无关文件仍可并行。尚未启用身份的本机窗口暂用版本校验和无界面适配直接操作。Fetch、Push、更新和分支操作已接同一写协调，具体接线见下文；其余桌面 Git 写操作仍待迁移。

## 文件读取（主机入口尚未开放）

目标端新增 `files.stat`、`files.readDirs`、`files.readRange`，桌面查看身份可以读取，不取得控制权。目录和状态按绝对路径批量查询，每项分别报错；文件按每段最多 1 MiB 读取，字节原样传输。分段请求携带预期磁盘戳，目标读前后核对打开文件及路径当前指向，变化则报冲突；不读取 FIFO 或设备。客户端保留原文本大小限制，只在所有分段属于同一版本时交出文本与内容指纹，不把权限或连接故障当成文件删除。窗口目录树、文本打开/重载与可见文件轮询已调用这些服务，异步结果核对主机身份、目录请求序号和文档读取基线。临时错误不清树、不标文件删除，也不清未保存内容；查看模式禁用编辑与格式化。Wiki 链接在目标查询，不读本机同名路径。文件清单、快速打开（含非项目条目）与全文搜索已通过 `files.list/search` 在目标执行，保留多仓库/单仓库和软链别名的忽略语义、限定目录、正则、大小写与未保存内容覆盖。目标自己生成搜索清单，草稿的相对路径不能逃出根目录；草稿最多 128 项、合计 8 MiB，单项沿用可编辑大小上限，回复最多 4 MiB，超限明确失败。窗口身份或查询变化会丢弃旧结果，连接身份变更后重新读取；失败保留已有清单与命中，不读本机同名路径。符号查询和定义跳转已通过只读 `files.symbols/definition` 接入：类型筛选、忽略目录、草稿覆盖和 import/限定符解析在目标执行；窗口只处理跳转、多候选选择和查找用法。主机或源文档版本、路径、当前标签及存续状态变化时，旧结果与选择框失效。源文本快照最多 50 MiB，结果沿用 4 MiB 预算。图片文件与 Markdown 嵌入图片已使用只读 `files.resourceRange` 在目标分段读取，按用途限制体积、核对版本，并在固定资源根内安全打开。Markdown 缓存随文档版本和主机身份更新，关标签取消目标读取；localhost 图片及指向本机回环地址的重定向不会在本机下载。HTML 及相对 CSS、JS、图片、字体等同源资源也经 `ReadResource` 读取：窗口预先注册 `posse-preview` scheme，每次载入用独立随机 token 固定主机身份、文档路径和磁盘戳，URL 不包含目标绝对路径。资源根与 Markdown 相同，保留 `link/..` 在目标解析；越界、`~/` 和 NUL 拒绝，不给 WebKit 本机目录权限，也不开本机 HTTP 服务。输出 HTML/CSS 的 localhost、`*.localhost`、回环和未指定 IP 引用改为空白地址，其他外部 HTTP(S) 子资源维持 WebKit 加载。网页链接交给网页标签，同根 HTML 可继续预览，根外和本机 file 导航被阻止。关标签、换主机或视图代次变化销毁页面并取消读取，文档戳变化作废旧 token；首次失败保留源码，重载失败保留成功页面，均不回退本机同名路径。目录批量传输和其余未迁移入口仍未完成，不宣布完整文件能力。窗口保存已按文档串行后台执行，提交快照与完整磁盘版本固定，覆盖确认不跳过版本检查，保存期间的编辑保持未保存。关闭操作等待保存完成，并复查所有待关闭文档；未知结果只查询原操作和当前版本，不自动重发，当前内容不一致时保留草稿及冲突提示，详见 `files.md`。

终端剪贴板图片已接入目标上传 `files.pasteImage`：最多 50 MiB，目标端校验 PNG 头和 SHA-256 后创建 0600 随机临时文件，与条件保存共用请求正文预算及桌面写入去重。上传成功且原控制身份、原终端视图仍有效时才粘贴目标路径；失败或结果未知不重发、不发送本机路径。断线不取消已接受上传，成功文件保留供 agent 读取。文件栏也已接入单文件上传与下载副本：顶部上传到工作区根目录，目录右键上传到所选目录，目标同名文件先按完整版本确认；文件右键下载到用户选定的本机路径，查看身份即可使用。两方向均限单文件 50 MiB，保留原始二进制和换行，读取失败、版本冲突或取消不留下半份文件；窗口的旧选择器和确认不能借用新身份，传输中的草稿保留。「用本机应用打开副本…」先让用户选择本机保存位置，沿用下载校验后打开保存的副本；修改不回写，迟到的旧身份不拉起应用，打开失败保留已下载副本。文件栏顶部上传菜单和目录右键菜单还提供文件夹批量上传与下载（`files.mkdir` 加逐文件条件读写，跳过 `.git` 和 `.DS_Store`，拒绝目录内符号链接与特殊文件，单次最多 500 项、32 层深度、合计 256 MiB，已存在同名目录时先确认合并覆盖）。从访达拖入或复制粘贴到远端终端的本地文件经 `files.pasteFile` 上传到目标 `0700` 随机临时目录（保留原文件名、权限 `0600`、单文件最多 50 MiB，与 `files.save` 共用请求正文预算和去重执行器），全部成功且原控制身份与终端视图仍有效时才贴入目标路径，失败不贴本机路径。

## 会话媒体读取（主机入口尚未开放）

目标新增只读 `media.list` 与 `media.path`。前者按 agent、会话 ID 和会话文件位置在目标增量扫描，返回粘贴图片、最近 40 项生成图片/视频及生成总数，回复最多 4 MiB；后者为磁盘图片返回目标路径，为日志内嵌图片或视频缩略图生成目标私有派生文件，窗口可继续用已有资源分段与摘要校验读取。内嵌项携带原始日志行摘要，偏移处记录改变时拒绝读取另一张图片；派生内容不使用客户端给出的显示名称作为文件名。

媒体服务允许桌面查看身份，独立直调和旧实例身份拒绝。扫描器最多缓存 8 个，派生文件最多 64 个、合计 128 MiB，按最近使用回收；目录 0700、文件 0600，daemon 退出时取消在途工作并清理。图片和派生缩略图最多 50 MiB。视频源只核对普通文件，缩略图在目标生成，支持取消；不会为了显示缩略图把完整视频传给窗口，视频本体下载仍受既有单文件限制。服务端定向 race、相关包完整回归、代码复审和 Grok 独立验收已通过；视频缩略生成器为测试注入，真实 QuickLook 和双 Mac 未验证。窗口图片面板已接目标列表、缩略图与悬停大图/动图，查看身份可以浏览和复制。复制只把图片数据写入本机剪贴板，不把目标路径冒充本机文件；点击图片在当前工作区打开目标图片标签，视频及「用本机应用打开副本…」经用户选定位置下载校验后打开，最多 50 MiB。远端卡片不提供本机访达和路径拖动入口。关闭面板、换会话、切主机和断开取消读取，旧身份和旧面板的迟到结果不复制、不跳转、不拉起应用；暂时失败的缩略图在下次轮询重试。窗口定向 race、桌面整包和静态检查通过，代码复审与 Grok 独立验收通过；系统剪贴板、保存对话框和应用打开使用测试替身，主机入口及真实双 Mac 仍未验证。

## Git 基础读取（主机入口尚未开放）

合并预演在临时 Git 目录执行，生成对象只写临时对象库，通过 alternates 读取目标原有对象；不修改目标工作树、索引或对象库，不执行自定义 merge driver。有效内置 text/binary/union 和工作树、嵌套目录、info/global 属性覆盖被带入隔离环境。属性查询使用私有临时目录中不存在的索引，避免把仅存在于目标暂存区的属性用于预测，与原生 merge-tree 的读取方式保持一致。复杂转换、相关子模块、浅克隆或多个合并基准等无法忠实处理的情况明确返回预测不可用；真实读取失败仍按错误处理。

输入树路径最多 20000；合并涉及的变化正文单个 blob 最多 8 MiB、去重合计 32 MiB，不将未改动的大资源计入正文预算。元数据和标准输出/错误的读取预算为 48 MiB，前后两遍输入与合并预演各占三分之一，两遍份额相同才能在同一步停下并得到一致基线，用剩的退回请求；计数之后任一份额超出时保留计数，返回 `unavailable`/`limit`，回复超过 4 MiB 时同样处理，不报错，总请求期限 30 秒。Git 子进程的单文件写入限制为 16 MiB，不修改 daemon 的进程限制；临时目录总量以 64 MiB 阈值每 100 毫秒检查并在结束后复核，这是运行中阈值，不能保证瞬时用量绝不超过。取消和完成后清理临时目录。

窗口仅为目标实际工作区根仓库显示基准关系，软链接按发现返回的 RealPath 识别，不把包含工作区的父仓或嵌套仓当成基准仓库。可见时每 10 秒轮询，隐藏或断线取消未完成读取，失败保留旧结果并提供显式刷新；首次仓库发现失败也能刷新恢复。同步和合并入口仅向控制端显示，实际写入见下文。本批服务和窗口定向 race、静态检查与深浅冲突/不可用预览通过；服务测试覆盖原生 Git 对照、有效属性、目标仓库不变、预算、取消清理及 RPC/客户端边界。窗口独立静态审查未发现明确缺陷；主线程桌面完整回归、全项目构建和 go vet、MyGo vet、i18n 及差异格式检查通过。服务独立审查未发现明确缺陷，属性/隔离/取消清理、真实 RPC 及客户端校验定向复验通过；Grok 独立验收通过，五包定向 race 无失败或跳过，四张已有深浅预览已检查；未重复完整 app 或前批矩阵。实际同步、合并回项目使用下文的已接受写操作，主机入口见上文，真实 SSH/双 Mac 未验证。

## 检出、新建、重命名与删除分支

`git.branch` 是已接受的 `desktop.call` 写操作，参数嵌入工作区登记和仓库身份，拒绝未知字段，使用十分钟客户端期限。与 `git.fetch` 共用 `lockFetchTarget`，路径和 Git common-dir 与文件保存进入同一写协调范围；排队后再次核对身份，锁内验证动作及 OID。校验冲突为 `conflict`、`Started=false`，不执行写命令。命令诊断、结果大小和操作记录沿用已有有界净化。

## 文件 Git 写操作

`git.paths` 通过已接受的 `desktop.call` 执行，嵌入 `GitFetchParams`，拒绝未知字段，客户端期限十分钟。路径只能是正斜杠的非空仓库相对路径，拒绝绝对路径和 `..`。参数保存点击时的 HEAD（无提交为空）、状态类别及覆盖所需的文件版本；逐段回滚另带原始字节与 SHA-256，正文不超过 `files.MaxSize`，结果只保留摘要与前提，不重复缓存正文。

仓库路径、Git common-dir、项目共享键与涉及的全部文件路径一次申请，不能先锁仓库再锁文件。它与 `files.save` 和 checkout 共用写协调，拿齐锁后再次核对工作区登记、仓库身份、HEAD、状态类别与文件版本。前提冲突为 `conflict`、`Started=false`，不执行写命令、不写文件、不删除；进入命令或 `WriteFileChecked` 后 `Started=true`，中途失败不回滚已完成部分。外部编辑器和命令不参加锁，文件版本复查不是文件系统 CAS。

各动作使用独立参数，所有 Git 路径带 `:(literal)`：

- `stage` 只接受仍未跟踪的路径，`resolve` 只接受仍冲突的路径，均执行 `add -A -- <paths>`。
- `unstage` 在无 HEAD 时执行 `rm --cached -r -q -- <paths>`，有 HEAD 时执行 `restore --staged -- <paths>`。
- `rollback` 依次执行 `restore --source=HEAD --staged --worktree -- <paths>`（重命名包括原路径）、新增文件 unstage、逐文件 `rm --cached -q --ignore-unmatch -- <path>`；最后一步成功才删除工作区文件，不删除目录。恢复和删除前检查点击时版本。
- `take` 仅冲突文件，先 `checkout --ours|--theirs -- <path>`，成功再 `add -- <path>`，不加 force，也不与“标记已解决”合并。
- `write` 的仓库和 HEAD 校验只用读取查询，实际修改只有 `files.WriteFileChecked`，Git 操作日志为空；返回新文件版本。版本过期不写，逐段回滚不更新其他编辑器缓冲区的保存版本。

## Git 提交

`git.commit` 使用已接受的 `desktop.call`，参数嵌入 `GitFetchParams` 并拒绝未知字段。客户端先 Prepare 再 Execute，期限十分钟；说明非空且最多 1 MiB，经 stdin 交给 `commit -F -`。单处改动另带文件原始字节和 SHA-256，最多 `files.MaxSize`；缓存只留正文和说明的摘要及原前提。路径复用 `git.paths` 校验和 `:(literal)` 规则。

`git.status` 的 `IndexID` 固定为 `ls-files -s -z` 原始输出的 SHA-256，不刷新或改写 index；无提交、空索引时 HEAD 为空，摘要为空输出的 SHA-256。提交请求固定点击时 HEAD 与 IndexID，一次取得 `lockFetchTarget` 的仓库路径、common-dir、项目共享键及全部相关文件锁，锁内复查工作区登记、仓库身份、HEAD、索引和文件版本。缺失也是预期版本；不符返回 `conflict`、`Started=false`，不改变 HEAD、索引或工作区。与目标保存互斥，等待保存后必须重新核对版本；等待提交的旧保存不会进入当前提交。

- `paths`：检查所有将从工作区进入提交的路径版本，显式 `Add` 里的新文件先 `add -A -- <literal paths>`，然后 `commit -F - --only [--amend] -- <literal paths>`。未勾选的暂存文件保留；amend 无路径时尾部仍有 `--`，只改说明。
- `whole`：必须仍处于 merge、cherry-pick 或 revert，暂存勾选路径后执行 `commit -F - [--amend]`；不加 `--only`、`-a`，提交暂存区全部内容。
- `change`：拒绝进行中的 Git 操作；在写对象之前确认路径的 HEAD blob 与索引 blob 一致，否则交回原 `ErrStagedChange`，`Started=false`。沿用临时索引的 `read-tree HEAD`、`update-index --cacheinfo`、`commit -q -F -`，成功后仅更新真实索引的该路径。请求字节不会替换为磁盘字节，工作区和其他暂存内容不变。

### 储藏写入

存入、应用、弹出与删除通过已接受的 `desktop.call` 方法 `git.stash`，参数嵌入 `GitFetchParams`，拒绝未知字段，动作仅为 push/apply/pop/drop。有身份的本机窗口和受控远端走目标 daemon，无身份旧测试窗口保持原调用；查看端保留文字但不显示按钮、菜单和 autostash 删除，直接调用不发送、不弹确认，也不报 `git.write`。

### 合并、变基与进行中的操作

`git.integrate` 使用已接受的 `desktop.call`，参数嵌入 `GitFetchParams`，拒绝未知字段；动作只有 merge、rebase、checkout-rebase、cherry-pick、revert、continue、skip、abort。客户端先 Prepare 后 Execute，客户端等待和 Git 命令均为十分钟。复用 `lockFetchTarget` 一次取得仓库路径、common-dir 与项目共享键，不逐个锁文件；拿锁后复查工作区登记和仓库身份。前提不符返回 conflict、Started=false，命令开始后 Started=true，输出沿用有界净化。

所有动作固定 HEAD OID 和当前分支。分支名使用现有校验，不能以 `-` 开头或含 `..`；本地分支查 `refs/heads/<name>`，远端跟踪分支查 `refs/remotes/<name>`，裸名字被同名标签遮住时拒绝。合并只执行 `merge --no-edit -- <name>`；变基只执行 `rebase <name>`，目标就是当前分支时不执行。检出并变基只执行 `rebase <current> <branch>`，分离 HEAD 用字面量 HEAD；目标被其他 worktree 检出时拒绝，不先 switch。

Cherry-pick 按应用顺序携带最多 500 个完整 OID，还原只携带一个 OID。锁内逐个 `rev-parse --verify --end-of-options <oid>^{commit}` 核对等于原值，再执行 `cherry-pick <oid>...` 或 `revert --no-edit <oid>`；冲突停在当前提交，保留已经应用的提交，不应用后续提交，不补 abort/reset。

继续核对原操作、HEAD、IndexID 且当前无未合并条目。merge 读取锁内 MERGE_MSG 原始字节，以整体提交的 `commit -F -` 经 stdin 提交；说明缺失、空、含 NUL、无效 UTF-8 或超过 1 MiB 时拒绝，不使用提交框文字。其余操作分别 `GIT_EDITOR=true rebase/cherry-pick/revert --continue`，不先做普通提交，不丢弃剩余序列；均不跳过钩子。skip 仅 rebase/cherry-pick，核对操作和 HEAD、不要求索引相同，以 `GIT_EDITOR=true <op> --skip` 执行；abort 核对四种操作及 HEAD，仅 `<op> --abort`，操作已结束时不执行。

本机有身份窗口和远端控制窗口迁移上述入口，无身份旧窗口保留原 gitx 调用；查看端零写调用、隐藏菜单和横幅按钮，直接调用也不报门禁错误。会改工作目录的动作沿用 guardAgent，确认固定 OID、仓库及控制代次；继续和跳过不加确认，中止保留原确认并固定操作和 HEAD。冲突时继续禁用，rebase/cherry-pick 仍可跳过。

回复丢失只查询原 ref 与参数，结果未知占住同仓库及同 common-dir 的全部 gitState。确认另开先运行本机旧队列，再核对新动作，不能插队；gitStart 与 gitNext 都保留占用。取消用当前控制身份和原 ref，回执不等于完成或中止，也不触发 abort；关闭确认框、断线和失控都不取消已接受操作。成功刷新只交给原连接的当前控制端，断线不切工作区、不额外关闭分支弹窗。任务和工作区的 `gitx.Merge` 仍保留 `--no-ff` 与失败 abort；历史改写、worktree 同步和合并回项目见下文；重命名与目录传输仍隐藏并在入队前由 `git.write` 拒绝，手机协议不变。

## Git 历史改写与 worktree 同步、合并回项目

`git.history` 通过已接受的 `desktop.call` 执行，仅接受 reset、reword、squash、drop，参数嵌入 `GitFetchParams` 并拒绝未知字段。客户端 Prepare 后 Execute，等待与 Git 命令均十分钟；一次 `lockFetchTarget` 获取仓库路径、common-dir 和项目共享键，锁内复核登记、仓库身份、点击时 HEAD/当前分支与完整目标 OID。进行中的 merge/rebase/cherry-pick/revert 拒绝；前提变化 conflict、Started=false，不执行命令。

已推送检查通过只读 `git.remotesContaining`，核对仓库身份后列出 `branch -r --contains <oid> --format=%(refname)`，剔除 refs/remotes/ 和 /HEAD 指针。写入携带确认过的有序远端跟踪名列表与 Confirmed；锁内列表变化或非空但未确认不执行。完整说明由现有 `git.commitFiles` 可选字段读取并核对身份；查看端不发起改写所需读取或确认，不在远端路径上运行本机 Git。

合并回项目复用已接受的 `workspace.merge`，不改变其检查、`gitx.Merge` 的 --no-ff 或失败 abort。单仓库先重新读取目标 divergence，冲突时只问先同步，预测不可用时显示原说明；多仓库不在窗口逐仓预测，保留目标任一仓库冲突或不可预测就全部不合的检查。确认仅发一次；丢失回复从错误保留原 ref，仅查询 desktop.operation，不重发。未知结果另开需要明确确认，先续跑本机旧队列并重新预测；运行中及未知结果占住工作区和同 common-dir 的所有 gitState，gitStart/gitNext 和仓库重新发现保留占用。

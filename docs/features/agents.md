# agent 识别、编排与会话标题

hooks 注入方式和 hook 的 stdout 规则见根目录 AGENTS.md。这里是 agent 识别、手动启动的 hooks、多 agent 编排（`posse task`）、会话标题、Posse 自带的技能、权限、各家状态细节、恢复终端、操作网页、文件去处和 agent 痕迹。

- 终端里的 agent 不只看启动参数：每次标题变化时取 PTY 的前台进程组（`Terminal.Foreground`），按它的 argv 认出 agent（`agent.OfProcess`；argv[0] 只是 `agent` 时看 exec 的路径：grok 和 Cursor 都装了叫 `agent` 的入口，指向谁看 PATH），和记录的不同就换过来、清掉旧会话信息（`session.detectAgent`）。这样在 grok 退出后的 shell 里手动敲 `claude`，图标和状态都跟着变。换上的 agent 没有 hooks 时，会话 ID 从它的参数里取（`agent.SessionFromArgs`：`--session-id`、`--resume <UUID>`，Codex 是 `resume <UUID>`），技能与工具面板凭它找会话文件。grok 和没经过同名脚本启动的没有 hooks，状态靠 OSC 7501（见下一条），没报过 7501 时靠标题（`agent.TitleOnlyStatus`：Claude 以 `✳` 开头是空闲，转动的圆形符号或盲文转圈符是工作中；grok 盲文转圈符开头是工作中，含 `Action Required` 是待处理，其余是空闲）。前台换成 shell、编辑器等不是 agent 的程序时不改，免得 agent 临时让出前台被当成退出。agent 退出时把它从终端上摘掉，终端退回普通 shell（侧栏不再列出，标签换回终端图标）：收到退出事件（Claude 的 SessionEnd 带 `prompt_input_exit` 等、Codex/Cursor 的 SessionEnd），或记下的 agent 进程组组长已经不在、exec 成了别的程序（`session.goneAgentPg`，标题变化时和每 2 秒查一次，崩溃、被杀、没有 hooks 的 agent 靠它）。
- 手动启动也带 hooks（`internal/agent/manual.go`）：常驻进程写出 `$POSSE_HOME/bin/{claude,codex,cursor-agent,grok,agent}`（`agent` 按它实际指向 grok 还是 Cursor 当成那一家补参数，`agent.ShimTarget`，认不出原样运行），转给 `posse agent exec <命令> --`，它在 PATH 里跳过这个目录找到真正的程序，按 `ManualArgs` 补上和界面启动一样的参数（Claude 不指定 `--session-id`，会话 ID 由 hooks 报上来；grok 只补 `--session-id`（用户自己带了 `-r`、`-c`、`-s` 时不补）和权限参数，常驻进程从 grok 进程的参数里读出会话 ID），环境里加 `POSSE_AGENT_SHIM=1` 后 exec 过去。`-p`、`exec`、`mcp`、`login` 这类非交互、管理用法原样运行；环境里已经有 `POSSE_AGENT_SHIM`（agent 自己跑工具时再调）或不在 posse 终端里也原样运行。zsh 终端（包括 agent 退出后回到的 zsh）走 Posse 的 shell 集成：用户自己的 zsh 配置照常读，每次出提示符前把 `$POSSE_HOME/bin` 放回 PATH 最前（`.zshrc` 常把 `~/.local/bin` 插到最前）；用户手动开的嵌套 zsh、bash、fish 不走集成。收到 hook 事件时常驻进程按它记 agent 并标成有 hooks（`session.markHooked`）。
- 装了哪些 agent 由常驻进程检测（`internal/daemon/agents.go`、`agent.DetectInShell`），经 `daemon.status` 的 `agents` 给界面和手机：新建终端、工作区右键、空工作区的启动格、新建工作区的「同时启动」、派发的「交给」和手机的 agent 列表只列装了的，`task start` 指定没装的直接报错。启动时和之后每 10 分钟起一次用户的交互式登录 shell（不走 Posse 的 zsh 集成，PATH 去掉 `$POSSE_HOME/bin`）跑 `command -v`，`.zshrc` 里的 alias、函数也算装了；其间每 30 秒按那个 shell 的 PATH stat 一次，新装的半分钟内出现。shell 跑不出结果（fish 这类不认 POSIX 语法的）时退回常驻进程自己的 PATH。还没检测完（`agents` 为 null）时全列。支持哪几家由 `agent.Known` 定，检测只决定显示哪些。
- 设置页「Agent」卡片给装了的每家一个开关，关掉的存在 `$POSSE_HOME/agents.json` 的 `disabled`（和权限档位同一个文件，窗口进程直接写，`agent.SetEnabled`）。窗口的各处选项（同上一条）不列它；常驻进程每次启动 agent 时现读，`startAgent` 拒绝它（桌面、手机、`terminal create`、`workspace create` 带 `--agent`、`task start` 都经这里，`workspace create` 在建工作区之前就挡；恢复历史会话也挡，重启后恢复终端时关掉的 agent 换成开 shell），手机的 agent 列表也去掉它（`enabledAgents`）。已经在运行的不受影响，在终端里自己敲 claude 这类命令不挡。
- 程序状态协议 OSC 7501（Rex 定义的，[规范](https://www.superlogical.com/rex/docs/build/program-status.md)）：程序在输出里报 idle、working、done、blocked（带 kind、msg）、error、clear。常驻进程在输出交给内核之前挑出来（`term/progstatus.go`，序列被两次读取切开也认，超过 4096 字节、说明解不开或带控制字符的整条丢掉，方向控制字符去掉，键和值两边的空白去掉，带 id 的子记录不管），并应答功能探测 `OSC 7501 ; ?`：要先于内核对紧跟着的 `CSI c` 的应答，所以界面接入时也由常驻进程应答（libghostty-vt 不认识 7501，界面不会重复回）。实测（Claude Code 2.1.318、Codex 0.166.0、Grok 1.0.74、Cursor 2026.10.22）：Claude、Grok 收到探测应答才报，Codex 不探测、一直在报；Cursor 不探测、不报，也不发 OSC 9;4 进度，状态照旧只靠 hooks；Claude 收到应答后不再把状态写进终端标题。等待时：Claude 提问报 `blocked`、`kind=question`，msg 是问题和选项；Codex 等批准命令报 `blocked`、`kind=permission`、不带 msg，标题同时写 `[ ! ] Action Required | …`（比 blocked 先到），取消后报 working 再报 idle；Grok 提问报 `blocked`，msg 是问题。实测 Codex 带 hooks 时等待由 PermissionRequest 记（带审批卡），没有 hooks 时由标题记，两种取消后都由 7501 回到空闲（用 `-a on-request -s read-only -c approvals_reviewer=user` 让它弹审批框，本机配置的 `auto_review` 会自动放行）。只有报告者（`app`：claude-code、codex、grok-build）和终端里认出的 agent 对得上才算（`daemon/progstatus.go`），别的程序报的不改 agent 状态。报过之后这个 agent 的状态以 7501 为准：working 是工作中，blocked 是等待（hook 没记过等待时用它的 msg 当说明，Claude 提问时是问题和选项），idle、done、error 是空闲；只跟状态的变化走，同一状态下的说明更新不动 agent 状态，所以 Claude 的 PermissionRequest 挂着等手机期间报的工作中冲不掉 hook 记下的审批卡。hook 事件照常提供会话 ID、最后一条回复、答题卡和审批、子 agent、退出和任务提醒，只是工作中、空闲换成 7501 报的（`session.preferOSC`），等待和退出照 hook；标题只用来看 Codex、Grok 等批准时的 `Action Required`：只往等待升，标题不再这样写时退回 7501 报的状态（`titleWaiting`），hook 记的等待不受它影响。读当前状态、算下一个状态和写回在同一把锁里（`Terminal.UpdateAgent`），同时到的 Stop hook 带来的最后一条回复、子 agent 不会被旧值盖掉。注入 hooks 的 agent（Claude、Cursor，按这家有没有 hooks 算：posse 派的 Grok 也记着 hooked，但等不到 hook，不在其内）和 Codex（手动启动的要到第一个 hook 才记成带 hooks）一轮从 hook 报工作中或有人往终端里输入开始，这之前 7501 报的工作中不算（Codex 启动时先报约两秒工作中，否则刚开的终端就成了未读、还会推送）。这样 Esc 中断（Claude、Codex 都不发 hook）、Grok 的提问都有准确的状态。clear、agent 换了或退出后回到 hooks 和标题；交接后的新常驻进程在收到下一条报告前也是，旧进程停读时没写完的半条序列随 Tail 带过去接着拼。
- 多 agent 编排（`posse task`）：派发方是调用方所在的终端（`POSSE_TERMINAL_ID`），为空表示用户（界面或终端之外）。worker 是新开的 agent 终端，带 `POSSE_TASK_ID`，启动提示由 `workerPrompt` 生成，写明 `posse task ask/check/done` 的用法。`ask/check/done` 只接受 worker 自己的终端，`reply/send/close` 只接受派发方，用户可以接手任何任务。worker 汇报后停在输入框、终端留着（编排说明让派发方默认不关，用户要求时才 `task close`）；对 done、failed 的任务 `task send` 会把它重新打开成 running，提醒同一个 worker `task check` 后接着做、再 `task done` 一次（`reopenTask`）。worker 的终端关了、其中的 agent 退出或换成了别家时拒绝，提示用 `task retry`；几方同时追加时只重新打开一次，消息都照常投递；追加的消息没记下时退回原状态，重新打开的同时 agent 退出的照常记 exited。done 消息记着汇报时的结果（`messages.outcome`），任务重新打开后收件箱和提醒仍按它说完成还是失败；任务上的 summary、report 在再次汇报前是上一轮的（`task show` 写 previous，界面写「上一轮汇报」），前几轮的汇报留在往来消息里。界面任务页只对用户自己派发的这类任务显示「追加任务」输入框：agent 派发的由派发方追加，免得它收到不知来由的汇报。编排说明默认派完就结束本轮、等提醒，用户要结果也一样，只有用户明确要等或在脚本里才用 `task wait` 阻塞：派发方阻塞时用户插不进话。
- 讨论（`posse discussion`，见 `discussions.md`）：成员的专用 worker 也是任务（`DiscussionID` 不为空、派发方为空），按成员串行排队；成员之间可以经 `discussion mention` 互相 @（有层数上限），讨论任务的 `task ask/check/done` 必带 `--execution`，`done` 带完整回复（`--body`/`--body-file`），`task.send` 被拒、`task retry` 在 CLI 被拒，`task clear` 跳过成员当前绑定的任务。普通任务不带 `--execution` 照旧。
- 派发方的收件箱是 question/done/exit 三类消息，worker 的是 answer/note。有未提醒过的消息时，posse 给对方的 agent 一行提醒（派发方是 `Posse: … Run \`posse task inbox\` to read.`，worker 是让它 `posse task check`），每条消息只提醒一次。有 hook 的 agent 由 hook 交（`takeNudge`、`agent.DeliversOn`）：Claude、Codex 的 PostToolUse，Claude 的 PostToolUseFailure 和 Cursor 的 postToolUse、postToolUseFailure 随工具结果放进上下文（`additionalContext` / `additional_context`），agent 忙着也能在两次工具调用之间读到；本轮结束时 Claude 的 Stop 用 `additionalContext`（`decision: block` 会显示成 Stop hook error）、Codex 的 Stop 用 `decision: block` 加 `reason`、Cursor 的 stop 用 `followup_message` 让它接着处理，这时状态记工作中；用户中途停下的 Cursor stop（`status: aborted`）不读 followup_message，被用户中断的工具失败事件（`is_interrupt`）带的上下文随这一轮丢掉，这两种都不交，留给空闲后往终端里输入。本轮结束时交了提醒后 90 秒内这个终端没再来 hook 事件，算 agent 没接着做：提醒退回未提醒、状态记回空闲，改为往终端里输入（`checkStopDelivery`）。子 agent 的工具事件（Claude 带 `agent_id`、Cursor 带 `parent_tool_call_id`）不交；Codex 子 agent 的事件认不出来。hook 没赶上的（消息到时 agent 已经空闲），等它空闲（hooks 或标题报告 idle，或主线程停着、只有后台子 agent 在跑）且 5 秒内没有人键入时往终端里输入这行并回车；grok 没有 hook，只走这条。worker 终端或其中的 agent 没汇报就退出时，任务记为 exited 并通知派发方；`task close` 先改状态再关终端，不算意外退出。常驻进程重启时还在进行的任务记为 lost。
- worker 最多嵌套 3 层。`posse task guide` 是给协调方 agent 看的说明（源文件 `internal/cli/task_guide.md`），`--skill` 输出带 frontmatter 的 SKILL.md。`posse task retry` 在 CLI 里组合 show 和 start，用原任务的说明、agent、模型、思考深度和工作区重派（`--model`、`--effort` 可以单独换一项，`--spec`、`--spec-file` 换说明），只接受 failed、exited、lost、stopped 的任务。
- 指定模型和思考深度：`posse task start`、`terminal create`、`workspace create` 带 `--agent` 时可加 `--model`、`--effort`，不给就用 agent 自己的默认设置，值不做校验、原样交给 agent（`agent.Model.args`）：Claude `--model`、`--effort`；Codex `--model`、`-c model_reasoning_effort=…`；Grok `--model`、`--reasoning-effort`；Cursor 没有单独的思考深度参数，`--effort` 要配 `--model`，拼成 `<模型>[effort=<深度>]`。派出去的 Cursor worker 另加 `--trust`（`Model.Worker`）：worker 终端前面没人守着，在没信任过的目录（新建的 worktree）里 Cursor 会卡在工作区信任框上，这时 hooks 还没起作用，Posse 也认不出待处理；用户自己开的 Cursor 照它的默认，第一次进目录时问。任务的模型和思考深度存在 tasks 表，`task list`、`task show` 显示成 `codex:gpt-5.5/high`。
- 会话标题（`posse session title`，规则在 `posse session guide`，源文件 `internal/cli/session_guide.md`）：用户调用技能 `posse-rename`（只能由用户调用，Claude 里是 `/posse-rename`）或让 agent 起名时，agent 读指南、拟 `MMDD｜类型｜摘要`，标题跟着 Posse 的界面语言写（`errtext.SystemLang`，指南和常驻进程规整用同一种）：中文时类型限 修复 开发 调研 调试 重构 文档 杂项、摘要不超过 20 字，英文时类型限 fix feat research debug refactor docs chore、摘要不超过 40 个字符；两种语言的类型词和同义词（feat、功能算开发，配置、构建算杂项）都换成当前语言的写法，摘要开头重复的类型词只在后面跟着分隔符时去掉（「修复率统计」不动），在自己的终端里运行命令；常驻进程收到后（RPC 入口 `internal/daemon/title.go`）规整格式（`namer.Normalize`，日期换成今天、类型同义词换成标准写法），按终端里的 agent 写（Codex、Grok 的写法在 `internal/namer/store.go`）：Claude 只认 UserPromptSubmit hook 返回的 sessionTitle，先记成待交，下一次提交时由 posse hook 交过去（Claude 随后写 `custom-title`、改终端标题）；Codex 照它的 /rename 写 state 库 `threads`（paginated 写 name、旧格式写 title）并追加 `session_index.jsonl`；Grok 写会话目录 `summary.json` 的 `generated_title`、`session_summary` 并置 `title_is_manual`；Cursor 没有核实过能写的地方，只在 Posse 里显示。会话 ID 优先用命令环境里 agent 注入的（`CLAUDE_CODE_SESSION_ID`、`CODEX_THREAD_ID`、`GROK_SESSION_ID`），没有再用常驻进程记下的。标题记在终端的 agent 状态上（`AgentState.Title`、`TitlePending`，交接时随记录带过去），同一个会话的后续事件沿用、换了会话就清掉；界面的标签、侧栏和手机的标签名用它代替终端标题。
- Posse 自带两个技能：编排 `posse-tasks` 和会话命名 `posse-rename`（技能文本在 `internal/skills/posse.go`，正文分别指向 `posse task guide`、`posse session guide`，规则跟着程序版本走）。它们不按会话注入，由用户装进用户的技能目录：`~/.agents/skills/<名字>`（Codex、Grok、Cursor 都读），Claude 读的 `~/.claude/skills/<名字>` 是指向它的相对链接；离开 Posse 也看得到，但说明写明只在 Posse 里用。frontmatter 的 `metadata` 带 `managed-by: posse` 和内容版本 `posse-skills-version`（`posseSkillsVersion`，改了技能内容就加一，`TestPosseSkillsVersion` 按内容摘要守着），靠前者认出是 Posse 装的，同名但没有标记的是用户自己的，不装、不覆盖。安装经 npx skills，来源是窗口写出的 `~/Library/Application Support/Posse/skills`（日常版和开发版共用用户目录和锁文件，来源不放在各自的 `POSSE_HOME` 里）：`npx skills add <来源> -g -a codex -a claude-code -s <名字>… -y`。npx skills 不查本地来源的更新，装上的版本比这一版旧、或同一版内容不同就算有更新；比这一版新的（更新的 Posse 装的，比如开发版）不算，免得日常版和开发版轮流降级对方，更新是对这几个再装一次（之前删掉了 Claude 的链接、或要装的某个在 `~/.claude/skills` 里同名的是用户自己的，就整批不带 `-a claude-code`：它对一次装的所有技能都生效）；点安装时先重读一遍磁盘，提示出来之后用户自己放了同名技能的不装。`posse task guide --skill` 输出的头部不带标记，用户用它自己放的技能 Posse 不管。没有工作区可建终端、或之前是直接复制装的，不经 npx 直接照同样的布局放好文件；npx 跑失败时对话框里也能改成直接复制。入口见 `ui.md` 的侧栏提示卡和技能页。旧版按会话注入的 `$POSSE_HOME/claude-plugin` 和 Cursor 插件里的 `skills` 由常驻进程启动时删掉。`posse task` 各命令的输出都写明下一步（`task start` 提示不必等、`inbox` 里的完成消息提示怎么追加、退出消息提示怎么重派、worker 的 `check`、`done` 提示怎么汇报和等待），技能没触发或说明被压缩掉时协议照样走得下去。
- agent 权限照 Orca 的 Agent Permissions（`internal/agent/permission.go`）：默认跳过审批，界面启动、恢复会话、任务 worker 和手动敲的 claude/codex/cursor-agent/grok 都带上各家的跳过参数（Claude `--dangerously-skip-permissions`、Codex `--dangerously-bypass-approvals-and-sandbox`、Grok `--permission-mode bypassPermissions`、Cursor `--yolo`）；手动启动时用户自己带了权限参数（`--permission-mode`、`-a`、`-s`、`--force` 等）就不补。设置页的「Agent 权限」可改成逐项确认，档位存在 `$POSSE_HOME/agents.json`（窗口进程直接写），每次启动 agent 时读，改了不用重启常驻进程，已经在运行的不变。跳过审批时 Claude 不会发 PermissionRequest，手机审批用不上。
- Claude 的后台子 agent：主线程 Stop 带着 `background_tasks`，其中还在跑的 subagent、teammate、workflow 记在 `AgentState.Subagents`（交接时随记录带过去），不为空时这次 Stop（以及 Esc 后标题回到 `✳`）不算本轮完成，仍是工作中：`terminal wait --for idle`、界面和手机都按工作中，但主线程已经回到输入框（`agent.Parked`），task 提醒照常输入。后台 shell、monitor 不算（dev server 会一直挂着）。子 agent 结束时 Claude 先发 SubagentStop（带 `agent_id`，从列表划掉），再自己开一轮处理结果（UserPromptSubmit 带 `<task-notification>`），那一轮的 Stop 才是完成；最后一个划掉后 20 秒没有新的主线程事件（子 agent 被停掉等）也按完成算。后台子 agent 不发 SubagentStart，所以还在跑的以 Stop 为准；子 agent 里的工具事件带 `agent_id`，不改主线程的状态。
- hook 是同步调用的，每个事件都要拉起一次 posse，所以只订阅改状态用得上的：Claude 的 PreToolUse 只匹配 `AskUserQuestion`、Codex 的只匹配 `request_user_input`（只为认出向用户提问；Codex 的信任 hash 把 matcher 算在内），工作中由 UserPromptSubmit、PostToolUse 记；Claude 不订阅 SubagentStart；Cursor 的工具事件只留做完时的 postToolUse、postToolUseFailure。代价：Codex 默认模式下 `request_user_input` 调用失败不发 PostToolUse，误记的等待要到下一个工具做完或 Stop 才清掉；别的 Stop hook 拦下停止、Claude 接着做的一轮，要到第一个工具做完才记工作中（Claude 自己开始的一轮照样发 UserPromptSubmit）。
- Cursor（`cursor-agent`）的状态：beforeSubmitPrompt、postToolUse、postToolUseFailure 是工作中，stop 是空闲，sessionEnd 是退出；sessionStart 不改状态（带初始提示时第一轮可能不发 beforeSubmitPrompt，由工具事件兜底）。会话 ID 不能预先指定，由 hook 报上来。Cursor 没有"等待批准"的事件，标题只是会话名，待处理目前认不出来。
- 重启电脑或常驻进程后恢复终端（`internal/daemon/restore.go`，参照 Orca 的 resumeOnRestart，但不存屏幕内容）：每个终端在库里记着 agent、会话 ID、前台程序所在的目录和这时显示的名字（会话标题，没有时是去掉状态前缀的终端标题；`terminals.agent`、`session_id`、`cwd`、`label`，`saveResume`）。常驻进程开始退出（收到信号、`daemon.stop`）后终端的退出不记，记录保持 running，下次启动记成 lost、照常列在界面、手机首页和 `terminal list` 里（`Lost`，标签和侧栏照旧写记下的名字，没有 agent 的写默认名字：恢复出来是新开的 shell，记下的终端标题多半是之前退出的 agent 留下的；状态是空心带横线的蜂巢格「未恢复」）。用户关掉的终端马上记成退出，程序自己退出的等 5 秒（`resumeSettle`）再记：关机时不在交互式 shell 里的命令可能比常驻进程先收到 SIGTERM；agent 退出后同样等 5 秒才从记录上摘掉，免得和常驻进程差不多同时收到 SIGTERM 时把要续接的会话清掉。第一次在界面接入、手机打开终端页或用 CLI 操作它时按原来的 ID、名字和创建时间拉起：有会话的 agent 用 `launcher.Resume` 续接，没有会话的新开一个，关掉了的 agent 和普通终端在记下的目录开 shell，第一行打「Posse 已恢复上次的终端」；关掉还没恢复的只删记录，改名只改记录，hook、任务、Git 记录不会把它拉起。恢复信息在 hook 到达和每 2 秒的 agent 检查时写库。设置「通用 › 恢复终端」打开后（`agents.json` 的 `restoreAll`）常驻进程一启动就全部恢复，交接过来的进程不自动恢复。任务不续接，照旧记 lost，用 `task retry` 重派。
- agent 操作网页（`posse web`，说明在 `posse web guide`，源文件 `internal/cli/web_guide.md`）：网页标签在窗口进程里，CLI 直接连窗口进程的 `$POSSE_HOME/app.sock`（`internal/app/webctl.go`，权限 0600，同一 home 已有窗口进程在接就不接管，没人应答的残留文件删掉重建），常驻进程不参与，窗口没开时回 `no_window`、不替它拉起窗口。命令作用于调用方所在工作区（`POSSE_WORKSPACE_ID`，不在 Posse 终端里时用侧栏选中的，`--workspace` 指定）的网页标签，有多个时默认最近显示过的，`--tab` 按编号指定；`open` 新开并切到这个标签，不抢键盘；`open`、`goto` 给本地文件路径（相对路径由 CLI 按自己的工作目录换成绝对路径）时载入这个文件。`snapshot`、`click`、`fill`、`press`、`console` 调页面里的 `window.__posse`（`internal/app/webctl.js`，每次随 Eval 带上，页面载入时也经 `PreloadScript` 注入，console 从页面自己的脚本之前开始记，最多 200 条）：snapshot 列可见的可交互元素和标题、地标，ref 写在元素的 `data-posse-ref` 上，再次 snapshot 不变；点击、按键是脚本派发的 DOM 事件，Enter 提交表单、Tab 换焦点这几样默认动作由脚本补上。只看主 frame，iframe 里的元素和输出看不到。从没显示过的标签（工作区在窗口里没选中过）没有尺寸，截图报错，别的命令照常。`posse web device <机型|off>` 开关手机预览（和工具栏的手机按钮一样，见 `ui.md`），开着时截图是机型大小的画面。
- 文件去处（`internal/agent/notes.go` 的 `notesHint`，`internal/daemon/notes.go`）：终端带 `POSSE_NOTES=<项目目录>/.posse`，各工作区共用，worktree 删掉后报告还在；git 项目由常驻进程往共用 git 目录的 `info/exclude` 补一行 `/.posse/`（所有 worktree 都生效，不改仓库的 `.gitignore`），目录本身等 agent 用到时自己建。posse 启动的 agent 收到一段指路：给人看的报告、计划、交接写进 `$POSSE_NOTES`（项目自己的规则另有规定时照项目的）；测试包、截图、日志、对比副本这类临时文件放 `$TMPDIR` 下（系统会清），不放项目、下载、桌面和项目旁边；另开副本用 `posse workspace create --mode worktree`，不自己 `git worktree add`。只有 Claude 有：经 `--append-system-prompt`（手动启动时用户自己给了系统提示就不加），不碰用户的配置；Codex 的 `developer_instructions` 会整个替换用户的同名设置、Grok 的 `--rules` 同属附加指令，都不注入，Cursor 的插件没有按会话常驻的规则。worker 的说明让报告写在 `$POSSE_NOTES/tasks/<任务ID>/`。
- agent 痕迹（`internal/daemon/traces.go`，存在 posse.db 的 `traces` 表）：常驻进程记下 agent 在工作区外留下的文件和目录。来源：工具做完时的 hook（Claude、Codex 的 PostToolUse，Cursor 的 postToolUse）里写文件工具的路径（读文件、搜索类工具的不算），以及 shell 命令里猜出的写入目标（输出重定向、mkdir、touch、tee、cp/mv/rsync 的目标、curl/wget/unzip/tar/go/xcodebuild 等的输出选项、adb pull，`history.WriteTargets`；先 cd 到绝对路径的按它拼相对路径，变量和通配符不猜）；终端里 git 的操作记录里成功的 `worktree add` 和 `clone`（终端里有 agent 时才记）。只记还存在、不在本工作区、项目目录和 `POSSE_HOME` 里的路径；`/tmp`、`$TMPDIR`、agent 自己的目录（`~/.claude` 等）、共享缓存（`~/Library/Caches`、`~/Library/Developer`、`~/.gradle`、`~/.npm` 等）不记。按创建时间分类：这一轮开始（agent 进入工作中的时刻，之前没有时用终端的创建时间）之后新建的记成「新建」，并往上找到这一轮一起新建的最上层目录（`~/Downloads/ddt-apk/a/b.apk` 记成 `~/Downloads/ddt-apk`，不越过下载、桌面这类用户目录和工作区的上级目录）；已有的文件记成「改过」；主目录下的隐藏文件和目录、`~/Library`、`/etc`、`/usr/local`、`/opt` 记成「配置」；自建的 worktree 单独一类（Posse 自己管的和登记成工作区的不算）。同一路径只记第一次，已记成新建的目录里后来写的文件不另记。`posse trace list [--workspace W] [--project P]` 列出来（`trace.list`，顺手去掉磁盘上已经没有的），界面怎么清理见 `ui.md`。

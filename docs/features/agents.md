# agent 识别、编排与会话标题

hooks 之外的 agent 识别、手动启动的 hooks、多 agent 编排（`posse task`）、会话标题、编排技能注入、权限、各家状态细节。

- 终端里的 agent 不只看启动参数：每次标题变化时取 PTY 的前台进程组（`Terminal.Foreground`），按它的 argv 认出 agent（`agent.OfProcess`；argv[0] 只是 `agent` 时看 exec 的路径：grok 和 Cursor 都装了叫 `agent` 的入口，指向谁看 PATH），和记录的不同就换过来、清掉旧会话信息（`session.detectAgent`）。这样在 grok 退出后的 shell 里手动敲 `claude`，图标和状态都跟着变。换上的 agent 没有 hooks 时，会话 ID 从它的参数里取（`agent.SessionFromArgs`：`--session-id`、`--resume <UUID>`，Codex 是 `resume <UUID>`），技能与工具面板凭它找会话文件。grok 和没经过同名脚本启动的没有 hooks，状态只靠标题（`agent.TitleOnlyStatus`：Claude 以 `✳` 开头是空闲，转动的圆形符号是工作中）。前台换成 shell、编辑器等不是 agent 的程序时不改，免得 agent 临时让出前台被当成退出。agent 退出时把它从终端上摘掉，终端退回普通 shell（侧栏不再列出，标签换回终端图标）：收到退出事件（Claude 的 SessionEnd 带 `prompt_input_exit` 等、Codex/Cursor 的 SessionEnd），或记下的 agent 进程组组长已经不在、exec 成了别的程序（`session.goneAgentPg`，标题变化时和每 2 秒查一次，崩溃、被杀、没有 hooks 的 agent 靠它）。
- 手动启动也带 hooks（`internal/agent/manual.go`）：常驻进程写出 `$POSSE_HOME/bin/{claude,codex,cursor-agent,grok,agent}`（`agent` 按它实际指向 grok 还是 Cursor 当成那一家补参数，`agent.ShimTarget`，认不出原样运行），转给 `posse agent exec <命令> --`，它在 PATH 里跳过这个目录找到真正的程序，按 `ManualArgs` 补上和界面启动一样的参数（Claude 不指定 `--session-id`，会话 ID 由 hooks 报上来；grok 只补 `--session-id`（用户自己带了 `-r`、`-c`、`-s` 时不补）、编排说明的 `--rules` 和权限参数，常驻进程从 grok 进程的参数里读出会话 ID），环境里加 `POSSE_AGENT_SHIM=1` 后 exec 过去。`-p`、`exec`、`mcp`、`login` 这类非交互、管理用法原样运行；环境里已经有 `POSSE_AGENT_SHIM`（agent 自己跑工具时再调）或不在 posse 终端里也原样运行。zsh 终端（包括 agent 退出后回到的 zsh）走 Posse 的 shell 集成：用户自己的 zsh 配置照常读，每次出提示符前把 `$POSSE_HOME/bin` 放回 PATH 最前（`.zshrc` 常把 `~/.local/bin` 插到最前）；用户手动开的嵌套 zsh、bash、fish 不走集成。收到 hook 事件时常驻进程按它记 agent 并标成有 hooks（`session.markHooked`）。
- 装了哪些 agent 由常驻进程检测（`internal/daemon/agents.go`、`agent.DetectInShell`），经 `daemon.status` 的 `agents` 给界面和手机：新建终端、工作区右键、空工作区的启动格、新建工作区的「同时启动」、派发的「交给」和手机的 agent 列表只列装了的，`task start` 指定没装的直接报错。启动时和之后每 10 分钟起一次用户的交互式登录 shell（不走 Posse 的 zsh 集成，PATH 去掉 `$POSSE_HOME/bin`）跑 `command -v`，`.zshrc` 里的 alias、函数也算装了；其间每 30 秒按那个 shell 的 PATH stat 一次，新装的半分钟内出现。shell 跑不出结果（fish 这类不认 POSIX 语法的）时退回常驻进程自己的 PATH。还没检测完（`agents` 为 null）或旧常驻进程不报时全列。支持哪几家仍是 `agent.Known`，每家的 hooks、标题、会话解析要专门写，检测只决定显示哪些。
- 设置页「Agent」卡片给装了的每家一个开关，关掉的存在 `$POSSE_HOME/agents.json` 的 `disabled`（和权限档位同一个文件，窗口进程直接写，`agent.SetEnabled`）。窗口的各处选项（同上一条）不列它；常驻进程每次启动 agent 时现读，`startAgent` 拒绝它（桌面、手机、`terminal create`、`workspace create` 带 `--agent`、`task start` 都经这里，`workspace create` 在建工作区之前就挡；恢复历史会话也挡），手机的 agent 列表也去掉它（`enabledAgents`）。已经在运行的不受影响，在终端里自己敲 claude 这类命令不挡。
- 多 agent 编排（`posse task`）：派发方是调用方所在的终端（`POSSE_TERMINAL_ID`），为空表示用户（界面或终端之外）。worker 是新开的 agent 终端，带 `POSSE_TASK_ID`，启动提示由 `workerPrompt` 生成，写明 `posse task ask/check/done` 的用法。`ask/check/done` 只接受 worker 自己的终端，`reply/send/close` 只接受派发方，用户可以接手任何任务。worker 汇报后停在输入框、终端留着（编排说明让派发方默认不关，用户要求时才 `task close`）；对 done、failed 的任务 `task send` 会把它重新打开成 running，提醒同一个 worker `task check` 后接着做、再 `task done` 一次（`reopenTask`）。worker 的终端关了、其中的 agent 退出或换成了别家时拒绝，提示用 `task retry`；几方同时追加时只重新打开一次，消息都照常投递；追加的消息没记下时退回原状态，重新打开的同时 agent 退出的照常记 exited。done 消息记着汇报时的结果（`messages.outcome`），任务重新打开后收件箱和提醒仍按它说完成还是失败；任务上的 summary、report 在再次汇报前是上一轮的（`task show` 写 previous，界面写「上一轮汇报」），前几轮的汇报留在往来消息里。界面任务页只对用户自己派发的这类任务显示「追加任务」输入框：agent 派发的由派发方追加，免得它收到不知来由的汇报。编排说明默认派完就结束本轮、等提醒，用户要结果也一样，只有用户明确要等或在脚本里才用 `task wait` 阻塞：派发方阻塞时用户插不进话（旧说明允许「下一步非要结果」时阻塞，真实 Codex 在用户说「然后告诉我结果」时就会等）。
- 派发方的收件箱是 question/done/exit 三类消息，worker 的是 answer/note。派发方 agent 空闲（hooks 或标题报告 idle，或主线程停着、只有后台子 agent 在跑）且 5 秒内没有人键入时，posse 往它终端里输入一行 `Posse: … Run \`posse task inbox\` to read.` 并回车；每条消息只提醒一次。worker 终端或其中的 agent 没汇报就退出时，任务记为 exited 并通知派发方；`task close` 先改状态再关终端，不算意外退出。常驻进程重启时还在进行的任务记为 lost。
- worker 最多嵌套 3 层。`posse task guide` 是给协调方 agent 看的说明（源文件 `internal/cli/task_guide.md`），`--skill` 输出带 frontmatter 的 SKILL.md。`posse task retry` 在 CLI 里组合 show 和 start，用原任务的说明、agent、模型、思考深度和工作区重派（`--model`、`--effort` 可以单独换一项，`--spec`、`--spec-file` 换说明），只接受 failed、exited、lost、stopped 的任务。
- 指定模型和思考深度：`posse task start`、`terminal create`、`workspace create` 带 `--agent` 时可加 `--model`、`--effort`，不给就用 agent 自己的默认设置，值不做校验、原样交给 agent（`agent.Model.args`）：Claude `--model`、`--effort`；Codex `--model`、`-c model_reasoning_effort=…`；Grok `--model`、`--reasoning-effort`；Cursor 没有单独的思考深度参数，`--effort` 要配 `--model`，拼成 `<模型>[effort=<深度>]`。任务的模型和思考深度存在 tasks 表，`task list`、`task show` 显示成 `codex:gpt-5.5/high`。
- 会话标题（`posse session title`，规则在 `posse session guide`，源文件 `internal/cli/session_guide.md`）：用户调用技能 `session-namer`（Claude 里是插件技能 `/posse:session-namer`，只能由用户调用）或让 Codex、Grok 起名时，agent 读指南、拟 `MMDD｜类型｜摘要`（类型限 修复 feat 调研 调试 重构 文档 杂项，摘要不超过 20 字），在自己的终端里运行命令；常驻进程收到后（RPC 入口 `internal/daemon/title.go`）规整格式（`namer.Normalize`，日期换成今天、类型同义词换成标准写法），按终端里的 agent 写（Codex、Grok 的写法在 `internal/namer/store.go`）：Claude 只认 UserPromptSubmit hook 返回的 sessionTitle，先记成待交，下一次提交时由 posse hook 交过去（Claude 随后写 `custom-title`、改终端标题）；Codex 照它的 /rename 写 state 库 `threads`（paginated 写 name、旧格式写 title）并追加 `session_index.jsonl`；Grok 写会话目录 `summary.json` 的 `generated_title`、`session_summary` 并置 `title_is_manual`；Cursor 没有核实过能写的地方，只在 Posse 里显示。会话 ID 优先用命令环境里 agent 注入的（`CLAUDE_CODE_SESSION_ID`、`CODEX_THREAD_ID`、`GROK_SESSION_ID`），没有再用常驻进程记下的。标题记在终端的 agent 状态上（`AgentState.Title`、`TitlePending`，交接时随记录带过去），同一个会话的后续事件沿用、换了会话就清掉；界面的标签、侧栏和手机的标签名用它代替终端标题。
- 编排技能 `posse-tasks` 随 agent 启动按会话注入，不写全局目录，正文都指向 `posse task guide`（技能文本在 `internal/agent/skill.go`）：Claude 加 `--plugin-dir $POSSE_HOME/claude-plugin`（posse 生成的插件，含这个技能和 session-namer，内容没变不重写；Cursor 的插件同样带这两个技能）；Codex 和 Grok 没有按会话加载技能的办法，分别用 `-c developer_instructions=…` 和 `--rules` 放一句指路（编排、会话命名各一句；用户的 `config.toml` 里设了 developer_instructions 时 Codex 不注入）。
- agent 权限照 Orca 的 Agent Permissions（`internal/agent/permission.go`）：默认跳过审批，界面启动、恢复会话、任务 worker 和手动敲的 claude/codex/cursor-agent/grok 都带上各家的跳过参数（Claude `--dangerously-skip-permissions`、Codex `--dangerously-bypass-approvals-and-sandbox`、Grok `--permission-mode bypassPermissions`、Cursor `--yolo`）；手动启动时用户自己带了权限参数（`--permission-mode`、`-a`、`-s`、`--force` 等）就不补。设置页的「Agent 权限」可改成逐项确认，档位存在 `$POSSE_HOME/agents.json`（窗口进程直接写），每次启动 agent 时读，改了不用重启常驻进程，已经在运行的不变。跳过审批时 Claude 不会发 PermissionRequest，手机审批用不上。
- Claude 的后台子 agent：主线程 Stop 带着 `background_tasks`，其中还在跑的 subagent、teammate、workflow 记在 `AgentState.Subagents`（交接时随记录带过去），不为空时这次 Stop（以及 Esc 后标题回到 `✳`）不算本轮完成，仍是工作中：`terminal wait --for idle`、界面和手机都按工作中，但主线程已经回到输入框（`agent.Parked`），task 提醒照常输入。后台 shell、monitor 不算（dev server 会一直挂着）。子 agent 结束时 Claude 先发 SubagentStop（带 `agent_id`，从列表划掉），再自己开一轮处理结果（UserPromptSubmit 带 `<task-notification>`），那一轮的 Stop 才是完成；最后一个划掉后 20 秒没有新的主线程事件（子 agent 被停掉等）也按完成算。后台子 agent 不发 SubagentStart，所以还在跑的以 Stop 为准；子 agent 里的工具事件带 `agent_id`，不改主线程的状态。
- grok 不注入 hooks（只能写进 `~/.grok/hooks`），状态靠终端标题：盲文转圈符开头是工作中，含 Action Required 是待处理，其余是空闲。
- Cursor（`cursor-agent`）的状态：beforeSubmitPrompt 和工具事件是工作中，stop 是空闲，sessionEnd 是退出；sessionStart 不改状态（命令行带初始提示时第一轮不发 beforeSubmitPrompt）。会话 ID 不能预先指定，由 hook 报上来。Cursor 没有"等待批准"的事件，标题只是会话名，待处理目前认不出来。
- 重启电脑或常驻进程后恢复终端（`internal/daemon/restore.go`，参照 Orca 的 resumeOnRestart，但不存屏幕内容）：每个终端在库里记着 agent、会话 ID、前台程序所在的目录和这时显示的名字（会话标题，没有时是去掉状态前缀的终端标题；`terminals.agent`、`session_id`、`cwd`、`label`，`saveResume`）。常驻进程开始退出（收到信号、`daemon.stop`）后终端的退出不记，记录保持 running，下次启动记成 lost、照常列在界面和 `terminal list` 里（`Lost`，界面标签和侧栏照旧写记下的名字，状态是空心带横线的蜂巢格「未恢复」，侧栏照常列出 agent 会话）；手机不列，它的会话流每 500ms 按会话 ID 找终端，列出来就会被拉起。用户关掉的终端马上记成退出，程序自己退出的等 5 秒（`resumeSettle`）再记：关机时不在交互式 shell 里的命令可能比常驻进程先收到 SIGTERM。第一次在界面接入或用 CLI 操作它时按原来的 ID、名字和创建时间拉起：有会话的 agent 用 `launcher.Resume` 续接，没有会话的新开一个，关掉了的 agent 和普通终端在记下的目录开 shell，第一行打「Posse 已恢复上次的终端」；关掉还没恢复的只删记录，改名只改记录，hook、任务、Git 记录、手机不会把它拉起。恢复信息在 hook 到达和每 2 秒的 agent 检查时写库，不在 PTY 读协程里写。agent 退出后要等 5 秒（`resumeSettle`）才从记录上摘掉：关机时 agent 和常驻进程差不多同时收到 SIGTERM，agent 先退出不能把要续接的会话清掉。设置「通用 › 恢复终端」打开后（`agents.json` 的 `restoreAll`）常驻进程一启动就全部恢复，交接过来的进程不自动恢复。任务不续接，照旧记 lost，用 `task retry` 重派。
- agent 操作网页（`posse web`，说明在 `posse web guide`，源文件 `internal/cli/web_guide.md`）：网页标签在窗口进程里，CLI 直接连窗口进程的 `$POSSE_HOME/app.sock`（`internal/app/webctl.go`，权限 0600，同一 home 已有窗口进程在接就不接管，没人应答的残留文件删掉重建），常驻进程不参与，窗口没开时回 `no_window`、不替它拉起窗口。命令作用于调用方所在工作区（`POSSE_WORKSPACE_ID`，不在 Posse 终端里时用侧栏选中的，`--workspace` 指定）的网页标签，有多个时默认最近显示过的，`--tab` 按编号指定；`open` 新开并切到这个标签，不抢键盘。`snapshot`、`click`、`fill`、`press`、`console` 调页面里的 `window.__posse`（`internal/app/webctl.js`，每次随 Eval 带上，页面载入时也经 `PreloadScript` 注入，console 从页面自己的脚本之前开始记，最多 200 条）：snapshot 列可见的可交互元素和标题、地标，ref 写在元素的 `data-posse-ref` 上，再次 snapshot 不变；点击、按键是脚本派发的 DOM 事件，Enter 提交表单、Tab 换焦点这几样默认动作由脚本补上。只看主 frame，iframe 里的元素和输出看不到。从没显示过的标签（工作区在窗口里没选中过）没有尺寸，截图报错，别的命令照常。`posse web device <机型|off>` 开关手机预览（和工具栏的手机按钮一样，见 `ui.md`），开着时截图是机型大小的画面。

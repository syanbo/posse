# agent 识别、编排与会话标题

hooks 之外的 agent 识别、手动启动的 hooks、多 agent 编排（`hive task`）、会话标题、编排技能注入、权限、各家状态细节。

- 终端里的 agent 不只看启动参数：每次标题变化时取 PTY 的前台进程组（`Terminal.Foreground`），按它的 argv 认出 agent（`agent.FromProcess`），和记录的不同就换过来、清掉旧会话信息（`session.detectAgent`）。这样在 grok 退出后的 shell 里手动敲 `claude`，图标和状态都跟着变。没有经过下面同名脚本启动的（grok，或脚本没生效时）没有 hooks，状态只靠标题（`agent.TitleOnlyStatus`：Claude 以 `✳` 开头是空闲，转动的圆形符号是工作中）。前台换成 shell、编辑器等不是 agent 的程序时不改，免得 agent 临时让出前台被当成退出。agent 退出时把它从终端上摘掉，终端退回普通 shell（侧栏不再列出，标签换回终端图标）：收到退出事件（Claude 的 SessionEnd 带 `prompt_input_exit` 等、Codex/Cursor 的 SessionEnd），或记下的 agent 进程组组长已经不在、exec 成了别的程序（`session.goneAgentPg`，标题变化时和每 2 秒查一次，崩溃、被杀、没有 hooks 的 agent 靠它）。
- 手动启动也带 hooks（`internal/agent/manual.go`）：常驻进程写出 `$HIVE_HOME/bin/{claude,codex,cursor-agent}`，转给 `hive agent exec <命令> --`，它在 PATH 里跳过这个目录找到真正的程序，按 `ManualArgs` 补上和界面启动一样的参数（Claude 不指定 `--session-id`，会话 ID 由 hooks 报上来），环境里加 `HIVE_AGENT_SHIM=1` 后 exec 过去。`-p`、`exec`、`mcp`、`login` 这类非交互、管理用法原样运行；环境里已经有 `HIVE_AGENT_SHIM`（agent 自己跑工具时再调）或不在 hive 终端里也原样运行。用户的 `.zshrc` 常把 `~/.local/bin` 插到 PATH 最前，所以照 Ghostty 的 shell 集成：zsh 终端带 `ZDOTDIR=$HIVE_HOME/shell/zsh`，那里的 `.zshenv` 先还原用户的 ZDOTDIR（`HIVE_USER_ZDOTDIR`）、读用户的 `.zshenv`，再加一个 precmd 每次出提示符前把 `$HIVE_HOME/bin` 挪回最前；之后的 `.zprofile`、`.zshrc` 照常从用户目录读。agent 退出后 `exec` 回的 zsh 经 `HIVE_ZDOTDIR` 再走一次集成（`ShellArgv`）。用户手动开的嵌套 zsh、bash、fish 不走集成。收到 hook 事件时常驻进程按它记 agent 并标成有 hooks（`session.markHooked`）。改了脚本或集成文件要重启常驻进程，之后新开的终端才生效。
- 多 agent 编排（`hive task`）：派发方是调用方所在的终端（`HIVE_TERMINAL_ID`），为空表示用户（界面或终端之外）。worker 是新开的 agent 终端，带 `HIVE_TASK_ID`，启动提示由 `workerPrompt` 生成，写明 `hive task ask/check/done` 的用法。`ask/check/done` 只接受 worker 自己的终端，`reply/send/close` 只接受派发方，用户（调用方为空）可以接手任何任务。
- 派发方的收件箱是 question/done/exit 三类消息，worker 的是 answer/note。派发方 agent 空闲（hooks 或标题报告 idle，或主线程停着、只有后台子 agent 在跑）且 5 秒内没有人键入时，hive 往它终端里输入一行 `Hive: … Run \`hive task inbox\` to read.` 并回车；每条消息只提醒一次。worker 终端或其中的 agent 没汇报就退出时，任务记为 exited 并通知派发方；`task close` 先改状态再关终端，不算意外退出。常驻进程重启时还在进行的任务记为 lost。
- worker 最多嵌套 3 层。`hive task guide` 是给协调方 agent 看的说明（源文件 `internal/cli/task_guide.md`，测试限制在 80 行以内），`--skill` 输出带 frontmatter 的 SKILL.md。`hive task retry` 在 CLI 里组合 show 和 start，用原任务的说明、agent 和工作区重派，只接受 failed、exited、lost、stopped 的任务。
- 会话标题（`hive session title`，规则在 `hive session guide`，源文件 `internal/cli/session_guide.md`）：取代原来独立的 session-namer 技能。用户调用技能 `session-namer`（Claude 里是插件技能 `/hive:session-namer`，只能由用户调用）或让 Codex、Grok 起名时，agent 读指南、拟 `MMDD｜类型｜摘要`（类型限 修复 feat 调研 调试 重构 文档 杂项，摘要不超过 20 字），在自己的终端里运行命令；常驻进程（`internal/daemon/title.go`）规整格式（日期换成今天、类型同义词换成标准写法），按终端里的 agent 写：Claude 只认 UserPromptSubmit hook 返回的 sessionTitle，先记成待交，下一次提交时由 hive hook 交过去（Claude 随后写 `custom-title`、改终端标题）；Codex 照它的 /rename 写 state 库 `threads`（paginated 写 name、旧格式写 title）并追加 `session_index.jsonl`；Grok 写会话目录 `summary.json` 的 `generated_title`、`session_summary` 并置 `title_is_manual`；Cursor 没有核实过能写的地方，只在 Hive 里显示。会话 ID 优先用命令环境里 agent 注入的（`CLAUDE_CODE_SESSION_ID`、`CODEX_THREAD_ID`、`GROK_SESSION_ID`），没有再用常驻进程记下的。标题记在终端的 agent 状态上（`AgentState.Title`、`TitlePending`，交接时随记录带过去），同一个会话的后续事件沿用、换了会话就清掉；界面的标签、侧栏和手机的标签名用它代替终端标题。写 Codex、Grok 的存储是"只读各 agent 的会话目录"之外的另一个例外。
- 编排技能 `hive-tasks` 随 agent 启动按会话注入，不写全局目录，正文都指向 `hive task guide`（技能文本在 `internal/agent/skill.go`）：Claude 加 `--plugin-dir $HIVE_HOME/claude-plugin`（hive 生成的插件，含这个技能和 session-namer，内容没变不重写；Cursor 的插件同样带这两个技能）；Codex 和 Grok 没有按会话加载技能的办法，分别用 `-c developer_instructions=…` 和 `--rules` 放一句指路（编排、会话命名各一句）。`-c` 会整个替换 developer_instructions，用户的 `config.toml` 里设了它时不注入。这些参数由常驻进程生成，改了要重启常驻进程，之后新开的 agent 才带上。
- agent 权限照 Orca 的 Agent Permissions（`internal/agent/permission.go`）：默认跳过审批，界面启动、恢复会话、任务 worker 和手动敲的 claude/codex/cursor-agent 都带上各家的跳过参数（Claude `--dangerously-skip-permissions`、Codex `--dangerously-bypass-approvals-and-sandbox`、Grok `--permission-mode bypassPermissions`、Cursor `--yolo`）；手动启动时用户自己带了权限参数（`--permission-mode`、`-a`、`-s`、`--force` 等）就不补。设置页的「agent 权限」可改成逐项确认，档位存在 `$HIVE_HOME/agents.json`（窗口进程直接写），每次启动 agent 时读，改了不用重启常驻进程，已经在运行的不变。跳过审批时 Claude 不会发 PermissionRequest，手机审批用不上。
- Claude 的后台子 agent：主线程 Stop 带着 `background_tasks`，其中还在跑的 subagent、teammate、workflow 记在 `AgentState.Subagents`（交接时随记录带过去），不为空时这次 Stop（以及 Esc 后标题回到 `✳`）不算本轮完成，仍是工作中：防休眠、`terminal wait --for idle`、界面和手机都按工作中，但主线程已经回到输入框（`agent.Parked`），task 提醒照常输入。后台 shell、monitor 不算（dev server 会一直挂着）。子 agent 结束时 Claude 先发 SubagentStop（带 `agent_id`，从列表划掉），再自己开一轮处理结果（UserPromptSubmit 带 `<task-notification>`），那一轮的 Stop 才是完成；最后一个划掉后 20 秒没有新的主线程事件（子 agent 被停掉等）也按完成算。后台子 agent 不发 SubagentStart（Claude Code 2.1.306 实测），所以还在跑的以 Stop 为准；子 agent 里的工具事件带 `agent_id`，不改主线程的状态。
- grok 不注入 hooks（只能写进 `~/.grok/hooks`），状态靠终端标题：盲文转圈符开头是工作中，含 Action Required 是待处理，其余是空闲。
- Cursor（`cursor-agent`）的状态：beforeSubmitPrompt 和工具事件是工作中，stop 是空闲，sessionEnd 是退出；sessionStart 不改状态（命令行带初始提示时第一轮不发 beforeSubmitPrompt）。会话 ID 不能预先指定，由 hook 报上来。Cursor 没有"等待批准"的事件，标题只是会话名，待处理目前认不出来。

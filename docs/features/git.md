# Git 界面

照 WebStorm 做的 Git 界面。按 WebStorm 里的使用统计，提交多半由 agent 做，用得多的是看改动、比较分支、同步和整理分支，界面以这些为重心。本机读取和未迁移的写操作仍在窗口进程里调系统 git（约定见 AGENTS.md）。远程工作区的仓库发现、状态和分支列表已接目标 daemon，只读查看包含分支、标签、改动与储藏，窗口基础接线已通过定向 race、生产视图测试和 Grok 独立验收。文件版本读取、diff 与编辑器改动基线已接目标服务并通过回归、复审及 Grok 独立验收；日志列表、提交详情和文件历史已通过回归、复审及 Grok 独立验收；逐行追溯已通过回归、复审及 Grok 独立验收；固定分支比较已通过回归、复审及 Grok 独立验收，工作树比较已通过回归、复审及 Grok 独立验收；推送预览已接目标服务并通过回归、复审修复及 Grok 独立验收；worktree 基准关系与冲突预测已接目标服务并通过回归、独立审查及 Grok 验收，无法可靠预测时明确显示原因。手动 Fetch 已接目标服务，通过回归、审查修复和 Cursor 独立验收：未知结果可按原操作查询，明确确认后才另开新操作；取消或失败可能已更新部分引用。目标 Fetch 操作记录仅保留本次窗口的有界历史。自动 Fetch 也复用目标服务，仅在持有控制且工作区显示时执行；未知结果只查原操作，不自动重发。实际 Push 已接目标服务：本机与远端都按已显示的预览执行，锁内核对基线，未知结果查询原操作。更新项目和其他本地分支已接目标服务，固定提交和上游后在写锁内复查；检出分支、检出修订、新建、重命名、删除和恢复分支也通过目标 `git.branch` 核对点击时的 OID 后执行。暂存、取消暂存、文件与逐段回滚、接受冲突一边和标记已解决经目标 `git.paths` 执行，覆盖内容前核对文件版本和 HEAD。部分提交、修改上一次提交和提交一处改动经目标 `git.commit` 执行，锁内核对 HEAD、索引摘要和工作区文件版本。储藏的存入、应用、弹出和删除经目标 `git.stash`，固定 OID 并在共享仓库锁内复查。合并、变基、检出并变基、Cherry-pick、还原及进行中的继续、跳过、中止经目标 `git.integrate`。历史改写经 `git.history`，worktree 同步复用 merge/rebase，合并回项目经已接受的 `workspace.merge`。窗口主机菜单已接入，接口边界及验证状态见 [SSH 远程工作区](remote.md)。

- 一个工作区里的多个仓库：文件栏打开时（或状态栏要画分支按钮时）找出工作区里所有的仓库（`gitx.Discover`）：工作区所在的仓库，以及下面的仓库，不限深度，跟着指向目录的软链走（`Works` 这种全是软链的目录也认得）。普通目录一直往下找，碰到仓库就不再往里走，仓库里面交给 git：没被忽略的未跟踪目录里的仓库（多深都找，照外层的忽略规则，里面指向别处仓库的软链也跟）、子模块（含没有 `.gitmodules` 的）、仓库里指向别的仓库的软链；被外层 `.gitignore` 忽略的嵌套仓库不算（`.fvm/flutter_sdk`、`ios/.symlinks/plugins`、`node_modules` 里的 git 依赖都在这一类）。跳过点目录和 `node_modules`、`Pods`、`build` 这类目录，跳过指向工作区自己或上级的软链，同一个仓库经两条软链进来只算一个（它里面的仓库也认两种写法）；工作区是指向仓库子目录的软链时按真实路径找外围仓库，仓库根目录照 git 给的真实路径写，按文件的功能在工作区的写法和真实路径之间换算（手机按真实路径算 `sub`）。只用查询命令，不进操作记录。普通目录最多走 2 万个、5 秒，读取预算用完也停。这两种都在改动页写"目录太大，没扫完"，不在侧栏报错，之后不再自动重找，刷新按钮重找；没撞上的每分钟、或工作区目录本身变了时重找。同一条后台发现失败关掉之后，到点重试不再把侧栏提示弹回来。
  - 当前仓库：分支按钮和分支弹窗、日志浮层里整个仓库的日志、改动页顶上一行（日志、回滚、储藏按钮）和储藏分页对着当前仓库。它跟着当前标签走（切到别的仓库的文件，或 diff、比较是别的仓库的），文件栏开着之前是工作区所在的仓库或第一个；也可以手动换：改动页顶上和分支弹窗最上面的仓库名、日志左边分支树最上面的"仓库"组（文件历史不列，对着文件所在的仓库）。手动换的留着，直到再切到别的标签。分支按钮写"仓库名 · 分支"，所有仓库在同一个分支上时只写分支。diff、比较、文件历史、Annotate、回滚和推送对话框各自记着自己的仓库，当前仓库换了照样对着原来的仓库，操作也在那个仓库里执行；重找后仓库没了，对它的操作报错。
  - 按文件的功能按文件所在的仓库算（嵌套时取最里面的）：编辑器行号旁的改动、文件历史、Annotate、回滚这个文件、文件树的标记（有改动的仓库目录和上面的普通目录也标）。快速打开和检索的文件清单各仓库按自己的忽略规则列，仓库外面的普通目录照常遍历。外层仓库不再把找到的嵌套仓库列成未跟踪的目录。
  - 改动页按仓库分组，只列有改动的仓库：仓库标题行有展开箭头、整个仓库的勾选、仓库名和文件数，右边是分支和传入传出；右键回滚、看日志、在访达中显示。下面是各自的冲突、改动、未跟踪，↑↓ 跨仓库走。提交信息只有一份：勾了几个仓库的文件时按钮写"提交 N 个文件到 M 个仓库"，用同一条信息在各仓库分别提交；全部成功才清空信息，失败的仓库报错、留着勾选，成功的仓库勾选清掉，改好再点只提交剩下的。"修改上一次提交"只在一个仓库有勾选时能勾（都没勾时是当前仓库）；合并、Cherry-pick 进行中的仓库按自己的规则整体提交。合并、rebase 停在冲突上的横幅和本地改动没取回的横幅每个仓库各一条，开头写仓库名。顶上的回滚和 ⌥⌘Z 对着当前仓库，它没改动时对着第一个有改动的仓库。
  - 操作记录：终端里在软链过去的仓库里跑的 git 命令（trace2 给的是真实路径，在工作区外面）按找到的仓库的真实路径归到工作区。
  - 读状态：当前仓库照旧 1.5 秒读一次，其余仓库 10 秒读状态与只读索引摘要；操作结束后马上重读它所在的仓库。自动 fetch 只拉当前仓库，同一项目的 worktree 里同一位置的仓库共用计时。
  - worktree 工作区：项目目录本身不是仓库、下面有仓库时（`Works` 这种），新建工作区对话框列出找到的仓库，默认勾上正在看的那个；勾了就在 `$POSSE_HOME/worktrees/<项目>/<名称>` 下按原来的相对位置给每个勾上的仓库建一个 worktree（嵌套的放在外层的 worktree 里，软链过去的建在软链的位置），各仓库同一个分支名、从各自当时的分支开出来，记在工作区的 `repos` 里；都不勾是同一目录上的工作区。工作区里只有这些仓库，项目目录里别的文件不带过去。CLI 是 `workspace create <项目> <名称> --repos a,b`，`task start --worktree` 同样带 `--repos`，派发方本身在多仓库的 worktree 里时 worker 拿同样的几个仓库。分支弹窗的"基于它新建工作区"在当前仓库不是项目目录那个时只给当前仓库建。建到一半失败（分支在别处检出等）时撤掉已建的 worktree 和新开的分支。`workspace diff` 给各仓库的改动和合计；`workspace merge`（侧栏右键"合并回各仓库…"、任务总览的按钮）把各仓库合进检出了它基准分支的那个 worktree（一般是项目里的仓库；从多仓库工作区派出去的 worker 基准是派发方的分支，合进派发方的工作区），先查完所有仓库，有一个有未提交的改动、没有哪里检出基准分支、那里有改动或合并会冲突（merge-tree 预测，预测不了也算）就一个都不合，没有新提交的跳过；删工作区先查所有仓库的未提交改动（放在外层里的内层 worktree 不算外层的未跟踪文件），再从里往外逐个删，工作区目录里还有别的文件时不带 `--force` 留着目录并说一声。`workspace list --dirty` 逐个仓库查。工作区根目录不是仓库，侧栏、手机列表的分支和重新指定目录都不从根目录读 HEAD，用记下的共用分支。这种工作区没有单一的基准分支，改动页的"相对 main"、同步和冲突预测不出现。
  - 项目右键菜单的"识别多个 Git 仓库"（默认开，存在项目记录里，CLI 是 `project set <项目> --multi-repo on|off`）：关掉后只认工作区所在的那一个仓库，和以前一样。
- 改动页（文件栏"改动"）：
  - 刷新：文件栏或文件标签看得见时每 1.5 秒读一次 `git status`。有改动时分段上的"改动"后面挂一个强调色的数（有改动的文件数，不含储藏），切在文件页也看得见。
  - 文件名照 WebStorm 上色、不画状态字母（改动页、回滚对话框、提交和比较里的文件、文件树同一套）：修改和重命名蓝、新增绿、删除灰（加删除线）、未加入 Git 使用 WebStorm 内置未跟踪红（浅色 `#B23247`、深色 `#E88F89`），冲突用错误红，悬停文件名显示状态（比较里第二行是完整路径）。文件名前是和文件树一样按类型的文件图标（删除的文件图标也变灰），目录行是文件夹；子模块和未跟踪的嵌套仓库（git 报成 `nested/`）画成目录、名字不带斜杠；文件历史的标题也带图标。
  - 手机改动页的目录列表和平铺列表沿用桌面文件名配色（深浅主题相同）：新增绿、修改和重命名蓝、删除灰并加删除线、未跟踪和冲突红。状态先认未跟踪、冲突，再取工作区状态；工作区没变才取暂存区状态，因此暂存新增后继续修改显示蓝色，暂存重命名后删除显示灰色。手机普通文件页通过 `files.tree` 使用与桌面共享的文件树标记：已暂存新增、未跟踪、冲突保留各自状态，其余改动和含改动的普通父目录统一标蓝，被忽略项淡化；多仓和软链规则也共用，详见 `mobile.md`。
  - 提交：照 WebStorm 不分暂存和未暂存，每个文件一个勾选框（已跟踪的默认勾、新文件默认不勾），只提交勾选的文件，暂存区里没勾的原样留着。合并、Cherry-pick、还原进行中 git 不许部分提交，这时按钮是"提交合并结果""提交 Cherry-pick 结果""提交还原结果"，勾选的文件连同已加入 Git 的一起整体提交。
  - 冲突、改动、未跟踪各组可以点标题展开收起（不记进 ui.json；收起的组 F7 照样能跳到）。分页右边的文件夹按钮切换"按目录分组"（ui.json 的 `changesByDir`）：各组的文件和回滚对话框一样排成目录树，目录行可以收起（不记）、整个勾选，右键回滚整个目录。
  - 储藏：改动页分"提交"和"储藏"两个分页。储藏就是 `git stash`（含未跟踪文件，顶上的按钮先问说明、可以留空），储藏分页单击一条有弹出（取回并删掉）、应用（储藏留着）、删除。储藏是所有 worktree 共用的：别的分支存的标出分支名，弹出、应用前确认，检出那个分支且位于同一主机的工作区在菜单里能直接切过去。WebStorm 的"搁置"（IDE 自己存的补丁，终端里的 agent 看不到）不做。
- 改动卡片：编辑器行号旁标出相对 HEAD 的改动，⌥⌘Z 回滚一段；点色条弹出改动卡片（照 WebStorm 的 gutter 弹窗排成一行）：上一处 / 下一处、回滚这一处（改的是编辑器里的内容，可撤销，保存才写盘）、显示 diff、复制改之前的内容、"提交此更改"（回车只提交这一处，钩子照常执行，其余改动留在工作区；有没保存的改动、这个文件有已暂存的改动、合并进行中时不做），下面是改之前的内容，Esc 或点外面关。
- 回滚：改动页顶上的回滚按钮（焦点在改动页时 ⌥⌘Z）打开批量回滚对话框，文件按目录排成树（只有一个子目录的中间层并成一行，目录可收起、可整个勾选），默认勾提交时勾着的文件。点文件名在对话框上面另开一个 diff 浮窗，F7 / ⇧F7 跨文件，"包含在回滚中"就是文件树里的勾选，顶栏的"回滚这一处"（⌥⌘Z）立刻写回磁盘，Esc 只关 diff 浮窗。新文件（未跟踪、刚加入 Git）勾了"同时删除新文件"才删，否则刚加入的移出暂存区、未跟踪的不动。单个文件的回滚（diff 栏和编辑器顶栏的"回滚这个文件"、改动列表右键的"回滚…"）也打开这个对话框，只勾这个文件，是新文件时默认勾上"同时删除新文件"。diff 栏回滚后换到同一组的下一个文件，没有了就关掉 diff；编辑器顶栏回滚后按磁盘重载，没保存的改动一起丢掉，新文件删掉后关掉标签。
- 回滚对话框、它的 diff 浮窗和 Push 对话框可以拖标题移动、拖四边四角拉伸，同一次运行里再打开沿用尺寸，位置每次回到居中。Push 对话框标题右边有关闭；提交列表和右边的分栏可以左右拖，宽度记在 ui.json 的 `pushListWidth`。进行中的推送状态、查询和取消留在底部按钮那一排，不插在列表上面。
- diff：每个工作区只有一个 diff 标签，打开别的文件换掉里面的内容，排版和忽略空白沿用。默认左右对照、忽略空白（只忽略空白，不忽略空行）。上方的路径点开是同一组文件的菜单，F7 / ⇧F7（diff 栏最左边的上下箭头）跨文件跳改动，到头了在 diff 栏正下方提示"已经是第一处 / 最后一处改动"。左右对照的分界线能拖，所有 diff 共用一个位置（ui.json 的 `diffSplit`）。F4 跳到编辑器。工作区 diff 可以逐段回滚，立刻写回磁盘：左右对照时照 WebStorm 两列行号挨着分隔线，左栏行号左边给每处改动放 `>>`，上下合并时悬停的那处右边有"回滚"。diff、比较和日志浮层里打开的文档不轮询磁盘、不记进 ui.json。
  - 图片（png/jpg/gif/webp）的 diff 左右对照两张图，各标版本、像素尺寸和文件大小，透明处垫棋盘格；新增的一边写新文件、删除的写已删除。动图两边各自播放，标出帧数（和文件标签的图片同一套，见 `files.md`）。
  - 比较在后台做：超过 1 MB 的先显示"正在比较…"，切换忽略空白也在后台重比、算完再换；超过 20 MB 的先不比较，写两边的大小和行数，点"仍要比较"照样在后台比。比较大文件临时要的内存比完就还给系统，大 diff 开着时每 15 秒主动 GC 一次（`diffmem.go`）。
- Annotate：照 WebStorm 在文件自己的标签里开关，不另开标签：开着时显示逐行作者，顶栏的"关闭 Annotate"切回编辑器。当前分支的 HEAD 变了之后重读，选中的提交如果已经不在结果里就收起。
- worktree 工作区相对基准分支（建工作区时记下的）：改动页分支行下面一行写"相对 main"、基准分支上的新提交数、待合回的提交数；两边都有新提交时预测冲突文件（不碰工作区和暂存区，不进操作记录）。和传入、传出一起每 10 秒算，分支按钮的悬停提示也写。"同步"在 worktree 里把基准分支合并进来或 rebase 上去，停在冲突上不报错，用改动页的横幅解决。"合并"、侧栏 worktree 右键的"合并到 main…"、任务总览的合并按钮：预测到冲突时不去试，引导先同步；有桌面身份时预测不可用也不尝试合并，多仓库由目标 daemon 一次检查全部仓库。合并成功后仅原连接仍为控制端时询问是否删除工作区；目标结果没有未跟踪文件列表时不在本机扫描远端路径，使用不带列表的原说明。无身份旧窗口保留本机预测、失败后的冲突引导和未跟踪文件列表。
- 分支比较照 WebStorm 上下两栏，各是一边独有的提交，打开时收起底部的日志浮层（它会盖住下半截）。默认各占一半，拖中间的分隔线调比例（所有比较共用，ui.json 的 `compareSplit`）；两边分支各一种颜色，标题里的分支名和提交圆点同色；没有单独的顶栏，Cherry-pick、交换两边、刷新放在上一栏标题行的右边。每栏标题行最左边有自己的搜索框，按提交信息、作者（不分大小写）或哈希前缀只筛这一栏、两栏互不影响，标题里的数目写成"显示 / 全部"。提交照 WebStorm 点选：单击选一个，⌘ 点加上或去掉，⇧ 点选上一段，多选只在同一边里，右边看最后点的那个。Cherry-pick 把选中的提交按提交先后应用到当前分支（中途冲突停下，解决后接着应用剩下的）：只有都是另一边独有的提交、且另一边正是工作区检出的分支时可点，agent 正在这个工作区工作时先确认。Fetch、更新或推送之后比较会重读；当时 diff 标签开着的如果正是某一边移动前的顶端提交，就改看新顶端里的同一个文件，右边选中的提交一起跟上，更早的提交保持不动。
- 分支按钮和 Git 日志开关默认在底部状态栏的最左端（分支名长时标签栏放不下），只在工作区的主界面显示；套餐用量靠右，挨着内存。设置页「外观」→「界面」卡片里的「分支和 Git 日志」可改回「标签栏」（ui.json 的 `gitInTabBar`）：两个按钮回到右上角那一格标签栏的右端、文件栏开关前面，套餐用量回到状态栏左端。分支弹窗：点分支名，在状态栏时弹窗从按钮上方弹出、贴着左边，拖右边缘调宽；在标签栏时从按钮下方弹出、贴着右边，拖左边缘调宽；宽度两处共用（360 到 800，默认 420，ui.json 的 `branchPopWidth`）；⌥⌘N 新建分支，⇧⌘K Push（WebStorm 的 ⌘T 更新项目和 posse 的新建终端冲突，放进弹窗）。更新当前分支是 `pull --rebase --autostash`，其他分支只快进。被另一个 worktree 检出的分支照 WebStorm 留在"本地"组里：是 posse 工作区的，右边写"在 <工作区>"，检出改成切到那个工作区；不是 posse 建的，右边写"worktree · <目录名>"（悬停看完整路径），菜单里是"在 Posse 中打开"（回车也是）、"在访达中显示 worktree"和"复制 worktree 路径"。"基于它新建工作区"走 posse 的 worktree 工作区。检出、rebase、合并、更新、reset 之类改动工作目录的操作，工作区里有 agent 正在工作时先确认。更新项目、更新分支、删除分支做完弹窗不关。更新进行中时「更新项目」和分支菜单的「更新」在原处转圈，点正在跑的那一次是取消，不另插一行，免得列表跳动；删除仍用忙碌行。传入数和分支列表就地刷新；其他操作要去别的界面或对话框，点了就关。
- 别处建的 worktree："在 Posse 中打开"把它加成项目的工作区（名字取目录名，重名加 -2，CLI 是 `workspace create <项目> <名称> --mode attach --path <目录>`）并切过去，要求它是这个仓库的 worktree、还没有工作区；侧栏和空工作区页和 posse 建的一样画分支图标。它的目录名常和仓库同名，所以侧栏、标题显示它当前的分支（`workspace.Shown`，窗口每秒读 HEAD，游离时用原名），存的名字不变，CLI 照旧认原名。
- 工作区目录不见了：worktree 工作区的目录在外面被删掉后，窗口发现就删掉记录、清掉 git 的 worktree 记录（分支不再算检出在那里），提示"目录已删除，移除了工作区 …"；里面还有终端在跑的等终端退出再删，上一级目录也不在的（外接盘没挂上）不动。没被自动删掉的（上一级目录也不在、终端还在跑，或者项目目录本身不在了）窗口每秒查一次目录，侧栏行尾写"目录不存在"、不再显示旧分支，分支按钮和日志浮层收起，文件栏不再去读；空工作区页换成说明卡片，开着终端或文件时标签栏下面一条提示，两处都有"重新指定目录…"（`workspace.relocate`：git 项目要求是仓库根目录、worktree 还要是这个仓库的，改完跑 `git worktree repair`；主工作区连项目目录和同目录的工作区一起改）和"从 Posse 移除…"（只删记录、清掉 git 的 worktree 记录，不删分支；主工作区是移除项目）。
- 项目目录找不到（被删、挪走，或者所在的磁盘没挂载）而 worktree 工作区的目录还在：git 删不了这个 worktree，也查不了里面有没有没提交的改动。删这种工作区、删项目时确认框写明找不到项目目录和要删的目录，两个动作：「只移除」（默认，回车按它）只删记录、目录留着，「连同目录删除」连 `$POSSE_HOME/worktrees` 里的目录一起删（记录指到外面的不碰）；目录本来不在或是空的直接算删掉了。项目目录找不到时删项目会连同它的 worktree 工作区一起移除。CLI 是 `workspace rm --force` 和 `project rm --force`：只删记录，打印留下的目录，加 `--discard-files` 才删目录（`--json` 的 `left`、`repoGone`）；不带 `--force` 时报错并提示可以加。手机没有删工作区的入口。
- 带桌面身份的更新项目和更新分支通过已接受的 `git.update` 执行；没有桌面身份的旧测试窗口保留 `gitx.Update`。请求固定工作区登记、仓库身份、本地分支名、上游、提交 OID 和点击时是否为当前分支；当前分支使用已读取状态的 OID，其他分支使用列表中的 OID。与 Fetch 共用仓库写锁，锁内任一项不符即返回冲突且不执行。当前分支只执行 `pull --rebase --autostash`；其他本地分支不得已检出，只执行无强制选项的 `fetch <remote> <branch>:refs/heads/<name>`，分叉失败不会改写分支。
  - pull 的 rebase 冲突按失败处理，保留现场供原状态横幅显示；不自动继续、跳过或中止。pull 成功但新出现的 autostash 未恢复时仍为成功，结果带储藏哈希和冲突标记，打开改动页并沿用原横幅。成功提示的提交数在目标按更新前 OID 与更新后的上游引用计算。
  - 关闭弹窗、断线和失去控制不取消已接受的更新；回复丢失只查询原操作，未知结果后另开更新必须确认。取消使用当前控制身份和原标识，回执不等于完成或回滚。运行中和结果未知时占住仓库，本机后续 Git 操作排队，终态后续跑原队列；远端未迁移的 重命名与目录传输闭包仍由 `git.write` 拒绝，不入队。原有 agent 工作确认固定发起时的 OID 与控制身份。更新结果和净化日志留在本次窗口的操作记录中。
- 带桌面身份的分支检出、修订检出、新建、重命名、本地删除与恢复、远端删除通过已接受的 `git.branch` 执行。参数固定工作区登记、仓库身份和点击时的提交 OID，在 Fetch 共用的路径/common-dir 写锁内复查，与文件保存互斥。无桌面身份的旧测试窗口保留原 `gitx` 调用；手机 checkout 协议不变。
  - 本地检出核对分支 OID 和 worktree 占用，只用 `switch <name>`；已经在当前分支且 OID 一致时不执行命令。远端按第一个 `/` 分出本地名：已有同名本地分支时同时核对本地和跟踪 OID，只切换本地分支；点击时不存在则必须仍不存在，才用 `switch --track <remote>/<branch>`，不先 fetch。修订在锁内解析为提交，已有预期 OID 时必须相符，只将解析后的 OID 交给 `switch --detach`。
  - 新建固定 `FromOID`，空起点取点击时已读取的 HEAD 提交，分离 HEAD 也可用；只执行 `branch <name> <oid>` 或 `switch -c <name> <oid>`，重名冲突。重命名仅限本地分支，核对原分支 OID、未被其他 worktree 检出且新名字不存在后执行 `branch -m <old> <new>`。删除本地分支核对 OID，拒绝当前分支及任何 worktree 检出的分支；默认 `branch -d`，未合并且引用未变时交回确认结果，不报失败或部分更新。强制确认另开一次操作，仍核对原 OID 后执行 `branch -D`。成功后保留原“已删除 / 恢复”提示，恢复在目标端从删除结果的 OID 新建、不检出，不覆盖重现的同名分支。检出、新建和重命名成功仅刷新，不新增提示。
  - 远端删除先确认，锁内核对跟踪 OID，再执行 `push --force-with-lease=refs/heads/<branch>:<oid> <remote> --delete <branch>`；分支名独立传参，`+` 开头不成为强制 refspec，无单独的 `--force`，不 fetch 或 prune。租约不符则拒绝删除，本地跟踪引用保持不动。
  - 查看端隐藏这些操作，直接调用也不打开对话框、不发送、不调用本机 Git。控制端的搜索回车同样走检出入口；已在列出的 Posse 工作区检出的分支切换工作区，外部 worktree 支持经目标 `workspace.create` 打开或从分支新建工作区，远端不调本机访达。改工作目录的动作继续使用 agent 工作确认，确认绑定 OID、仓库和控制代次，变化后不发送。
  - 请求超时十分钟；断线、关闭弹窗和失控不取消已接受操作，丢失回复只查询原 ref 和原参数，另开操作必须确认。运行中和未知结果占住仓库，本机旧 Git 操作进入原队列；确认另开时先续跑旧队列，再重新核对分支操作。取消使用当前控制身份和原 ref，回执不等于完成或回滚。结果及净化日志沿用有界操作记录。
- 自动 fetch：当前工作区主界面的分支按钮画出来时，每 5 分钟在后台 `fetch --all` 一次（打开后先拉一次）；同一项目、相同仓库相对路径的 worktree 共用计时。有桌面身份的本机与远端窗口都必须当前身份有效并持有控制，复用已发现的仓库身份，经目标 `git.fetch` 执行；没有桌面身份的旧测试窗口仍走本机 `gitx.Fetch`。查看、释放、断线、切主机或设置/讨论等页面盖住工作区时不发起。搜索框旁的手动 Fetch 还要这次控制下的仓库发现仍然有效；发现过期时分支按钮会重新发现（文件栏关着也一样），完成前按钮禁用，点击没有反应。Fetch 进行中时搜索框旁的按钮换成转圈，点一下取消；Fetch 状态行只在结果未知（带查询原操作、刷新当前状态、取消）、失败或部分更新、报错时出现，进行中和成功都不写字。上一次 Fetch 已有结果、仓库若仍被 Fetch 占着，弹窗照常显示忙碌行。身份未就绪、仓库忙或记录容量不足时短暂等待再试，不占用五分钟计时；常驻进程交接中被目标以忙碌拒绝时不显示失败，5 秒后再试。
  - 已接受的自动 Fetch 不因切走或失去控制而取消；回复丢失只查询原操作，未知结果继续占用仓库，不弹另开操作的确认，也不重发。进行中同一项目、同一位置仓库的手动 Git 排队，后来打开的工作区也一样。取消沿用现有 Fetch 入口，取消不承诺回滚；已知失败不弹提示或写错误条，等下个五分钟间隔。成功刷新同项目里依赖引用的分支按钮、分支弹窗、比较、日志等界面，不弹“已获取”。传入、传出提交数仍每 10 秒读取已有引用；远端使用目标读取，不调用本机 Git。
- Git 日志：照 WebStorm 底部的 Git 工具窗口，是从终端那一栏底边滑上来的浮层，盖在终端上、不改终端尺寸，也不盖右边的文件栏；点别处不收，只有浮层右上角的隐藏按钮、⌘9 和分支按钮右边的日志按钮开关。顶上一排小标签：整个仓库的"提交日志"（不能关）、"操作记录"和文件历史（可以关），不进标签栏、不记进 ui.json。拖上边缘调高度（至少给终端留 120），开关按项目记在 ui.json 的 `logPanels`，高度所有项目共用。
  - 每行是提交图、标题、分支和标签、作者、时间。提交图照 WebStorm（IntelliJ 社区版 `platform/vcs-log`，`internal/app/loggraph.go`）：从各分支头往下深度优先、先走第一个父提交，给提交分布局序号；每行的提交和穿过这一行、看得见的线按布局序号排列，排第几画在第几列；线从这一行元素的中心连到相邻行的中心，换列是一整段斜线；一段线跨过 30 行以上时只在离两头一行以内画，断开处是箭头（出发后一行朝下、到达前一行朝上），中间不占列；父提交还没读出来时下一行画朝下的箭头。悬停在箭头上那段线加粗描边，提示要跳到的提交（标题、作者、时间，没读出来的只写哈希），点了选中线另一头的提交并滚到中间，没读出来的接着往下读到它为止。提交是实心圆点，HEAD 所在的提交是外圈、底色环、内点；线和点的颜色按布局序号，线取两头序号大的一头。每行的图按这一行最靠右的元素定宽，至少是推荐宽度（前面各行宽度的加权平均加一个标准差，不超过 6 列），标题紧跟着图；列表窄时图和标题一起让，放不下的线裁掉，作者、时间列不动；尺寸按 WebStorm 的比例换算（每列 16、点半径 4、线宽 1.5，按 26 的行高放大）。合并提交的标题用次要色；几个分支从同一个提交分出时各走各的线，到那个提交才汇合，经过的线按位置直下（不按等着的提交去找，否则会斜到第一条等它的线上，画成锯齿）；分支和标签占标题后面剩下的地方，只列整个放得下的（最多 2 个），其余写成 +N；时间写"今天 14:26""昨天 17:04""10月3日 09:12"，跨年的只写日期，悬停是到秒的完整时间和星期。在浮层里点文件，diff 开在上面的标签里。
  - 多仓库工作区中，顶部的分支筛选旁显示这份日志所属的仓库名，长名字省略，悬停显示完整路径；切换仓库同步更新，文件历史保持显示文件所属的仓库。
  - 左边分支树照 WebStorm 分 HEAD、本地、远程（按远端分组）、标签；打开整个仓库的日志时默认选中当前分支（分离的 HEAD 时选 HEAD），点一项只看它的提交，再点一次回到全部分支，⌘ 单击加进或移出（同时看几个分支）。分支树和提交列表、提交列表和右边的提交详情之间的分栏线左右拖调宽（分支树 160–480、详情 260–640，逐行追溯的详情和日志共用一个宽度），记在 ui.json 的 `logRefsWidth`、`logDetailWidth`。
  - 文件历史照 WebStorm 的"历史记录"：左边是改过这个文件的提交（作者、时间、信息、标签，右键菜单和日志一样），右边是选中提交对这个文件的 diff（默认上下合并，排版和忽略空白换提交时沿用），不跟踪重命名。Fetch、更新或推送之后，文件历史和整份日志如果正看着最新一次提交，选中项和右边跟着新的最新一次，从这次提交打开的 diff 标签也改看新提交里的同一个文件；看更早的提交保持不动。当时还在读的话，这次读完再读一遍并跟上。
- Git 操作记录（照 WebStorm 的 Console）：日志浮层的"操作记录"标签，列出浮层所在项目（各工作区，含 worktree）里界面执行过的 Git 操作（提交、Push、储藏、自动 Fetch……），每个操作下面是它调用的 git 命令、输出和报错（不是 git 报出的失败也记）；不在操作里的只记会改动仓库的和失败的，轮询的查询不记。Posse 终端里改动仓库的 git 命令（提交、推送、拉取、检出、储藏、add 等，查询和提示符里的 git 不算）也列进来，按时间排，名字写"Claude 终端"这类，只有命令、仓库、耗时和退出码；手机上的切换分支同样列进来，名字写"手机 · <手机名>"，失败时带 git 的报错，pull 里的 fetch 等不另记；常驻进程的环境里设了别的 `GIT_TRACE2_EVENT` 时不记。输出含标准错误，超过 8 KB 留头尾。记录存在 `$POSSE_HOME/git-console.jsonl`（界面操作）和 `git-trace.jsonl`（终端命令），重开窗口还在，每个项目留最近 500 条；清空只清当前项目。
  - 每个操作一行：左边是结果图标（成功、失败、进行中、已取消），右边是开始时间（悬停看整个操作的耗时），下面和操作名对齐列出命令，命令的耗时在右边，输出前面一道竖线；按天分隔；连着几次同名、同目录、命令一样、都成功又没有输出的操作（自动 Fetch 没拉到东西）合成一条，写"×N"，悬停看起止时间。没看过的失败命令让所在项目的标签带红点；右键复制命令或输出。
- 操作提示：操作成功在窗口底部提示（Fetch、更新拉到几个提交、推送、提交）；git 报错去掉 `hint:` 行。本地分支照 WebStorm 直接删（`branch -d`），提示上有"恢复"；没合并的问一次再强制删；远端分支先确认。改提交信息、和上一个提交合并、删除提交在界面里完成，不打开编辑器，范围里有合并提交时拒绝；改写推送过的提交先说明之后要强制推送。
- 冲突：rebase、合并等停在冲突上时文件栏自动打开到改动页，改动列表顶部有继续 / 跳过 / 中止的横幅，冲突文件可以整个采用一方（rebase 时 ours 是目标分支）。
  - 带 `--autostash` 的操作（更新当前分支、交互式变基改写提交）本身成功、只是本地改动没干净地取回时（git 把它们留在说明为 autostash 的储藏里），不当失败报：提示"…，但取回本地改动时有冲突"（和拉到几个提交合成一条）并打开改动页。横幅写冲突文件数、"查看储藏"；右键冲突文件的两边叫"更新后的版本""我的本地改动"；冲突都解决后横幅给"删除储藏…"（确认后按储藏的提交删，期间新存的储藏不会删错），✕ 关掉。根本没取回（会覆盖拉下来的文件）时提示去储藏里手动应用。横幅只跟着这个工作区自己的操作（操作前后比最新一条储藏），记在窗口内存里，重开窗口后不再出现，储藏和冲突文件照旧。
- 目标推送：已有桌面身份时，本机与远端都使用 `git.pushPreview` 和 `git.push`。只有持有控制且当前预览加载完成才能推送；附注标签可选。服务端在与 Fetch 共用的仓库写锁内重新计算预览，工作区登记、仓库身份、基线、本地分支 OID、跟踪引用及其 OID/缺失状态、remote 和远端分支必须匹配；否则返回冲突且不开始推送。预览的 500 条上限只截断列表，推送仍包含整条分支。
  - 强制推送继续先确认，确认绑定当时主机请求和预览；切主机、换代、仓库身份或预览变化后失效。只使用 `--force-with-lease --force-if-includes`，被拒绝时显示已有说明，不自动升级为强制推送或重试。
  - 关闭对话框、断线或失去控制不撤销已接受操作。回复丢失只查询原标识，未知结果后另开推送须明确确认；取消使用当前控制身份和原标识，取消确认不等于完成。开始后失败、取消或超时都可能已更新部分远端引用。结果与净化后的日志在本次窗口内按主机有界保留，操作记录可继续查询和取消；不会写入本机持久 Git 历史。
  - 进行中和结果未知时占住正在推送的仓库，后续本机 Git 操作排队；操作完成、已知失败、取消结束或确认另开后释放，并继续原队列。取消仅获确认时仍占用。对话框沿用“推送提交”标题，成功提示有预览提交数时显示数量，无提交时显示“已推送到”。
- 推送与执行：强制推送带租约保护，远端有本地还没合进来的提交时拒绝，自动 fetch 刷新过远端引用也一样。推送目标照 `git push` 算：`remote.pushDefault` 指向 fork 时推到 fork 的同名分支、不改上游；跟踪的远端分支被删了时说明会重新建出来。对话框开着、又还没开始推送时，Fetch、更新或推送会重算预览；正看着将要推送的最新提交时，选中和右边的 diff 跟着新的最新一次，更早的提交保持不动。ssh 要口令时直接失败、不卡住；fetch、pull、push 最长 10 分钟、其余 2 分钟；有操作在执行时新操作排队，网络操作可以取消。
- 键盘：
  - 分支弹窗的搜索框里 ↑↓ 选分支、回车检出。
  - 日志左边的分支树点过一行后 ↑↓ 换行（停在分支、标签上就只看它的提交）、→ 展开组或进到组里第一项、在分支上 → 到提交列表、← 收起组或回到上一层、回车展开或收起组（在分支上和单击一样，正只看它时回到全部分支；筛选时各组都展开，点击和回车都收不起来）。
  - 日志点过一行后 ↑↓ 换提交、← 回分支树、→ 到右边它改的文件（没选过文件时选第一个），文件列表里 ↑↓ 换文件并打开 diff、← 回到提交列表。
  - 分支比较的两栏同样 ↑↓ 换提交、→ 到右边的文件、← 回到提交所在的栏；比较页的文件列表（提交里的和与工作区比较的）↑↓ 只移动高亮、回车打开 diff（打开后 diff 换掉比较页）。
  - 文件历史 ↑↓ 换提交和右边的 diff；推送对话框的文件列表 ↑↓ 换 diff；改动列表点过一行后 ↑↓ 换文件预览 diff、空格勾选、回车打开文件（冲突文件不在 ↑↓ 之列）。

- 文件 Git 写操作：有桌面身份的本机窗口与远端控制窗口使用已接受的 `git.paths`，无桌面身份的旧测试窗口保持本机实现。查看端隐藏并安静拒绝加入 Git、回滚、接受一边和标记已解决；控制端沿用原回滚确认，远端不调用访达。暂存与标记已解决是独立动作，接受一边仍先 checkout 再 add。
- 整体回滚按恢复 HEAD、移出暂存、删除新文件依次执行；每一步成功才做下一步，删除先从索引移除，成功后只删除对应文件。覆盖或删除前固定文件版本，缺失也是版本；HEAD、状态类别或版本变化时不开始写入。中途失败与取消保留已完成部分。
- 逐段回滚只作用于工作区 diff，提交 SHA-256 与完整原始字节，用目标 `WriteFileChecked` 保存。发送前磁盘戳变化会提示并重读；成功前不改变可见 diff，服务端拒绝时重载，成功使用返回的磁盘版本。编辑器行号卡片仍只修改缓冲区，保存走 `files.save`；回滚不替仍打开的旧缓冲区更新保存版本，旧版本保存会冲突。
- 路径操作关闭弹窗、断线或失去控制后仍继续，后续重载、关标签和 diff 跳转只在成功且原连接仍为当前控制端时执行。丢失回复只查原操作和原参数，未知结果继续占住仓库；确认另开先让已排队的本机操作执行。取消回执不等于完成或回滚。

- 目标提交：有桌面身份的本机窗口和远端控制窗口经已接受的 `git.commit` 提交；无身份的旧测试窗口保留 `Commit`、`CommitPaths`、`CommitChange`、`LastMessage`。查看端不显示提交框、勾选框或“提交此更改”，直接调用也不读取、不发送、不报 `git.show` / `git.write`。储藏按钮只向当前控制端显示。勾选 amend 时通过目标 `git.status` 的按需完整说明字段读取 `log -1 --format=%B`，核对原连接和仓库身份。
  - 点击固定 HEAD 与 `IndexID`；后者是只读 `ls-files -s -z` 原始输出的 SHA-256，状态轮询不重写索引。提交一次取得仓库路径、common-dir、项目共享键和本次文件的锁，复查工作区登记、仓库身份与文件版本；缺失文件也有预期版本。前提变化返回冲突且不开始，索引、HEAD 和工作区不变。
  - 普通勾选提交只先 `add -A` 显式列出的新文件，再 `commit -F - --only`；所有路径用 `:(literal)`，未勾选的暂存内容不进本次提交且仍暂存。只改上次说明使用 `commit -F - --only --amend --`。merge、cherry-pick、revert 进行中的整体提交先暂存勾选路径，再 `commit -F -`，包含全部暂存内容，不用 `--only` 或 `-a`。
  - “提交此更改”发送计算出的文件字节与 SHA-256，不用工作区文件替代；编辑器未保存时继续提示先保存。目标确认该路径的 HEAD blob 与索引一致，且无进行中的 Git 操作，才在临时索引提交；成功只更新真实索引的该路径，工作区字节与其他暂存内容保持原样。说明不能为空且最多 1 MiB，正文不超过 `files.MaxSize`；说明经 stdin，不加跳过钩子、跳过签名或允许空提交选项。
  - 多仓库共用说明，每个仓库一次提交；失败保留说明和失败仓库勾选，只清已成功仓库的勾选，全部成功才清说明和 amend。多个仓库 amend 在发送前报原错误。请求十分钟，关闭、断线和失控不取消已接受提交；丢失回复仅查原 ref 与原参数，断线后不清说明。未知结果仍占仓库，确认另开先续跑本机旧队列。取消用当前控制身份与原 ref，回执不等于完成或回滚；命令开始后钩子拒绝、失败和取消保留现场，不 reset 或自动取消暂存。

- 目标储藏：有桌面身份的本机窗口和远端控制窗口经已接受的 `git.stash` 存入、应用、弹出和删除；无身份旧窗口保留现有 `gitx` 调用。查看端保留储藏文字，隐藏存入按钮、条目菜单与 autostash 删除，直接调用也安静返回。
  - 存入固定点击时的 HEAD、`IndexID` 和有序状态条目（路径、原路径、XY、未跟踪、冲突、子模块），说明框发送前和锁内都复查。说明可空，非空最多 4096 字节且为无 NUL 的 UTF-8，独立传给 `-m`；只执行 `stash push --include-untracked`。成功后锁内对比储藏 OID，恰好新增一条时返回其 OID。
  - 应用、弹出与删除只传储藏提交 OID，客户端不传 `stash@{n}`。与 Fetch 共用仓库路径、common-dir 和项目共享锁，锁内复查登记及身份，再查唯一对应条目并立即 rev-parse 核对其当前 reflog。应用与弹出还核对 HEAD 和索引，分别执行 `stash apply --index`、`stash pop --index`；删除只按 OID，不受 HEAD 变化影响。跨分支沿用原确认并固定 OID、HEAD 和索引；删除确认固定 OID，过期不发送。
  - 运行中和结果未知占用同仓库及同 common-dir 的全部视图；本机旧 Git 操作进入原队列，确认另开先续旧队列再复查。回复丢失只查原 ref 和原参数；取消用当前控制身份和原 ref，回执不等于完成或回滚。关闭说明框、确认框、断线或失去控制不取消已接受操作。前提变化返回 conflict 且不开始；命令开始即 Started，失败、冲突或取消保留现场，不 reset、不额外 drop，pop 冲突不补删。仅原连接仍为当前控制端且结果成功时刷新、清掉对应 autostash 横幅。操作日志有界净化，说明只留摘要。

- 目标合并与变基：分支菜单的合并、变基、检出并变基，比较页和日志的 Cherry-pick，日志的还原，以及改动页横幅的继续、跳过、中止，统一经已接受的 `git.integrate`。有身份的本机与远端控制窗口走目标 daemon；无身份旧窗口保留原命令和确认，查看端隐藏这些菜单和按钮，直接调用也安静返回。
  - 固定点击时的 HEAD OID、当前分支和目标分支名/OID，锁内分别核对本地 `refs/heads/` 与远端跟踪 `refs/remotes/`。合并只 `merge --no-edit -- <name>`，变基只 `rebase <name>`，检出并变基只 `rebase <current> <branch>`；分离 HEAD 时 current 用字面量 HEAD，目标分支被其他 worktree 检出时拒绝，不先 switch。Cherry-pick 按应用顺序发送最多 500 个完整 OID，还原只接受一个；每个先验证为原提交，再执行 `cherry-pick <oid>...` 或 `revert --no-edit <oid>`。冲突保留现场和已经应用的提交，不自动 abort/reset。
  - 继续必须仍是同一操作、HEAD、IndexID 且无未合并条目。merge 读取锁内 MERGE_MSG 原始说明，用 `commit -F -` 提交整个索引，第二父提交仍来自 MERGE_HEAD；说明缺失、空、含 NUL、无效 UTF-8 或超过 1 MiB 时不提交。其余三种继续用 `GIT_EDITOR=true <op> --continue`，保留剩余序列；钩子照常运行，失败不中止。跳过只允许 rebase/cherry-pick，不要求索引未变；跳过和中止都核对原操作与 HEAD。冲突时继续按钮禁用，合法的跳过按钮仍可点击。
  - 仓库路径、common-dir 与项目共享键一次取齐，锁内复查登记和身份，前提不符返回 conflict、Started=false。请求与 Git 命令均为十分钟。运行中和未知结果占住同仓库及 common-dir 的全部视图；查询仅用原 ref 与参数，另开确认先续本机旧队列再复查。取消使用当前控制身份和原 ref，回执不等于完成或中止，也不执行 `--abort`。关闭确认框、断线和失控不取消已接受操作。guardAgent 和中止确认绑定点击时前提及控制代次；成功只刷新原连接仍控制的界面，断线不切工作区或额外关闭分支弹窗。
  - worktree 同步复用上述 merge/rebase，合并回项目经已接受的 `workspace.merge`；日志 reset/reword/squash/drop 经 `git.history`，详见下文。重命名与目录传输仍由 `git.write` 在入队前拒绝。任务与工作区使用的 `gitx.Merge` 仍为 `merge --no-ff`，失败后 abort；手机协议不变。

- 目标历史改写：日志的 soft/mixed/hard reset、改提交说明、压缩和丢掉经已接受的 `git.history`。固定点击时 HEAD、当前分支、目标完整 OID、仓库身份和控制代次；锁内重验工作区登记和原提交，有进行中的 merge/rebase/cherry-pick/revert 时拒绝。reset 仅运行 `reset --<mode> <oid>`，不要求目标为祖先。其余动作要求目标在当前历史中且改写范围没有合并提交，根提交不能压缩。
  - 已推送检查通过目标只读 `git.remotesContaining`；用户确认的远端跟踪名列表在写锁内重算，不一致或未确认就不执行。完整说明通过 `git.commitFiles` 的按需字段读取，不用本机 Git 或 HEAD 的 LastMessage 代替非 HEAD 正文。说明非空、无 NUL、有效 UTF-8，最多 1 MiB，经 stdin，结果只保留 SHA-256 摘要。
  - HEAD 改说明仅 `commit --amend --only -F -`，保留钩子、签名与其他已暂存内容。旧提交改说明、压缩、丢掉沿用交互式 rebase 的 `--autostash --no-autosquash` 与原配置；冲突保留现场，不自动 abort/reset。成功遗留 autostash 返回结构化成功，沿用现有横幅。
  - 运行中及未知结果占住同身份或同 common-dir 的全部仓库视图，含重新发现的仓库；只查原 ref 与参数，另开必须确认并先续跑本机旧队列。取消使用当前控制身份及原 ref，回执不等于完成或回滚。关闭确认、断线、失控不取消已接受操作；成功刷新只交给原连接的当前控制端。
- 目标 worktree 同步：以已加载 divergence 的基准 OID、点击时 HEAD/分支和 BaseRef 发起现有 `git.integrate` merge/rebase，不加 autostash、no-ff 或 ff-only；预测冲突仍允许执行，刷新后停在 merge/rebase 不报失败。前提未加载或确认已过期时不发送。
- 合并回项目：单仓库重新读取目标 `git.divergence`，预测冲突引导先同步，预测不可用则不调用；多仓库直接由目标 `workspace.merge` 执行原有全部检查。每次确认仅调用一次，回复丢失查询原 ref，未知结果占住工作区和共享 common-dir；确认另开先续旧队列并重读预测。断线不切换、不删除工作区。查看端隐藏日志改写、同步、侧栏和任务页合并入口，直接调用安静返回；无身份旧窗口保留原 gitx 与 invoke 路径。

# Git 界面

照 WebStorm 做的 Git 界面。按 WebStorm 里的使用统计，提交多半由 agent 做，用得多的是看改动、比较分支、同步和整理分支，界面以这些为重心。

- 界面各部分：
  - 文件栏"改动"：
    - 刷新：文件栏或文件标签看得见时每 1.5 秒读一次 `git status`。有改动时分段上的"改动"后面挂一个强调色的数（有改动的文件数，不含储藏），切在文件、检索页也看得见。
    - 改动与提交：文件的状态字母和文件名照 WebStorm 上色（改动页、回滚对话框、提交和比较里的文件、文件树同一套）：修改和重命名蓝、新增绿、删除灰（加删除线）、未加入 Git 和冲突红。照 WebStorm 不分暂存和未暂存，每个文件一个勾选框（已跟踪的默认勾、新文件默认不勾），只提交勾选的文件，暂存区里没勾的原样留着。冲突、改动、未跟踪各组可以点标题展开收起（不记进 ui.json；收起的组 F7 照样能跳到）。合并、Cherry-pick、还原进行中 git 不许部分提交，这时按钮是"提交合并结果"（Cherry-pick、还原时是"提交 Cherry-pick 结果""提交还原结果"），勾选的文件连同已加入 Git 的一起整体提交。
    - 储藏：改动页分"提交"和"储藏"两个分页。储藏就是 `git stash`（含未跟踪文件，顶上的按钮先问说明、可以留空），储藏分页单击一条有弹出（取回并删掉）、应用（储藏留着）、删除。WebStorm 另有的"搁置"（IDE 自己存的补丁，终端里的 agent 和命令行看不到）不做。
    - 改动卡片：编辑器行号旁标出相对 HEAD 的改动，⌥⌘Z 回滚一段；点色条弹出改动卡片（照 WebStorm 的 gutter 弹窗排成一行）：上一处 / 下一处、回滚这一处（改的是编辑器里的内容，可撤销，保存才写盘）、显示 diff、复制改之前的内容、"提交此更改"（回车只提交这一处，钩子照常执行，其余改动留在工作区；有没保存的改动、这个文件有已暂存的改动、合并进行中时不做），下面是改之前的内容，Esc 或点外面关。
    - 回滚：改动页顶上的回滚按钮（焦点在改动页时 ⌥⌘Z）打开批量回滚对话框，文件照 WebStorm 按目录排成树（只有一个子目录的中间层并成一行，目录可收起、可整个勾选），默认勾提交时勾着的文件。点文件名在对话框上面另开一个 diff 浮窗，F7 / ⇧F7 跨文件，"包含在回滚中"就是文件树里的勾选，顶栏的"回滚这一处"（⌥⌘Z）立刻写回磁盘，Esc 只关 diff 浮窗。新文件（未跟踪、刚加入 Git）勾了"同时删除新文件"才删，否则刚加入的移出暂存区、未跟踪的不动。单个文件的回滚（diff 栏和编辑器顶栏的"回滚这个文件"、改动列表右键的"回滚…"）也打开这个对话框，只勾这个文件，是新文件时默认勾上"同时删除新文件"。diff 栏回滚后换到同一组的下一个文件，没有了就关掉 diff；编辑器顶栏回滚后按磁盘重载，没保存的改动一起丢掉，新文件删掉后关掉标签。
    - 回滚对话框、它的 diff 浮窗和 Push 对话框可以拖标题移动、拖四边四角拉伸，同一次运行里再打开沿用尺寸，位置每次回到居中。
  - worktree 工作区相对基准分支（建工作区时记下的）：改动页分支行下面一行写"相对 main"、基准分支上的新提交数、待合回的提交数；两边都有新提交时预测冲突文件（不碰工作区和暂存区，不进操作记录）。和传入、传出一起每 10 秒算，分支按钮的悬停提示也写。"同步"在 worktree 里把基准分支合并进来或 rebase 上去，停在冲突上不报错，用改动页的横幅解决；"合并"、侧栏 worktree 右键的"合并到 main…"、任务总览的合并按钮：预测到冲突时不去试，引导先同步，合并失败时再算一次，确实冲突才引过去，别的原因照常报错。合并成功后问要不要删工作区：照 WebStorm 强制删 worktree，会删掉的没提交文件在确认框里列出来。储藏是所有 worktree 共用的：储藏分页里别的分支存的标出分支名，弹出、应用前确认，检出那个分支的工作区在菜单里能直接切过去。
  - 分支比较照 WebStorm 上下两栏，打开时收起底部的日志浮层（它会盖住下半截），各是一边独有的提交，默认各占一半，拖中间的分隔线（一条细线，悬停变强调色）调比例（所有比较共用，记在 ui.json 的 `compareSplit`）；两边分支各一种颜色，标题里的分支名和提交圆点同色；没有单独的顶栏，Cherry-pick、交换两边、刷新放在上一栏标题行的右边。每栏标题行最左边有自己的搜索框，按提交信息、作者（不分大小写）或哈希前缀只筛这一栏显示的提交、两栏互不影响，标题里的数目写成"显示 / 全部"。提交照 WebStorm 点选：单击选一个，⌘ 点加上或去掉，⇧ 点选上一段，多选只在同一边里，右边看最后点的那个。Cherry-pick 把选中的提交按提交先后应用到当前分支（中途冲突停下，解决后继续接着应用剩下的）：只有都是另一边独有的提交、且另一边正是工作区检出的分支时可点，agent 正在这个工作区工作时先确认。
  - 图片（png/jpg/gif/webp）的 diff 左右对照两张图，各标版本、像素尺寸和文件大小，透明处垫棋盘格；新增的一边写新文件、删除的写已删除。
  - diff 每个工作区只有一个标签，打开别的文件换掉里面的内容，排版和忽略空白沿用。diff 上方的路径点开是同一组文件的菜单，F7 / ⇧F7（diff 栏最左边的上下箭头）跨文件跳改动，到头了在 diff 栏正下方提示"已经是第一处 / 最后一处改动"。默认左右对照、忽略空白（只忽略空白，不忽略空行）。左右对照的分界线能拖，所有 diff 共用一个位置，记在 ui.json 的 `diffSplit`。F4 跳到编辑器；工作区 diff 可以逐段回滚，立刻写回磁盘：左右对照时照 WebStorm 两列行号挨着分隔线，左栏行号左边给每处改动放 `>>`，上下合并时悬停的那处右边有"回滚"。Annotate 照 WebStorm 在文件自己的标签里开关，不另开标签：开着时显示逐行作者，顶栏的"关闭 Annotate"切回编辑器。diff、比较和日志浮层里打开的文档不轮询磁盘、不记进 ui.json。
  - 分支弹窗：点标签栏的分支名，弹窗贴着右边，拖左边缘调宽（360 到 800，默认 420，ui.json 的 `branchPopWidth`），长分支名、远端名看得全；⌥⌘N 新建分支，⇧⌘K Push（WebStorm 的 ⌘T 更新项目和 posse 的新建终端冲突，放进弹窗）。更新当前分支是 `pull --rebase --autostash`，其他分支只快进。被另一个 worktree 检出的分支照 WebStorm 留在"本地"组里，不单独分组：是 posse 工作区的，右边写"在 <工作区>"，检出改成切到那个工作区；不是 posse 建的（别的工具、命令行建的），右边写"worktree · <目录名>"（悬停看完整路径），菜单里是"在 Posse 中打开"（回车也是）、"在访达中显示 worktree"和"复制 worktree 路径"。"基于它新建工作区"走 posse 的 worktree 工作区。检出、rebase、合并、更新、reset 之类改动工作目录的操作，工作区里有 agent 正在工作时先确认。更新项目、更新分支、删除分支做完弹窗不关，忙碌行、传入数和分支列表就地刷新；其他操作要去别的界面或对话框，点了就关。
  - 别处建的 worktree："在 Posse 中打开"把它加成项目的工作区（名字取目录名，重名加 -2，CLI 是 `workspace create <项目> <名称> --mode attach --path <目录>`）并切过去，要求它是这个仓库的 worktree、还没有工作区；侧栏和空工作区页和 posse 建的一样画分支图标；它的目录名常和仓库同名，所以侧栏、标题显示它当前的分支（`Shown`，窗口每秒读 HEAD，游离时用原名），存的名字不变，CLI 照旧认原名。worktree 工作区的目录在外面被删掉后，窗口发现就删掉记录、清掉 git 的 worktree 记录（分支不再算检出在那里），提示"目录已删除，移除了工作区 …"；里面还有终端在跑的等终端退出再删，上一级目录也不在的（外接盘没挂上）不动。没被自动删掉的（上一级目录也不在、终端还在跑，或者项目目录本身不在了）窗口每秒查一次目录，侧栏行尾写"目录不存在"、不再显示旧分支，分支按钮和日志浮层收起，文件栏不再去读；空工作区页换成说明卡片，开着终端或文件时标签栏下面一条提示，两处都有"重新指定目录…"（`workspace.relocate`：git 项目要求是仓库根目录、worktree 还要是这个仓库的，改完跑 `git worktree repair`；主工作区连项目目录和同目录的工作区一起改）和"从 Posse 移除…"（只删记录、清掉 git 的 worktree 记录，不删分支；主工作区是移除项目）。
  - 自动 fetch：分支按钮画出来时，按项目每 5 分钟在后台 `fetch --all` 一次（打开后先拉一次），同一项目的 worktree 共用计时；失败不报错，下次再试。fetch 期间同一项目所有工作区的手动 git 操作排队，不同时改引用。传入、传出提交数每 10 秒只用本地的远端引用算。自动、手动 fetch 和其他 git 操作之后，同一项目里开着的分支比较、分支弹窗、日志等依赖引用的界面都会重读。
  - Git 日志：照 WebStorm 底部的 Git 工具窗口，是从终端那一栏底边滑上来的浮层，盖在终端上、不改终端尺寸，也不盖右边的文件栏；点别处不收，只有浮层右上角的隐藏按钮、⌘9 和标签栏的日志按钮（分支按钮旁）开关。顶上一排小标签：整个仓库的"提交日志"（不能关）、"操作记录"和文件历史（可以关），不进标签栏、不记进 ui.json。拖上边缘调高度（至少给终端留 120），开关按项目记在 ui.json 的 `logPanels`，高度所有项目共用。每行是提交图、标题、分支和标签、作者、时间：提交图按这一页最宽处的线数定宽（最多 12 条），各行标题对齐；分支和标签占标题后面剩下的地方，只列整个放得下的（最多 2 个），其余写成 +N；时间写"今天 14:26""昨天 17:04""10月3日 09:12"，跨年的只写日期，悬停是到秒的完整时间和星期。在浮层里点文件，diff 开在上面的标签里。文件历史照 WebStorm 的"历史记录"：左边是改过这个文件的提交（作者、时间、信息、标签，右键菜单和日志一样），右边是选中提交对这个文件的 diff（默认上下合并，排版和忽略空白换提交时沿用），不跟踪重命名。左边分支树照 WebStorm 分 HEAD、本地、远程（按远端分组）、标签，点一项只看它的提交，再点一次回到全部分支，⌘ 单击加进或移出（同时看几个分支）。分支树和提交列表、提交列表和右边的提交详情之间的分栏线左右拖调宽（分支树 160–480、详情 260–640，逐行追溯的详情和日志共用一个宽度），记在 ui.json 的 `logRefsWidth`、`logDetailWidth`。
  - Git 操作记录（照 WebStorm 的 Console）：日志浮层的"操作记录"标签，列出浮层所在项目（各工作区，含 worktree）里界面执行过的 Git 操作（提交、Push、储藏、自动 Fetch……），每个操作下面是它调用的 git 命令、输出和报错（不是 git 报出的失败也记）；不在操作里的只记会改动仓库的和失败的，轮询的查询不记。Posse 终端里改动仓库的 git 命令（提交、推送、拉取、检出、储藏、add 等，查询和提示符里的 git 不算）也列进来，按时间排，名字写"Claude 终端"这类，只有命令、仓库、耗时和退出码，pull 里的 fetch 等不另记；常驻进程的环境里设了别的 `GIT_TRACE2_EVENT` 时不记。输出含标准错误，超过 8 KB 留头尾。记录存在 `$POSSE_HOME/git-console.jsonl`（界面操作）和 `git-trace.jsonl`（终端命令），重开窗口还在，每个项目留最近 500 条。清空只清当前项目。每个操作一行：左边是结果图标（成功、失败、进行中、已取消），右边是开始时间（悬停看整个操作的耗时），下面和操作名对齐列出命令，命令的耗时在右边，输出前面一道竖线；按天分隔；连着几次同名、同目录、命令一样、都成功又没有输出的操作（自动 Fetch 没拉到东西）合成一条，写"×N"，悬停看起止时间。没看过的失败命令让所在项目的标签带红点；右键复制命令或输出。
  - 操作成功在窗口底部提示（Fetch、更新拉到几个提交、推送、提交）；git 报错去掉 `hint:` 行。本地分支照 WebStorm 直接删（`branch -d`），提示上有"恢复"；没合并的问一次再强制删；远端分支先确认。改写推送过的提交（改信息、合并、删除）先说明之后要强制推送。操作停在冲突上时文件栏自动打开到改动页。更新当前分支、改写提交（交互式变基）这类带 `--autostash` 的操作，本身成功、只是本地改动没干净地取回（git 把它们留在说明为 autostash 的储藏里）：照 WebStorm 不当失败报，提示"…，但取回本地改动时有冲突"（和拉到几个提交合成一条）并打开改动页。横幅写冲突文件数、"查看储藏"；右键冲突文件的两边叫"更新后的版本""我的本地改动"；冲突都解决后横幅给"删除储藏…"（确认后按储藏的提交删，期间别人新储藏的不会删错；WebStorm 让你自己去储藏里删），✕ 关掉。根本没取回（会覆盖拉下来的文件）时提示去储藏里手动应用。储藏列表是所有 worktree 共用的，横幅只跟着这个工作区自己的操作（操作前后比最新一条储藏），记在窗口内存里，重开窗口后不再出现，储藏和冲突文件照旧。键盘：分支弹窗的搜索框里 ↑↓ 选分支、回车检出；日志点过一行后 ↑↓ 换提交；改动列表点过一行后 ↑↓ 换文件预览 diff、空格勾选、回车打开文件（冲突文件不在 ↑↓ 之列）。
  - 强制推送带租约保护：远端有本地还没合进来的提交时拒绝，自动 fetch 刷新过远端引用也一样。推送目标照 `git push` 算：`remote.pushDefault` 指向 fork 时推到 fork 的同名分支、不改上游；跟踪的远端分支被删了时说明会重新建出来。ssh 要口令时直接失败、不卡住；fetch、pull、push 最长 10 分钟、其余 2 分钟；有操作在执行时新操作排队，网络操作可以取消。diff 在后台比较（读文件的协程里算好，界面线程只装结果），超过 1 MB 的显示"正在比较…"，切换忽略空白也在后台重比、算完再换；超过 20 MB 的先不比较，写两边的大小和行数，点"仍要比较"照样在后台比。比较大文件临时要的内存比完就还给系统（`internal/app/diffmem.go`）；大 diff 开着时每 15 秒主动 GC 一次，关掉（关标签、换文件、关浮窗都算）后它被回收，内存也还回去。改提交信息、和上一个提交合并、删除提交在界面里完成，不打开编辑器；范围里有合并提交时拒绝。rebase、合并等停在冲突上时，改动列表顶部有继续 / 跳过 / 中止的横幅，冲突文件可以整个采用一方（rebase 时 ours 是目标分支）。

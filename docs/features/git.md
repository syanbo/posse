# Git 界面

照 WebStorm 做的 Git 界面，依据和取舍见 `docs/plans/git-ops.html`。

- Git 界面照 WebStorm 的用法做（依据和取舍见 `docs/plans/git-ops.html`），全部在窗口进程里调用系统 git，常驻进程不参与：
  - 路径都相对仓库根目录；仓库根目录换成工作区路径的写法（`repoRoot`），git 给的是解析过符号链接的（如 `/private/var`），混用会把同一个文件当成两个。界面调用的 gitx 函数用 `runRaw`（原样输出、`LC_ALL=C`、失败返回 `*gitx.Error`，`Msg` 是 git 自己的报错）。
  - 文件栏"改动"：文件栏或文件标签看得见时每 1.5 秒读一次 `status --porcelain=v2`，不用手动刷新；照 WebStorm 不分暂存和未暂存：每个文件一个勾选框（已跟踪的默认勾、新文件默认不勾），冲突、改动、未跟踪各组的标题最左边有展开箭头，点箭头或组名展开收起（`gitState.folded`，不记进 ui.json；收起的组 F7 照样能跳到）；提交勾选的文件——新文件先 `add`，再 `commit --only -- <文件>`，暂存区里没勾的原样留着。改动页分"提交"和"储藏"两个分页，照 WebStorm：储藏就是 `git stash`（含未跟踪文件，顶上的按钮先问说明、可以留空），储藏分页单击一条有弹出（取回并删掉）、应用（储藏留着）、删除；WebStorm 另有的"搁置"（IDE 自己存的补丁，终端里的 agent 和命令行看不到）不做。合并、拣选、还原进行中 git 不许部分提交，这时按钮是"提交合并结果"：勾选的先 `add`，再整体提交。编辑器行号旁标出相对 HEAD 的改动（`State.DiffBase`），⌥⌘Z 回滚一段；点色条弹出改动卡片（`changepop.go`，照 WebStorm 的 gutter 弹窗排成一行）：上一处 / 下一处、回滚这一处（改的是编辑器里的内容，可撤销，保存才写盘）、显示 diff、复制改之前的内容、"提交此更改"（回车只提交这一处：`gitx.CommitChange` 在临时暂存区里提交、钩子照常执行，再把真正暂存区里这个文件换成刚提交的版本；有没保存的改动、这个文件有已暂存的改动、合并进行中时不做），下面是改之前的内容，Esc 或点外面关。回滚照 WebStorm：改动页顶上的回滚按钮（焦点在改动页时 ⌥⌘Z）打开批量回滚对话框（`rollback.go`），文件照 WebStorm 按目录排成树（只有一个子目录的中间层并成一行，目录可收起、可整个勾选），默认勾提交时勾着的文件；点文件名在对话框右边看它的 diff（对话框加宽），F7 / ⇧F7 跨文件，顶栏的"回滚这一处"（⌥⌘Z）立刻写回磁盘，文件列表跟着状态更新；回滚和 Push 对话框照 WebStorm 可以拖标题移动、拖四边四角拉伸（`dialogBox`，只看列表和带 diff 两种排版各记一份尺寸，同一次运行里再打开沿用，位置每次回到居中）；新文件（未跟踪、刚加入 Git）勾了"同时删除新文件"才删，否则刚加入的移出暂存区、未跟踪的不动。工作区 diff 栏有"回滚这个文件"，回滚后换到同一组的下一个文件，没有了就关掉 diff。编辑器顶栏（文件有改动时）也有"回滚这个文件"：回滚成功后按磁盘重载，没保存的改动一起丢掉，新文件删掉并关掉标签（`rollbackDoc`；回滚后的动作经 `gitDoThen` 在 git 执行完才做）。
  - 分支比较（`compare.go`）照 WebStorm 上下两栏，打开时收起底部的日志浮层（它会盖住下半截），各是一边独有的提交，默认各占一半，拖中间的分隔条调比例（ui.json 的 `compareSplit`，所有比较共用，松手才写）；两边分支各一种颜色（`laneColor(0)`、`laneColor(1)`），顶栏和标题里的分支名、提交圆点同色。
  - 图片（png/jpg/gif/webp）的 diff 左右对照两张图（`imageDiffView`），各标版本、像素尺寸和文件大小，透明处垫棋盘格；新增的一边写新文件、删除的写已删除。
  - diff 每个工作区只有一个标签（`openDiff` 换掉里面的文件，排版和忽略空白沿用），diff 上方的路径点开是同一组文件的菜单，F7 / ⇧F7（diff 栏最左边的上下箭头）跨文件跳改动，也在这个标签里换文件，到头了在 diff 栏正下方居中提示 1.5 秒（"已经是第一处 / 最后一处改动"，`diffHint`；mygo 的 toast 只能放在窗口底部，离箭头太远）。diff 用 mygo 的 `editor.DiffView`，默认左右对照、忽略空白（`third_party/mygo` 加的 `IgnoreWhitespace`，只忽略空白，不忽略空行）。`diffSpec` 的版本：newRev 空是工作区、`":"` 是暂存区，oldRev 空是"这一边没有"。F4 跳到编辑器；工作区 diff 的逐段回滚立刻写回磁盘。Annotate 照 WebStorm 在文件自己的标签里开关（`fileDoc.blame`），不另开标签：开着时这个标签显示逐行作者，顶栏的"关闭 Annotate"切回编辑器。diff、比较和日志浮层里的文档是 `virtual`，不轮询磁盘、不记进 ui.json。
  - 分支弹窗：点标签栏的分支名，⌥⌘N 新建分支，⇧⌘K Push（WebStorm 的 ⌘T 更新项目和 hive 的新建终端冲突，放进弹窗）。更新当前分支是 `pull --rebase --autostash`，其他分支只快进。被另一个 worktree 检出的分支，检出改成切到那个工作区；"基于它新建工作区"走 hive 的 worktree 工作区。检出、rebase、合并、更新、reset 之类改动工作目录的操作，工作区里有 agent 正在工作时先确认（`guardAgent`）。
  - 自动 fetch：分支按钮画出来时，按项目每 5 分钟在后台 `fetch --all` 一次（打开后先拉一次），同一项目的 worktree 共用计时；失败不报错，下次再试。进行中占着同一项目所有开着的改动页的 busy（worktree 共用远端引用），那边的手动 git 操作排队，不同时改引用。传入、传出提交数每 10 秒只用本地的远端引用算。自动、手动 fetch 和其他 git 操作之后，同一项目里开着的分支比较、分支弹窗、日志等依赖引用的界面都会重读（`refsChanged`）。
  - Git 日志：照 WebStorm 底部的 Git 工具窗口，是从终端那一栏底边滑上来的浮层（`logPanel`），盖在终端上、不改终端尺寸，也不盖右边的文件栏；点别处不收，只有浮层右上角的隐藏按钮、⌘9 和标签栏的日志按钮（分支按钮旁）开关。顶上一排小标签：整个仓库的"提交日志"（不能关）、"操作记录"和文件历史（可以关），存在 `filesView.logs`，不进标签栏、不记进 ui.json。拖上边缘调高度（`logPanelHeight`，至少给终端留 120），开关和高度记在 ui.json。在浮层里点文件，diff 开在上面的标签里。文件历史照 WebStorm 的"历史记录"（`filehistory.go`）：左边是改过这个文件的提交（作者、时间、信息、标签，右键菜单和日志一样），右边是选中提交对这个文件的 diff（默认上下合并，排版和忽略空白换提交时沿用），不跟踪重命名。左边分支树照 WebStorm 分 HEAD、本地、远程（按远端分组）、标签，点一项只看它的提交，再点一次回到全部分支，⌘ 单击加进或移出（同时看几个分支，`LogFilter.Branches`）；分支和标签随分支弹窗一起读（`loadBranches`）。
  - Git 操作记录（`gitconsole.go`，照 WebStorm 的 Console）：日志浮层里"提交日志"旁边的"操作记录"标签，列出所有项目里界面执行过的 Git 操作（提交、Push、储藏、自动 Fetch……），每个操作下面是它调用的 git 命令、输出和报错。`gitRun` 用 `gitx.WithOp` 给操作的 ctx 标上名字，`runRaw` 和 `run` 经 `gitx.Trace` 报出操作里的每条命令（连同顺带的查询），操作失败或取消时 `gitx.OpResult` 再记一条界面上显示的报错（不是 git 报出的失败也有，和某条命令的报错相同时不重复显示）；不在操作里的只报会改动仓库的和失败的，轮询的查询不报。输出含标准错误，超过 8 KB 留头尾。完成的命令由窗口进程追加到 `$HIVE_HOME/git-console.jsonl`，窗口打开时读回最近 1000 条（攒到 2000 行时重写），gitx 的编号接在后面（`gitx.Seed`）；清空记下时间（ui.json 的 `gitConsoleCleared`），更早的不再显示。Hive 终端里改动仓库的 git 命令（`gitx.ChangesRepo` 白名单：提交、推送、拉取、检出、储藏、add 等，查询和提示符里的 git 不算）也列进来，按时间排，名字写"Claude 终端"这类，只有命令、仓库、耗时和退出码：常驻进程给新终端注入 `GIT_TRACE2_EVENT=af_unix:$HIVE_HOME/git-trace.sock` 和 `GIT_TRACE2_ENV_VARS=HIVE_TERMINAL_ID`（用户自己设了别的 GIT_TRACE2_EVENT 时不注入），每个 git 进程连一次 socket 写 trace2 事件，只取最外层的（sid 不带 `/`，pull 里的 fetch、maintenance 不另记）；没人监听时 git 静默跳过。常驻进程（`internal/daemon/gittrace.go`）把记录追加到 `$HIVE_HOME/git-trace.jsonl`（同样 1000 条、序号重启后接着数），`daemon.status` 带最新序号 `gitTraceSeq`，界面看到变了用 `git.trace` 取新的。gitx 自己调用 git 时设 `GIT_TRACE2_EVENT=0`，窗口从终端里拉起继承了变量也不会重复记。没看过的失败命令让标签带红点；右键复制命令或输出，可以清空。
  - 操作成功经 `a.notify` 在窗口底部提示（Fetch、更新拉到几个提交、推送、提交）；git 报错去掉 `hint:` 行。本地分支照 WebStorm 直接删（`branch -d`），提示上有"恢复"；没合并的问一次再强制删；远端分支先确认。改写推送过的提交（改信息、合并、删除）先说明之后要强制推送（`guardPushed`）。操作停在冲突上时文件栏自动打开到改动页。键盘：分支弹窗的搜索框里 ↑↓ 选分支、回车检出（`checkoutBranch`）；日志点过一行后 ↑↓ 换提交；改动列表点过一行后 ↑↓ 换文件预览 diff、空格勾选、回车打开文件（`changesKeys`，冲突文件不在 ↑↓ 之列）。
  - 强制推送一律 `--force-with-lease --force-if-includes`（只用 lease 时，自动 fetch 刷新远端引用后照样会覆盖别人的提交）。推送目标照 `git push` 算（`PushPreview` 读 `push:remotename` 和上游）：`remote.pushDefault` 指向 fork 时推到 fork 的同名分支、不改上游；跟踪的远端分支被删了时说明会重新建出来。界面调 git 都在新会话里（`runRaw`，ssh 要口令时直接失败不卡住），fetch、pull、push 最长 10 分钟、其余 2 分钟；有操作在执行时新操作排队（`gitState.queue`），网络操作可以取消（给整组发 SIGTERM，git 会删掉自己的 .lock 再退出，2 秒不退再强杀）。超过 2 MB 的文件不做 diff（比较在界面线程上）。改提交信息、和上一个提交合并、删除提交用交互式 rebase，hive 生成脚本改写待办列表和提交信息（`rebaseTodo`），不打开编辑器；范围里有合并提交时拒绝。rebase、合并等停在冲突上时，改动列表顶部有继续 / 跳过 / 中止的横幅，冲突文件可以整个采用一方（rebase 时 ours 是目标分支）。
